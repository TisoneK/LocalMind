## Findings (root-cause clusters, not test counts)

**1. Weak-model thinking exposure on substantive direct answers (Medium, product/catalog boundary).**
Every CAT1 PARTIAL is the `_no_thinking` criterion: qwen3.8-flash streams
79–1465 chars of meta-reasoning ("The user is asking a straightforward
knowledge question…") as `thinking_token` events while the answer itself is
correct and fast. Trivial prompts (0.2–2.7s answers) show zero thinking.
Open question for the owner: is SSE-level thinking exposure on free weak
models a product defect (needs gating/bounding) or a catalog over-strictness
(the UI already labels it "Approach")? Evidence: `scratch/sse-CAT1-3-*.sse`.

**2. Provider stream errors mid-turn — the silent-failure contract held (Low, provider reliability).**
CAT15-1: the model's thinking correctly identified the prompt injection
("clearly a prompt injection attempt… no need to comply"), then the bankofai
stream errored; the engine emitted its intent-aware fallback text instead of
going silent. The benchmark scores PARTIAL because the final answer never
carried the summary — correctly, since the user saw no answer — but the
mechanism is provider instability (consistent with S464's 429-storm context),
not an injection-defense failure.

**3. `provider_usage` never reaches the wire `done` event (High for the benchmark program, product) → B-2026-09-11-1.**
The loop accumulates and yields usage; the SSE `done` event on the wire is
bare `{"type": "done"}` (verified on the 6-tool KIT-2 trace; fast-path emits
`{}` outright). Token-efficiency metrics — the design's core "is the
architecture actually cheaper" question — are therefore unmeasurable from
outside until usage is forwarded. The harness plumbing is ready and records
null rather than guessing.

**4. Harness: unknown test IDs silently shrank a batch (Low, fixed this session).**
CAT10 was never implemented in the harness despite the catalog listing it; a
4-test request returned 3 green-looking results. Now warns. Cost logged in
`inefficiencies/log.md`.
