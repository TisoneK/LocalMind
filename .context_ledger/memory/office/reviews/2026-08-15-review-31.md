# Session 227 Review — B-2026-08-14-10 Retire Observe Tab + Product-Facing Intents

- **Date:** 2026-08-15
- **Agent:** Super Z / GLM-5.2 (Z.ai cloud sandbox)
- **Core:** 0.5.0
- **Target:** ADR-34 B-10 — retire Observe/pipeline and product-facing intents
- **Feature:** adr-34-realtime-workspace

## Problem

ADR-34 §5: "Retire Observe as a product pipeline. Remove the user-facing
Observe tab and its `Intent Classify → ... → Execute` visualization."

ADR-34 §6: "Retire intent as a product contract. Remove intent badges,
intent classification UI/events, and intent-based routing decisions from
the new surface."

The right panel had 4 tabs: Terminal, **Observe**, Agents, Memory. The
Observe tab rendered:
- Intent Classification (label + confidence bar)
- Agent Pipeline (6-stage `Intent Classify → Context Build → Agent
  Initialize → Tool Select → Generate → Execute` visualization)
- Performance, Tools Used, Memory, Runtime Snapshot, Capability Catalog

The CenterPanel top bar also had an **intent badge** showing the current
intent (Code/File/Chat/Search/Shell/Memory).

These surfaces were redundant with the Agent Workspace (B-9) and
conflicted with ADR-34's parent-first contract: intent classification
is no longer a routing owner, and the pipeline visualization implied a
linear `Intent Classify → ... → Execute` flow that no longer matches the
model-owned initialization + evidence/synthesis loop.

## Fix

### 1. Deleted `ObservabilityTab.tsx` (457 lines)

The entire component is removed. The Anomaly Alerts, Runtime Snapshot,
and Capability Catalog sections were nice-to-have but not required by
ADR-34. They can be re-extracted as reusable components in a future
session if needed.

### 2. `RightPanel.tsx`

- Removed `ObservabilityTab` import.
- Removed `Eye` icon from `lucide-react` import (only used by Observe tab).
- Removed `ObservationData` and `CapabilitiesData` from type imports.
- Removed `observation` and `capabilities` props.
- Removed `'observability'` from the `RightTab` union — now
  `'terminal' | 'memory' | 'agents'`.
- Changed default tab from `'observability'` to `'agents'` (ADR-34 B-9
  canonical surface).
- Removed the Observe tab entry from the `tabs` array.
- Removed the `{activeTab === 'observability' && <ObservabilityTab …/>}`
  render block.

### 3. `CenterPanel.tsx`

- Removed `Wrench` icon from `lucide-react` import (only used by intent
  badge).
- Removed `INTENT_LABELS` map (6 entries + aliases).
- Removed `currentIntent?: string` prop.
- Removed `currentIntent` from destructure.
- Removed the intent badge render block:
  ```tsx
  {currentIntent && (
    <div … title={`Intent: ${currentIntent}`}>
      <Wrench … />
      <span>{INTENT_LABELS[currentIntent] || currentIntent}</span>
    </div>
  )}
  ```

### 4. `WorkspaceLayout.tsx`

- Removed `useCapabilities` from imports + the `const capabilities =
  useCapabilities()` call (no longer consumed by any panel).
- Removed `currentIntent` from the `useChat` destructure.
- Removed `currentIntent={currentIntent}` prop pass to CenterPanel.
- Removed `observation={liveObservationForPanel}` and
  `capabilities={capabilities}` prop passes to RightPanel.
- The `useObservability` hook and `liveObservationForPanel` merge logic
  are retained — they feed `CenterPanel.contextTokens` (the context-window
  occupancy meter), not the Observe tab.

### 5. Internal compat fields retained (backend still emits)

The following are kept as internal state/compat — no UI renders them:
- `ObservationData.intent` field (`types/index.ts`)
- `IntentType` type (`types/index.ts`)
- `StageTiming` interface + `stageTimings?` on `ObservationData`
- `ObservabilityResponse` interface + `intent`/`stage_timings` fields
  (`client.ts`)
- `localmindClient.getObservability()` method (endpoint stays)
- `useObservability` hook (feeds `liveObservationForPanel`)
- `currentIntent` state + `setCurrentIntent` calls in `useLocalMind.ts`
- `liveObservation.intent` writes
- `_toolToIntent()` helper
- `case 'intent':` SSE handler
- `intent_classified` obs_event handling
- `classifyClientIntent()` client-side hint + `X-LocalMind-Intent` header
  (ADR-11 dispatcher hint, separate concern)

No new routing or UI behavior depends on these fields.
