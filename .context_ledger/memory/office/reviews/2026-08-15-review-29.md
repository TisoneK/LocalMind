# Session 225 Review — B-2026-08-14-8 Parent Evidence and Final-Synthesis Boundary

- **Date:** 2026-08-15
- **Agent:** Super Z / GLM-5.2 (Z.ai cloud sandbox)
- **Core:** 0.5.0
- **Target:** ADR-34 B-8 — parent evidence and final-synthesis boundary
- **Feature:** adr-34-realtime-workspace

## Problem

ADR-34 §3: "Evidence has one owner. Every tool result is returned to the
parent model as bounded evidence/context before synthesis. The UI may
stream the same evidence into Agent, Actions, and Terminal nodes, but
tool output must not populate the assistant's final answer. Only parent
synthesis may emit final chat content."

The codebase had an "authoritative sysinfo" shortcut in
`core/agent/loop.py` (lines 3193-3220) that VIOLATED this contract:

```python
if (
    tool_name == "sysinfo"
    and not tool_failed
    and _is_current_system_query(_user_message_text(messages))
):
    authoritative_answer = _authoritative_sysinfo_answer(
        observation,
        _user_message_text(messages),
    )
    yield StreamChunk(text=authoritative_answer, done=False)  # ← RAW TOOL OUTPUT
    yield StreamChunk(text="", done=True, usage=dict(_provider_usage))
    return
```

This code extracted the raw `"Current date/time: ..."` line from the
sysinfo tool output and yielded it DIRECTLY as the final assistant
answer — bypassing the parent model entirely. The user saw the tool
output as the chat content, not a model-synthesized response.

The user's complaint was exactly this: "the final output comes from the
tool not agent itself" and "Tool results should be passed to the
agent/llm then it decides on how to display the results not directly
from the tool."

## Root cause

The shortcut was added (Session 142 era) to prevent small models from
corrupting dates during paraphrase (e.g. "August 14" → "August 1").
While the concern was valid, the implementation violated the
evidence/synthesis boundary: code, not the model, decided the final
answer for time queries.

## Fix

### 1. Removed the authoritative sysinfo shortcut (`loop.py`)

The entire `if tool_name == "sysinfo" and _is_current_system_query(...):`
block is gone. After sysinfo (or any tool) returns, the loop now:

1. Appends the bounded tool result to `loop_messages` as a `"tool"` role
   message (unchanged).
2. Emits a new `evidence_to_parent` obs event marking the boundary:
   ```python
   _obs.emit(
       "evidence_to_parent",
       tool=tool_name,
       iteration=iteration + 1,
       evidence_chars=len(safe_observation),
       failed=tool_failed,
   )
   ```
3. Continues the loop — the parent model sees the evidence on the next
   iteration and synthesizes its own response.

The model may still choose to report the date/time verbatim — but that
is the model's decision, not a code shortcut. The `_authoritative_sysinfo_answer`
and `_is_current_system_query` helpers remain in `text_tools.py` for
the shell→sysinfo correction path (`_normalize_system_tool_call`).

### 2. Strengthened the synthesis directive (`_force_final_answer`)

Both `framing="limit"` and `framing="final"` directives now include an
explicit SYNTHESIS instruction:

```
SYNTHESIS: Do NOT copy the tool output verbatim. Synthesize a
natural-language answer that addresses the user's question using
the evidence. Report exact values (dates, numbers, names) from
the tool output, but frame them in your own words.
```

This reinforces the anti-fabrication directive with a positive
synthesis contract.

### 3. Existing delegation boundary (`chat.py`)

The `_visible_tool_output` function in `chat.py` already hides
delegation tool output (`delegate`, `delegate_parallel`,
`delegate_inline`) and child-agent-tagged tool calls from the chat
channel. This was verified by `test_visible_tool_output_hides_delegation_results`.

## Acceptance evidence (live Zen `laguna-s-2.1-free` smoke)

Message: "What is the current date and time? Use the sysinfo tool."

```
tool_call: sysinfo started (iteration 1)
tool_call: sysinfo done — output: "Current date/time: Friday, August 14, 2026  08:39:06 PM (UTC, UTC+0000)"
evidence_to_parent: tool=sysinfo, iteration=1, evidence_chars=193, failed=False
```

The model then produced (before a 503 rate-limit cut it off):

```
"The current date and time is **Friday, August 14,"
```

This is a MODEL-SYNTHESIZED response using markdown formatting and the
model's own phrasing — NOT the raw `"Current date/time: ..."` line that
the old shortcut would have yielded. The exact date/time value is
preserved (anti-fabrication directive), but the framing is the model's.

Before B-8, the final answer would have been:
```
"Current date/time: Friday, August 14, 2026  08:39:06 PM (UTC, UTC+0000)"
```
— the raw tool output line, yielded directly by code.
