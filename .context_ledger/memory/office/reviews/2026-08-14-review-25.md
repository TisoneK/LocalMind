# Review — ADR-32 fail-fast provider errors

## Executive Summary

The Session 220 handoff was completed. LocalMind now terminates a substantive parent turn immediately when the first provider call returns an exhausted-quota 429, authentication/permission error, or payment error. The error remains a raw internal `StreamChunk.error` until `chat.py` applies the existing ADR-20/21 canonical normalizer and emits the user-facing error card.

## Discovery Phase

- The adapter already classified permanent quota/billing 429 responses, but the final-response path still issued an unnecessary extra request after closing the response.
- `AgentLoop._plan_stream()` treated every planning error as non-fatal, so a terminal first provider error could be swallowed before the parent decision call.
- `AgentRuntime` dropped `done=True` error chunks and then generated the generic no-usable-answer fallback.
- The direct conversational boundary remains before parent setup; greetings do not acquire an adapter or run a preflight.

## Findings and Fixes

### High — terminal provider errors were swallowed at the parent boundary — fixed

Planning errors were logged and ignored, and runtime error chunks could be consumed as completion bookkeeping. Added the shared ADR-21 envelope-based terminal classifier, a `TerminalProviderError` boundary for planning, and runtime forwarding of error chunks. Terminal errors now stop before `chat_with_tools` and reach `chat.py:normalize_error()`.

### Medium — permanent 429 still caused an extra request — fixed

The adapter had removed backoff but re-sent the request after closing a permanent 429 response. It now returns the buffered response directly; final transient 429 attempts also return directly rather than issuing a fourth request.

## Regression Coverage

- Terminal quota 429 during planning: one planning call, zero parent tool calls.
- Transient per-minute 429: existing parent path continues.
- 401, 402, and 403: classified terminal.
- Runtime forwards terminal error chunks instead of producing the generic fallback.
- Existing greeting zero-provider-call regression remains green.
- Existing adapter 429 and canonical SSE normalization tests remain green.
