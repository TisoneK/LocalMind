# Review — Current-weather freshness guard

**Date:** 2026-08-14
**Session:** 198
**Agent:** Buffy / openai/gpt-5.6-luna
**Scope:** backend web-search extraction and synthesis

## Finding

A Kitengela weather request asked for current conditions on August 14, 2026. The search output contained a same-day August 14 result and an older August 8 result. The synthesis layer passed both snippets to the model without a deterministic freshness boundary, allowing the model to answer with the stale August 8 evidence.

The machine clock and repository were current; this was an evidence-selection problem, not a clock or search-availability problem.

## Fix

- Detect time-sensitive queries such as weather, current conditions, prices, news, and forecasts.
- Parse explicit month-name, ISO, and numeric dates from numbered search-result blocks.
- When a same-day dated result exists, remove explicitly dated non-current blocks before sufficiency checking and synthesis.
- When no same-day dated result exists, do not present dated evidence as current; return an honest gap report.
- Preserve ordinary research behavior for non-time-sensitive queries and undated search results.
- Add prompt rules reinforcing that current answers must not use older dated evidence as current.
