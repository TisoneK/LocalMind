## Part 1 — Where glm-5.3-flash's >60s of silent "thinking" goes (bankofai)

**Owner's symptom:** in the LocalMind app on bankofai/glm-5.3-flash, a small-talk turn sat silent for >1 minute, then one short thought ("Brief capability summary.") and the answer appeared together. Same provider + key + model in the app answers in ~2s on qwen3.8-flash. Owner challenge that shaped the diagnosis: "ZCode runs on glm-5.3-flash too and it's fast."

### Code findings (read, not changed)

- Small talk → social fast path = ONE provider call; persisted `latency_ms` is honest wall time turn-start→stream-end (`agent_runtime.py` fast-path epilog). No hidden multi-call inflation.
- The adapter streams with zero buffering: every SSE `reasoning_content` delta yields an immediate `StreamChunk.thinking` (`openai_compat.py` `_chat_openai_style`), forwarded chunk-by-chunk by the fast path (`trivial_input.py::_direct_chat_response`). Qwen's live-streaming thinking in the owner's own export proves the pipe end-to-end.
- On bankofai the app sends NO `thinking` / `reasoning_effort` param (zai-only gating; `localmind_reasoning_effort` unset by default) — GLM-5.3 runs always-thinking at the upstream's default.
- 429 retries: max 3 attempts, waits ≤10s — cannot account for 107s.

### Live probe 1 — the app's real fast path, both models (12 calls)

`scratch/probe_glm_latency.py`, evidence `scratch/sse-glm-latency-s471.json`. Same prompts as the owner's export, interleaved:

- glm on clean calls: TTFB 1.9–2.3s, thinking trickles (7–40 chunks), done by 2.1–2.9s — **the model is not inherently slow**.
- glm under contention: one call TTFB 15.4s → entire answer 250ms later → ~9s dead-air tail before stream close. 3 of 12 calls 429'd outright.
- qwen: TTFB ~1.6–2.2s consistently, reasoning streams incrementally, wall 2.3–4.2s.

### Live probe 2 — differential, request shape excluded (18 calls)

`scratch/probe_glm_diff.py`, evidence `scratch/sse-glm-diff-s471.json`. LocalMind's byte-exact request shape vs five one-variable variants (no `stream_options`, no temperature, browser UA, curl/HTTP-2, ~25k-token prompt): **all healthy calls 2.3–4.4s TTFB, no variant separates**; reasoning streamed from the first byte in every success (`first_reasoning == ttfb`). 2 calls rate-limited even at 5s spacing — the free promo tier is hair-triggered.

### ZCode cross-check (the owner's challenge, resolved)

ZCode's config on this machine carries provider `18ae0130-…` → `https://api.bankofai.io/v1` (openai-compatible) with glm-5.3-flash reasoning=max — i.e. **this very session runs on the same gateway/key path as the app**. Same endpoint, same key, same shape (V0) is fast *now*.

### Verdict

**The stall is time-variable congestion in bankofai's glm-5.3-flash upstream pool, not the app, not the model, not the request shape.** The owner's 107s turn = pre-first-byte queue (its 27 completion tokens generate in well under a second once started; "thought appears at once" = the whole sub-second generation arriving after the queue clears). Qwen answered fast in the same minute → per-pool capacity, not network/key. ZCode feels immune because agent turns are minutes apart (rate limit never trips) and seconds-blips vanish inside long turns. Nothing in LocalMind's streaming path is broken — live-verified on its exact current shape.

**Verification split:** live-verified = both probes + config cross-check; code-read = adapter/fast-path/latency accounting; assumed/not-reproduced = the exact 107s magnitude (best on-demand catch: 15s TTFB + 9s tail); tonight the pool is healthy.

**Levers (owner's call, NOT implemented):** no-first-byte watchdog (surface "waiting for provider…" instead of silent thinking, offer qwen fallback); per-model health memory; note the dead-air tail inflates `latency_ms` even on quick generations. The 120s chat timeout is the cliff edge — a longer queue becomes an error card.

## Part 2 — What to import from ZCode (tools architecture etc.)

Grounded in first-hand harness knowledge + on-disk inspection of ZCode's plugin/skill layout and LocalMind's tool bench (~38 tools). Ranked against the Parent-only architecture (ADR-53).

### Already covered — do NOT rebuild

Tiered lean schemas + on-demand `describe_tool` (ADR-40 ≈ ZCode's CORE set, shipped earlier); tool-result index (`search_tool_results` — LocalMind is AHEAD; ZCode bounds differently); skill system (`backend/data/skills/<slug>/SKILL.md`, YAML frontmatter, prompt-injection via the `skill` tool — ZCode's exact pattern, unprefixed by packaging); `todo_write`; propose→apply staged-edit approval; file/ops core (shell, file_reader, file_writer, edit_file, code_exec, process, git, diagnostics, web_search, web_fetch, browser); AGENTS.md entrypoints (ledger covers); context compaction.

### Tier 1 — the genuine gaps (priority order)

1. **MCP client support.** ZCode speaks `mcp__server__tool` natively; its plugins ship `.mcp.json` so a plugin installs *tools*, not just instructions (verified: android-emulator plugin). LocalMind has zero MCP code. Biggest interoperability lever: one client (start with stdio + streamable-HTTP transports) and the 38 bespoke tools stop being the capability boundary.
2. **Read-only Explorer subagent** (ZCode's `Explore` pattern). A disposable Parent TOOL — not a peer — with a read-only sandbox and the contract "return the conclusion with `file:line` refs, not file dumps." Pieces exist (search_tool_results, dir_explorer, parked delegate plumbing); missing the sandbox + bounded-conclusion output contract. Largest context-economy win for broad sweeps.
3. **Fresh-eyes acceptance judge** (ZCode `judge` pattern). Read-only; re-reads a finished deliverable against the ORIGINAL request; returns structured per-item pass/fail verdicts with evidence; the loop is forbidden from grading its own work. Deepens ADR-18 verification-first; fits Parent-only as a verification tool.
4. **Plugin-style skill packaging.** Versioned, namespaced (`plugin:skill`), marketplace cache dir, seed manifest, `also loadable as` aliases, bundleable scripts + `.mcp.json` + commands, plus a `skill-creator`-style authoring skill. Turns skills from dev-dropped files into an agent-extensible ecosystem.

### Tier 2 — worthwhile, lower urgency

- **web_fetch prompt-distillation:** fetch → small model answers a prompt against the page; ~15-min cache; returns conclusions, not page dumps (pairs with search_tool_results).
- **Loop-level background execution:** fire a long command, keep working, get re-invoked on completion (process tool exists; the completion-notification wiring doesn't).
- **Structured clarifying questions** (AskUserQuestion shape): options + previews + multiSelect instead of free-text round-trips.
- **Plan mode:** explore-only phase with explicit approval gate before changes (propose/apply covers edits; this covers "touch nothing yet").

### Deliberately NOT imported

ZCode/Codebuff-style live multi-agent delegation (spawn agents, agent-to-agent messaging) — parked compatibility residue per ADR-53. The explorer/judge shapes above are read-only Parent tools and keep that line intact.
