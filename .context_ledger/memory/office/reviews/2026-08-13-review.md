## Executive Summary

Context-only session per the user's "agentic workflow" target (chat-message
target overrides the standing ADR-8 target per `.context/kickoff.md`). Ran

The headline finding: the user's diagnosis is **structurally correct** but
**less severe than Session 152 believed**. Session 152 (the original ADR-18
documentation) and Sessions 173-175 have closed three of the six primitives
(Act with iteration cap + workspace feedback, Verify with a real
criteria_gate, Remember with failure_memory). The remaining four gaps are
all in the **front half of the loop** (Understand, Plan) and in the
**Observability that makes the loop visible to the user**.

Concretely: on most turns, `TaskState.success_criteria` is empty (only 2
call sites populate it, both conditional on the LLM deciding to emit it), the
`AgentOrchestrator.replan()` method is dead code (0 callers, replaced
in-path by a self-contained `_replan_for_gate` LLM call), the planning
stream is free-text injected into the system prompt with no structured DAG,
and the frontend ignores 4 of the 5 backend events that would make the
verify→replan loop visible to the user.

**No product code changed this session** (deliberate: this is the discovery
session). Implementation begins Session 177.

## Discovery (code-verified this session)

Read the actual source for each claim made in the prior audit; verdicts
below.

### Claim 1 — `is_done()` stubs across the 6 agents

**PARTIALLY CONFIRMED.** Session 173-174 closed two of six:

| Agent | `is_done` body | Status |
|---|---|---|
| coding | `criteria_gate(trace, "criteria not yet met")` | REAL (Session 173) |
| verifier | `criteria_gate(trace, "verification criteria not yet met")` | REAL (Session 174) |
| browser | `return False, ""` | STUB |
| analyst | `return False, ""` | STUB |
| debugger | `return False, ""` | STUB |
| reviewer | `return False, ""` | STUB |

Shared gate: `core/agent/verify.py:332-368`. Even with a real gate, when
`trace.success_criteria == []` it short-circuits to `(False, "")` at
`verify.py:354-355` — so on most turns it's still a no-op (see Claim 3).

### Claim 2 — `AgentOrchestrator.replan()` is dead code

**CONFIRMED.** `agent/orchestrator.py:361-511` defines a real `replan()`
method (with timeout + fallback). `grep` for `\.replan\(` across
`backend/src` returns **0 hits**. The only use of `_agent_orchestrator` in
the pipeline is at `_pipeline.py:175` (constructor) and `:912`
(`.orchestrate(` — NOT `.replan(`).

The in-loop verify-fail path lives in `agent/loop.py:3931-3988`
(`AgentLoop._replan_for_gate`). It builds its own messages and calls
`active_adapter.chat(...)` directly (`loop.py:3972`). The orchestrator
never sees the failure, never re-routes to a different agent, never updates
confidence. This is the single biggest reason the system can't switch from
"coding" to "debugger" mid-task.

Three obs events emitted only by the dead `replan()` method
(`orchestrator_replan_start`, `orchestrator_replan_done`,
`orchestrator_replan_timeout`, `orchestrator_replan_failed`) are also dead
code — they are never reachable.

### Claim 3 — `success_criteria` rarely populated

**CONFIRMED.** `TaskState` (`agent/task_state.py:42-55`) has the field. But
only **2 sites** populate it with non-empty data:

1. `tools/subgoal.py:193` — when the model explicitly invokes the
   `create_plan` tool with a `criteria` argument.
2. `core/thinking_dispatcher.py:1398-1403` — parses
   `plan_dict.get("success_criteria", [])` from the dispatcher's
   LLM-generated `execution_plan`.

The other 5 sites (`base_agent.py:377`, `_pipeline.py:2528/3431/3487`,
`loop.py:1177/1414/1686`) only forward the value. On any turn where the
dispatcher LLM doesn't emit `execution_plan.success_criteria` AND the model
never calls `create_plan`, `trace.success_criteria == []` and the
criteria_gate short-circuits — the legacy model-assertion path runs
unchanged.

This is the root cause of "feels like generative + tools": the verifier is
real, but the contract it would verify against is usually empty.

### Claim 4 — Verifier only runs when `intent == VERIFY`

**PARTIALLY CONFIRMED.** The verifier *agent class* still only routes via
`selection.py:82` (`Intent.VERIFY → "verifier"`). But Session 174 added a
second path: `_pipeline.py:119-163` defines
`_HIGH_STAKES_INTENTS = {FILE_WRITE, FILE_EDIT, CODE_EXEC}` and
`_verifier_acceptance_gate` that calls `is_verifier_done`. Picked via
`_acceptance_gate_for(intent)` at `_pipeline.py:3489` (main loop) and
`:1723` (escalate path).

But: this is the loop's in-head criteria gate using the verifier's
`is_done()`, NOT a separate post-execution verifier agent stage. And since
`is_verifier_done` short-circuits when `success_criteria == []` (see Claim
3), on most file-write/code-exec turns it still no-ops.

### Claim 5 — `_plan_stream` is free-text injected into prompt

**CONFIRMED.** `agent/loop.py:4135-4237` (`_plan_stream` async generator)
collects raw text chunks. `loop.py:1357` joins them, truncated to 1500
chars. `loop.py:1376` calls `_parse_plan_steps` (in `text_tools.py:36-67`)
which extracts only the numbered "STEPS:" block for the Todos panel UI —
**the parsed list is never fed back into execution**. The raw prose is
injected into `build_agent_system_prompt` at `loop.py:1479-1487`.

So the plan is a block of text the model sees, not a program the engine
drives. This means: no per-step state machine, no `depends_on` enforcement,
no per-step `token_budget` or `iter_budget`, no per-step success criteria.

### Claim 6 — `WorkspaceOrchestrator` only used for read-only paths

**CONFIRMED.** `workspace/orchestrator.py:578-598` (`_should_use_orchestrator`)
returns `intent not in {CHAT} and intent not in AGENT_INTENTS`. The
`AGENT_INTENTS` set (`agent/constants.py:148-173`) excludes essentially
every substantive intent (CODE_EXEC, FILE_*, SHELL, GIT, VERIFY, REVIEW,
DEBUG, ANALYZE, etc.). The call site additionally excludes WEB_SEARCH and
WEB_FETCH (`_pipeline.py:2150-2155`). Only `SYSINFO` (and a handful of
internal delegation/proposal intents the planner doesn't recognize)
survives — so the structured `depends_on` DAG only runs for read-only
sysinfo, exactly where it's least needed.

### Claim 7 — Memory is flat vector store with bolt-ons

**PARTIALLY CONFIRMED.** `MemoryComposer` (`memory.py:59-65`) wraps a
single `VectorStore`; `failure_memory.py` exposes three free functions
(`classify_failure`, `build_failure_summary`, `format_recall_hint`) with no
VectorStore and no shared state with `MemoryComposer`.

There IS one coordinated merge point: `_pipeline.py:1974-1990` appends the
failure-memory hint as a single string onto the end of `memory_facts`
before the loop sees it. So they are independent in storage/retrieval but
merged in consumption — not fully independent, but the merge is invisible
from either module's docstring and there is no unified taxonomy.

### Claim 8 — Frontend ignores gate/replan events

**CONFIRMED.** `grep frontend/src/` for the 5 backend event names:

| Backend event | Emitted at | Frontend consumers |
|---|---|---|
| `agent_loop_gate_passed` | `loop.py:1722` | NONE |
| `agent_loop_gate_failed_replan` | `loop.py:3913` | NONE |
| `orchestrator_replan_start` | `orchestrator.py:403` (DEAD — see Claim 2) | NONE |
| `orchestrator_replan_done` | `orchestrator.py:473` (DEAD) | NONE |
| `agent_loop_failure` | `loop.py:3854` | NONE (consumed only by backend at `_pipeline.py:3531`) |

The user sees: text streaming in, tool cards appearing, todos flipping to
done. That's the "generative + tools" UX. The user never sees "I verified X
passed", "I replanned because Y failed", "I'm now switching to the
debugger agent."

## Findings

### Architectural (High — flag for backlog, do not implement without ADR update)

- **F1 — `AgentOrchestrator.replan()` is dead code.** Replaced in-path by
  `AgentLoop._replan_for_gate` (a self-contained LLM call). The
  orchestrator never sees failures, never re-routes, never updates
  confidence. The verify→replan edge of the Observe→…→Continue loop is
  structurally half-built. Fixing this is the biggest single change that
  would make the system feel agentic. (Files: `agent/orchestrator.py`,
  `agent/loop.py`.)
- **F2 — No structured Goal Interpreter.** The raw user prompt is never
  turned into a typed `{goal, constraints, success_criteria, capabilities}`
  before work begins. `TaskState.success_criteria` is empty on ~90% of
  turns because only 2 sites populate it, both conditional on LLM
  emission. The verifier has nothing to verify against — so "done" is
  still effectively a model assertion. (Files: new `agent/goal_interpreter.py`,
  `agent/task_state.py`, `engine/_pipeline.py`.)
- **F3 — Planner emits prose, not a DAG.** `_plan_stream` produces free-text
  injected into the system prompt; `_parse_plan_steps` only feeds the
  Todos UI, never drives execution. No per-step state machine, no
  `depends_on`, no per-step `token_budget`/`iter_budget`/`success_criteria`.
  (Files: `agent/loop.py`, new `agent/planner.py`, `agent/task_state.py`.)
- **F4 — Frontend phase visibility is zero.** 4 of 5 backend
  verify/replan/failure events are completely ignored by the frontend. The
  user cannot see "I am planning", "I am verifying", "I am replanning
  because X failed". (Files: `frontend/src/hooks/useLocalMind.ts`,
  `frontend/src/types/index.ts`, new `frontend/src/components/chat/AgentPhases.tsx`.)
- **F5 — `WorkspaceOrchestrator` excludes all substantive intents.** The
  only intent that survives `_should_use_orchestrator` is `SYSINFO`. The
  structured `depends_on` DAG only runs for read-only sysinfo, exactly
  where it's least needed. Multi-step coding tasks go straight to
  `AgentLoop` with no structural plan. (Files:
  `workspace/orchestrator.py`, `engine/_pipeline.py`.)

### Code-quality (Medium — safe to fix in subsequent sessions)

- **F6 — 4 dead `is_done` stubs** (browser, analyst, debugger, reviewer)
  still `return False, ""`. The shared `criteria_gate` would make them
  real with a one-line change each (same pattern as coding/verifier).
- **F7 — 4 dead obs events** (`orchestrator_replan_start/done/timeout/
  failed`) emitted only by the dead `replan()` method. Either wire the
  method or delete the events.
- **F8 — `_plan` non-streaming variant is dead code** (`loop.py:4239`,
  marked at `:4248-4252`). Safe to delete.
- **F9 — Memory merge at `_pipeline.py:1974-1990` is undocumented.** The
  failure-memory hint is appended to `memory_facts` but neither
  `MemoryComposer` nor `failure_memory` mentions this contract. A new
  agent reading either module in isolation has no idea the merge exists.

## Recommended ADR Updates

- **ADR-18 P0 — mark as needing refinement.** The P0 acceptance gate
  shipped in Sessions 173-174, but it short-circuits whenever
  `success_criteria` is empty — which is most turns. ADR-18 P0 should be
  extended to cover the Goal Interpreter (F2), not just the gate itself.
- **New ADR-19 — Structured Plan DAG.** The current "plan is free-text
  injected into the prompt" architecture cannot support per-step state
  machine, `depends_on`, or per-step budgets. Needs a fresh ADR before
  Session 179 implements it.
- **New ADR-20 — Frontend Phase Visibility.** The frontend currently has
  no concept of "phases". Adding one is a UI architecture decision that
  needs an ADR before Session 180 implements it.
