## Executive Summary

The terminal (`TerminalPanel`, 721 lines — deferred from S213 as broad)
was already fairly complete (native caret, header running pulse,
auto-scroll). The key restraint here: **terminal output must not be
animated** — it can be high-volume and per-line motion would stutter. So
the alive cues are cursor/state-based, not output-based:

- a **blinking block cursor at the idle, empty prompt** (hidden once the
  user types — native caret takes over — or while running);
- a **live "executing…" cursor line** at the bottom of output while a
  command runs, so the shell visibly works before the first output line
  lands; auto-scroll now also fires on `isRunning` so it stays in view.

The blink is a CSS keyframe that holds steady under
`prefers-reduced-motion`. No change to the emulator's I/O, tab
completion, history, keyboard handling, or command submission.

## Design note (why no output animation)

Every other alive surface (S210–214) animates items in. The terminal is
the deliberate exception: streamed command output can be large and fast,
and animating each line would introduce jank and layout thrash. The
liveness cue belongs on the cursor and run-state, not the output stream.
