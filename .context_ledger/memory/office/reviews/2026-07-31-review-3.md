# Tools Target Audit — 2026-07-31

## Executive Summary

The kickoff target was **Tools**: trace why the application feels disconnected when a user sends a message, identify concrete inconsistencies, and fix them one at a time. The first end-to-end trace covered the React chat hook, native fetch/SSE client, FastAPI chat route, engine pipeline, observability bridge, agent selection, and tool dispatch.

One reproducible message-path defect was fixed and pushed in `be7dd56`: file-upload/storage failures emitted an untyped SSE payload that the frontend ignored, leaving an empty assistant bubble after the stream completed. The backend now emits the same typed `error` + `done` events used by engine and adapter failures, with a regression test.

The broader system is not yet fully connected. The next confirmed transport issue is in the frontend SSE parser: it does not flush a final buffered `data:` event when a stream ends without a trailing newline. That can hide the final response token or completion event and should be the next focused fix.

## Finding Fixed

### Medium — upload failures were invisible to the chat UI

**Root cause:** The upload exception path returned `{"error": ..., "done": true}` without a `type` field. The frontend switch in `useLocalMind.ts` only handles `type: "error"`; the untyped payload fell through to the default branch, then the stream ended and the assistant message could remain empty.

**Fix:** `backend/src/api/routes/chat.py` now emits:

- `{"type": "error", "error": ...}`
- `{"type": "done"}`

**Regression:** `tests/api/test_chat.py::TestChat::test_upload_failure_emits_typed_error_event` forces the upload path to fail and asserts both events are present.

## Remaining Findings

### High — final buffered SSE event can be lost

`frontend/src/lib/localmind/client.ts::streamChat()` splits each decoded chunk on newline and retains the last partial line in `buffer`. When `reader.read()` returns `done`, it exits without parsing that remaining buffer. A server/proxy that closes after a valid `data: {...}` line without a final newline can therefore lose the final token, `done`, or error event. This is the next smallest fix: centralize one SSE-line parser and flush `buffer` after the read loop, with a client-level regression test if the frontend test harness is introduced.

### High — agent abstractions are only partially connected to the engine

`agents/selection.py` and the directory-based agents exist and are tested, but `selection.py` documentation still states that the existing engine pipeline does not call it directly. The engine imports and runs `AgentLoop` across multiple branches. This is consistent with ADR-8 being multi-phase, but it explains why the code feels advanced yet disconnected: the agent registry and agent-specific workflows are not the sole runtime path. Do not broadly rewire this during a transport fix; schedule a separate integration pass with real-model validation.

### Medium — task-type routing has a fallback-heavy contract

ADR-8 Phase 4 exposes `select_agent_by_task_profile()`, but it falls back to intent routing whenever `primary_domain` is empty or unknown. That is safe for compatibility but means task-type routing is not guaranteed for every request. Add observability/tests around which routing path was actually used before removing the fallback.

### Medium — frontend state has defensive races and silent failures

`useChat` contains several guards for session-history overwrites, StrictMode, stuck streams, and session changes. This is valuable evidence of prior production failures, but many API hook errors are intentionally swallowed (`catch { /* keep */ }`). The next UI pass should surface connection state and distinguish “no data yet” from “request failed,” without changing the successful stream path.
