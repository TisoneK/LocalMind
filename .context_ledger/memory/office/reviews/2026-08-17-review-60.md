## Findings & fixes

### Bug D+E — `deepseek-v4-free` defaulted for Ollama; Ollama model not remembered → FIXED (`ad21e23`)
- **Shared root cause:** the Ollama chat model was persisted through the
  ambiguous generic `model` key (interpreted per `adapter`). (D) Switching
  provider→ollama with no model left a stale cloud model in `model`, which boot
  loaded as `ollama_model` (config.py line 337). (E) `select_model` never
  persisted the Ollama model — only the cloud branch did.
- **Fix:** a DEDICATED `ollama_model` key. `select_model` + `set_adapter`
  persist it; `load_runtime_settings` reads it and treats the generic `model`
  key as CLOUD-ONLY. **Live-verified across a reboot:** a stale
  `deepseek-v4-flash-free` is ignored (model=''→auto→phi4-mini), and a selected
  Ollama model (phi4-mini) survives restart; `shell_enabled=True` too.

### Bug B — no UI toggle for the shell tool → FIXED (`ad21e23` backend, `774129d` UI)
- `GET /api/settings` now returns `shell_enabled`; `POST /api/settings/local`
  sets it (boolean-safe write, persisted); `load_runtime_settings` restores it.
  A themed on/off switch in the Settings modal. Off by default (safety).
  Live-verified it persists across a reboot.

### Bug A — "Loading settings…" lag + not theme-oriented → FIXED (`774129d`)
- The modal blocked on sequential `getModels`/`getEmbeddingModels` (which prime
  Ollama `/api/show`, seconds). Now reveals right after the essential settings
  load; lists populate in the background. Loading state is a themed panel
  (theme tokens) instead of bare muted text on the backdrop.

### Bug C — context-window field didn't reflect the selected model → FIXED (`774129d`)
- The num_ctx field now shows the selected model's effective window as its
  placeholder (e.g. "32768 (auto)") and updates on model switch. Blank = auto;
  a number pins a custom window. Preserves the 0=auto backend semantics.
