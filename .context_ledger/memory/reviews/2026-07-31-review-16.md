# Review — 2026-07-31 — Explicit worker-to-report handoff

## Scope

Implemented a deterministic worker-to-report boundary for successful tool
execution. The change addresses the observed failure where a shell command
succeeded but the model returned only a heading such as "Here's what's in Dev:"
without reporting the directory contents.

## Delivered

- Added `WorkReportEntry` and `WorkReport` dataclasses in
  `backend/src/core/agent/models.py`.
- Derived reports from `AgentTrace` evidence rather than adding another model
  call, keeping the handoff deterministic and inspectable.
- Made evidence detection observation-first. A substantive successful result
  requires at least two matching evidence tokens when multiple tokens exist;
  side-effect-only results such as `OK` still allow concise confirmations.
- Integrated report enforcement into normal, short-stream, and forced final
  synthesis paths.
- Buffered terminal stream markers so worker evidence is emitted before the
  final `done=True` chunk.
- Preserved evidence in forced synthesis error/exception paths.
- Recorded late MiniMax/XML-intercepted non-search tool executions in the
  trace, while preserving the dedicated web-search synthesis path.
- Added regression coverage for heading-only shell responses, evidence-aware
  responses, side-effect-only success, forced synthesis report ordering, and
  the existing silent-failure scenarios.

## Validation

- Python compile checks passed for edited source and tests.
- Ruff import checks passed for the edited regression file.
- Ruff passed for the new agent model file.
- `git diff --check` passed.

## Review verdict

Ship-ready. No blockers remain.

## Follow-up

Keep the report contract deterministic and evidence-first. Future work may
promote `WorkReport` to a broader execution-result protocol shared by delegated
agents, but should preserve the current no-extra-model-call fallback and stream
ordering guarantees.
