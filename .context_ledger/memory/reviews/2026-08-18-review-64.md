## Discovery / key finding

The spec (§1, §9, §36) is a **single-agent-first** program: the Parent Agent is
the entire autonomous layer this phase; specialists, delegation, and
multi-agent orchestration are explicitly out of scope until the single-agent
runtime is proven reliable.

The shipped codebase has already run ahead of that:
- `backend/src/core/agent/delegation.py`, `backend/src/tools/delegate.py`,
  `backend/src/tools/delegate_parallel.py`, `tools/delegate_inline.py`,
  `tools/best_of_n_edit.py` — 262 references across `backend/src`.
- `docs/ARCHITECTURE.md` advertised `delegate / delegate_parallel → isolated
  specialized child agents` as part of the core model.

Conversely, the spec's *loop* is already substantially built and is exactly what
ADR-33/34/36/37/38/42/43/45/46 have been incrementally hardening
(`backend/src/core/agent/orchestrator.py`, `loop.py`, `goal_interpreter.py`,
`task_state.py`, `verify.py`, `post_execution_verifier.py`, `synthesizer.py`).
So the spec is best read as: the loop is real and maturing; delegation is the
one piece that jumped ahead of the stated phase.

## Colab addendum — Buffy (Freebuff) verification (2026-08-18)

Joined the colab after Claude Code captured the spec. Independently verified the
reconciliation against the code — and it **understates** the divergence. The spec
is not "single-agent-first with delegation accidentally shipped"; the whole
multi-agent layer the spec defers (§36) is already built AND is the live runtime:

- **`ParentAgent` is the runtime entry point, not a plan.** `core/agent_runtime.py`
  instantiates it (L667: `parent = ParentAgent(...)`); its module docstring says
  "The ParentAgent owns the actual decision loop and tool/delegation choices." Its
  own `description()` is already the spec's §38 *future* form — "delegates bounded
  cross-domain work to specialized agents."
- **The parent contract already encodes §41 + §38.** `agents/parent/context_builder.py`
  carries the closed loop (understand → check state → choose tools → observe →
  replan/delegate → don't claim success without evidence) AND the delegation rules
  ("delegate only bounded work … children do not inherit this history").
- **11 specialist agents are registered** (coding, research, browser, direct,
  verifier, reviewer, debugger, analyst, context_pruner, editor_selector, parent) —
  the exact "specialist agents" §36 says are *excluded this phase*.
- **Full delegation machinery:** handoff (`delegate`), parallel fan-out
  (`delegate_parallel`), inline mutation (`delegate_inline`), best-of-N
  (`best_of_n_edit`).
- **`selection.py` is now UI metadata:** "the parent runtime does not use this
  module for request-time routing … the parent delegates through the native
  delegation tools" (ADR-8 Phases 3–4 complete).

Net: the spec is no longer a build roadmap — it is a **quality bar** (esp. §40's
12 criteria: goal accuracy, tool selection, verification, honest completion) for a
system that has already run ahead of it. This sharpens B-2026-08-18-1: it is not
"should we add delegation later" but "the multi-agent layer exists and is wired —
freeze/hide it, rip it out, or accept we are ahead and steer remaining work toward
§40 hardening." Read-only verification; no code or memory state touched by this addendum.
