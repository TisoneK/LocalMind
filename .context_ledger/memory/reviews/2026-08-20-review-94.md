# Review — Session 330: synthesize/evaluate stage — fixed goal checklist gates completion

- **Date:** 2026-08-20
- **Agent:** Buffy / deepseek/deepseek-v4-flash (per system prompt)
- **Target:** the user's consolidated finding (transcript): "implement a synthesize/evaluate
  stage — goal-derived fixed checklist, real comparison of tool outcomes against it, completion
  gated on that comparison, not on tool-call success." Root-cause framing the user endorsed:
  the three observed failures (premature completion, todos mutating to match whatever ran, and
  the 2/2-100% lie on recon-only stops) are symptoms of ONE missing piece — no fixed
  goal-checklist held independently of execution; nothing checked outcomes against it before
  declaring completion.
- **ADR:** ADR-54 appended (completion gated on a goal-derived fixed checklist).
- **Commit:** `30e37b8` (product) + memory surface (this file).

## Executive Summary

Implemented the synthesize/evaluate stage on the warm-kernel parent path:

1. **Fixed goal checklist derived from the USER message** (`derive_goal_items`, deterministic,
   ZERO LLM calls — a regex pass per turn). A named file with a write verb, or a folder with a
   create verb, becomes a checkable goal item ("file exists at a.txt with content", "folder
   created at path-test"). Conversational/abstract requests derive [] → no contract → the
   legacy model-assertion path is unchanged. This is the fixed denominator: the user's request
   defines "done" up front; the checklist never mutates to match what ran.
2. **Wired as BOTH the Todos plan and the gate contract** (agent_runtime → parent.run →
   loop.run): `plan_steps=goal_items` (emitted up front as plan-0..N, pending) and
   `success_criteria=goal_items` (the acceptance-gate contract), with `skip_head_gate=True` so
   the criteria gate at the FINAL-ANSWER point — never at the iteration head, where a
   criteria-verified stop would end the turn with a bare "✓ n/n" before the model's synthesis.
3. **The gate no longer accepts a goal-checklist turn with zero tool evidence.** Live-found
   hole: the run-scoped evidence guard (`no tool ran → accept`) silently completed a turn where
   the model answered "I'll set up the tools needed for file operations." with zero tool calls,
   zero files, and all 3 goal todos flipped complete. With a goal checklist present, zero tool
   outcomes now means all criteria unmet → replan while iterations remain → honest-stop at the
   cap.
4. **Honest stop surfaces the truth:** at the cap with unmet criteria, the loop emits
   `agent_loop_gate_honest_stop` + completes only the PASSED goal items; the SSE bridge
   (`_finalize_plan_todos(..., skip=True)`) no longer flips the unmet items to complete — the
   panel shows the true fraction, never a false 100%.
5. **Windows-separator tolerance in evidence matching** (verify.py `_norm`): a criterion from
   the user's forward-slash message matches tool evidence the model wrote with backslashes —
   same disease family as S264/S325.

## Findings

1. **(High, fixed) No success contract on the warm-kernel parent path.** agent_runtime passes
   no success_criteria; the gate's no-criteria branch accepts any final text (modulo the narrow
   completion-floor / prose-commitment / hedge nudges). Confirmed in code and reproduced live.
2. **(High, fixed — live-found) The run-scoped evidence guard auto-accepted no-tool turns for
   goal-checklist criteria.** First live trace on the new build reproduced the user's exact bug:
   model produced one token ("I'll set up the tools needed for file operations."), no tools, no
   files, yet the turn completed with 3/3 todos. Fixed by falling through to evaluate_criteria
   (all-unmet) when a goal checklist is present.
3. **(Medium, fixed) The finalize lie.** `_finalize_plan_todos` marked ALL remaining plan todos
   complete at turn end ("done or moot") — even on a recon-only stop. Now skipped when the
   honest-stop signal fired.
4. **(Medium, fixed) Iteration-head gate would stop too early.** With criteria present,
   `is_parent_done` → `criteria_gate` would pass at the iteration head right after the last
   tool landed — ending the turn with a bare "✓ n/n" before the model's final synthesis (and
   before a requested read-back). `skip_head_gate` keeps the gate at the final-answer point.

## Fixes Applied

- `goal_interpreter.py`: `derive_goal_items(message)` + folder/file token extractors.
- `agent_runtime.py`: derive goals per parent turn; emit `agent_goal_checklist`; pass
  plan_steps + success_criteria + skip_head_gate.
- `loop.py`: `skip_head_gate` param (iteration head); `plan_steps` param threaded into the
  final-answer gate; `_emit_honest_stop()` (event + per-goal todo state); zero-evidence goal
  turns fall through to evaluation instead of auto-accept.
- `chat.py`: `_finalize_plan_todos(session_id, skip=...)`; honest-stop captured from
  `obs.history()` before the drain, applied at both finalize sites.
- `verify.py`: `_norm()` backslash tolerance in `_check_file` evidence fallback +
  `_fallback_evidence`.
- `base_agent.py`: pass-through `skip_head_gate`.
