## Executive summary

The "tool-discovery churn" on unambiguous file creates was **not** schema
discovery — `file_write` and `file_task` are both always-present core tools, so
no `describe_tool` round-trip ever happened. The real mechanism was a **prompt
contradiction**: the injected safety workflow (`backend/data/workflows/safety.md`)
demanded "Before `file_write`: check if `<path>` already exists", while
CRITICAL RULES #7 in the same system prompt said "to CREATE a file … call
file_write directly … do NOT list the folder first". The model resolved the
conflict toward the read-oriented probe (`file_task` → `not_found` → write),
then added a verification shell call.

Fix: a **create-shape exception** in the safety workflow plus matching
create-shape hints in the `file_write`/`file_task` tool descriptions. The
model-agnostic principle (per the owner's standing rule: cure the disease, not
one prompt): the request's SHAPE decides the check — a create request names the
path and the content, so the create itself is the check, and the runtime's
existing write verification delivers the on-disk evidence inside the write
result rather than in a round-trip before it. Overwrite protection is kept in
full for MODIFY-shaped or ambiguous requests.
