# Review — 2026-08-01 — Session 64

## Executive Summary

Implemented backend provider prompt-token telemetry so the Observe panel can populate Context Tokens from real provider usage rather than relying only on estimates. The change is additive: adapters normalize usage, the AgentLoop and Engine preserve it across tool and synthesis boundaries, and the existing estimation fallback remains available when providers omit usage.

## Scope

- Normalized OpenAI-compatible usage fields (`prompt_tokens`/`completion_tokens`, input/output aliases, and totals).
- Normalized Ollama native terminal counters (`prompt_eval_count`/`eval_count`) and nested OpenAI-style usage.
- Added provider usage to `StreamChunk` and propagated it through text streams, terminal frames, tool-call results, AgentLoop reconstruction, forced synthesis, and fallback/error paths.
- Updated Engine `turn_complete` observations to prefer real prompt counts and include `provider_usage` consistently across chat, agent, file-task, file-write, sub-agent, code-exec, memory, and final paths.
- Added a compatibility retry that removes optional `stream_options.include_usage` only when a provider rejects the field with an explicit 400/422 unsupported-field response.
