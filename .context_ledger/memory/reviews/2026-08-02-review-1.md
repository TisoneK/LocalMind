## 1. Executive Summary

Codebuff is an open-source, multi-agent, model-agnostic coding assistant that orchestrates ~12 specialized agents (file-picker, planner, editor, reviewer, basher, thinker, librarian, browser-use, context-pruner, etc.) via a single recursive `loopAgentSteps` runtime. It ships as a CLI (`codebuff`), an SDK (`@codebuff/sdk`), and a free ad-supported variant (`freebuff`). All LLM traffic routes through Codebuff's backend → OpenRouter, giving per-agent model selection (Opus for orchestrator/thinker, Gemini Flash Lite for basher/file-picker, MiniMax M3 for free tier, DeepSeek for code-review).

The comparison surfaced **LocalMind's biggest functional gap: no parallel delegation**. LocalMind's `delegate` tool is strictly handoff (`parallelizable=False`, `tools/delegate.py:486`); Codebuff's `spawn_agents` fans out N children concurrently via `Promise.allSettled` (`spawn-agents.ts:89`). Without parallel delegation, LocalMind cannot express best-of-N editing, parallel research+coding, multi-perspective review, or speculative execution.

Conversely, **LocalMind's clearest advantages are persistent semantic memory** (sqlite-vec + nomic-embed-text, passive retrieval every turn — Codebuff has no vector memory) **and the `.context/` multi-session protocol** (git-tracked, typed memory files — Codebuff has only static `knowledge.md`/`AGENTS.md`).

This review produces **12 concrete borrowing recommendations** across three tiers (5 low-risk borrow-now, 4 medium-risk post-ADR-8, 3 high-impact needs-cloud-routing), filed as backlog items `B-2026-08-02-1` through `B-2026-08-02-12`. The top 5: bounded output buffer, abort signal threading, tool-result simplification under memory pressure, parallel delegation primitive, per-agent model routing.

## 4. Findings (by severity)

Findings here are **borrowing opportunities**, not bugs in LocalMind. Each is scored on impact (what it unlocks), effort (line count), risk (what it could break), and model-readiness (works with `llama3.1:8b` or needs a stronger model?). Full detail in the companion session notes.

### Critical (high-impact architectural gaps)

**F1 — No parallel delegation primitive.** LocalMind's `delegate` tool is strictly handoff (`tools/delegate.py:40-46`, `parallelizable=False` at line 486). Codebuff's `spawn_agents` runs N children concurrently via `Promise.allSettled` (`spawn-agents.ts:89`) with an implicit await barrier. Without this, LocalMind cannot express: best-of-N editing, parallel research+coding, multi-perspective review, speculative execution. This is the single biggest functional gap. **→ B-2026-08-02-6** (Tier B).

**F2 — No per-agent model routing.** Every LocalMind agent uses the same model (`OLLAMA_MODEL` env var). Codebuff's `AgentDefinition.model` field lets each agent pick its own OpenRouter model — Opus for orchestrator/thinker, Gemini Flash Lite for basher/file-picker, MiniMax M3 for free tier, DeepSeek for code-review (`agents/base2/base2.ts:32-51`). Not every agent needs the same model size. **→ B-2026-08-02-10** (Tier C).

### High (significant capability gaps)

**F3 — No propose-stage tools.** Codebuff's `propose_str_replace` / `propose_write_file` (`common/src/tools/params/tool/propose-*.ts`) stage edits without applying, enabling best-of-N selection. LocalMind's `edit_file` / `file_writer` commit immediately — the model must pick one edit, run it, observe failure, retry. **→ B-2026-08-02-7** (Tier B).

**F4 — No abort signal threading.** LocalMind's `AgentLoop.run()` has no clean cancellation path. Codebuff threads `AbortSignal` through every layer (`RunOptions.signal`, `sdk/src/run.ts:175`); `loopAgentSteps` checks `signal.aborted` at the top of each iteration (`run-agent-step.ts:985`). The UI cannot cleanly cancel a running agent. **→ B-2026-08-02-2** (Tier A).

**F5 — No inline delegation (parent-context mutation).** Codebuff's `spawn_agent_inline` (`spawn-agent-inline.ts:26-178`) lets a child share the parent's `messageHistory` and overwrite it — enabling the `context-pruner` pattern (transparent context compaction before every main-agent step). LocalMind's strict isolation model forbids this, which is safer but blocks the pattern. **→ B-2026-08-02-9** (Tier B, riskiest).

**F6 — Hard output cap loses error context.** LocalMind's `code_exec` caps output at 4000 chars (`localmind.md:111`), `shell` similarly. When a command produces 50KB, the agent sees only the head — the error message is often in the tail. Codebuff's `BoundedOutputBuffer` (`run-terminal-command.ts:80-144`) keeps head + tail with a `[...TRUNCATED DUE TO LENGTH...]` marker. **→ B-2026-08-02-1** (Tier A).

### Medium (polish + UX)

**F7 — No steering without aborting.** Codebuff's `drainSteeringMessages` (`run-agent-step.ts:684-688`) lets the host inject user messages at step boundaries without aborting — smoother UX than cancel-and-re-run. LocalMind has no equivalent. **→ B-2026-08-02-5** (Tier A).

**F8 — Oldest-first trimming loses narrative.** LocalMind trims oldest-first near the context limit (`localmind.md:163`). Codebuff's `simplifyReadFileResults` / `simplifyTerminalCommandResults` replace old tool results with stubs (`{ path, contentOmittedForLength: true }`) — the model still sees *that* a file was read, just not its contents. More token-efficient. **→ B-2026-08-02-4** (Tier A).

**F9 — No subgoal scratchpad.** Codebuff's `add_subgoal` / `update_subgoal` / `create_plan` tools give the model a structured per-run scratchpad. LocalMind's plan is injected as text but can't be updated mid-run. **→ B-2026-08-02-8** (Tier B).

**F10 — Delegation failure messages are generic.** When `delegate` times out, the parent gets `ERROR: delegation to 'research' timed out after 120s`. A diagnostic message would distinguish timeout-vs-iteration-limit-vs-model-overload (extending LocalMind's own Session 32 hit-limit-aware pattern to delegation). **→ B-2026-08-02-3** (Tier A).

### Low / Nice to Have

**F11 — No skills system.** Codebuff's `skill` tool loads markdown skill files on-demand — a lower-friction extension mechanism than full agent definitions. LocalMind's extension story requires a full agent directory (5+ files). **→ B-2026-08-02-12** (Tier C).

**F12 — No best-of-N editor pattern.** Codebuff's `editor-multi-prompt` (`agents/editor/best-of-n/editor-multi-prompt.ts:58-246`) spawns N editors with different strategy prompts, a selector picks the winner, the parent applies it. Structurally impossible in LocalMind today (depends on F1 + F3 + F2). **→ B-2026-08-02-11** (Tier C).

### Where LocalMind already wins (no action needed)

- **Persistent semantic memory** — sqlite-vec + nomic-embed-text, passive retrieval every turn. Codebuff has nothing equivalent.
- **Multi-session `.context/` protocol** — git-tracked, typed memory files (tasks, backlog, ADRs, flaws, inefficiencies, sessions, system, user). Codebuff has only static `knowledge.md`/`AGENTS.md`.
- **Strict delegation isolation** — immutable `DelegationInstructionPacket` (`core/agent/delegation.py:23-140`), untrusted-evidence delimiters (`--- BEGIN UNTRUSTED EVIDENCE ---`), `forbidden_tools` propagation, explicit output requirements. Codebuff's spawn is looser.
- **Hit-limit-aware fallback messaging** — Session 32 contract: when `trace.hit_limit` is True, say "iteration limit reached" and suggest "tell me to continue" (never "switch to a larger model"). Codebuff's `STEP_WARNING_MESSAGE` is generic.
- **Local-first operation** — runs entirely on the user's machine via Ollama; no cloud dependency, no API costs, no data egress. Codebuff requires OpenRouter.

### What NOT to borrow (would be regressions)

- **XML-tag tool calling** — LocalMind already has native function calling via Ollama/OpenAI-compat. Switching to XML would be a regression.
- **Centralized backend routing** — Codebuff routes all traffic through `codebuff.com`. LocalMind is local-first by design.
- **Agent Store** — Codebuff publishes agents to a store. LocalMind is single-user desktop; agent sharing is lower priority.
- **`handleSteps` generator** — powerful but adds significant complexity (stringified functions, `eval`, no closure capture). LocalMind's playbook.md approach is simpler.
- **`set_messages` / `add_message` tools** — letting the model rewrite its own history is dangerous without strong guardrails. The controlled `delegate_inline` (B-2026-08-02-9) is the safe version.

## 6. Open Items

All 12 borrowing recommendations are filed in `.context/memory/tasks/backlog.md` as `B-2026-08-02-1` through `B-2026-08-02-12`, grouped into three tiers:

- **Tier A (borrow now, low-risk):** B-2026-08-02-1 (bounded output buffer), -2 (abort signal), -3 (delegation diagnosis), -4 (context compactor), -5 (steering).
- **Tier B (borrow after ADR-8):** -6 (parallel delegation), -7 (propose-stage tools), -8 (subgoal scratchpad), -9 (inline delegation).
- **Tier C (borrow when cloud routing lands):** -10 (per-agent model routing), -11 (best-of-N editor), -12 (skills system).

### Open questions for the maintainer (resolve before Tier B/C)

1. **Is parallel delegation in-scope for local-only setups?** Ollama serializes requests by default (`OLLAMA_NUM_PARALLEL=1`). Running 3 CodingAgent children in parallel would either queue at the Ollama layer or require `OLLAMA_NUM_PARALLEL=3` (3× memory pressure). Decision needed: is B-2026-08-02-6 a local-model feature, a cloud-model feature, or both?
2. **Is per-agent model routing acceptable given the local-first value prop?** Letting CodingAgent use `zen:deepseek-v4-pro` while DirectAgent uses local `qwen2.5:1.5b` means some agent calls egress to the cloud. User must opt in via `.env`, but the architectural commitment matters.
3. **Should `propose_*` tools be CodingAgent-only or available to all agents?** Codebuff exposes them to editor agents only. BrowserAgent (propose a click sequence) or ResearchAgent (propose a search strategy) could benefit.
4. **What's the migration path for `should_use_sub_agents()`?** ADR-8 Phase 3 deprecates it, but the legacy framework (`sub_agent.py`, ~50KB) is still present. B-2026-08-02-6 should not coexist with it long-term.
5. **Should the `context-pruner` pattern (B-2026-08-02-9) replace oldest-first trimming, or coexist?** The current trimming is simple and predictable. A `ContextPrunerAgent` is more token-efficient but adds an LLM call per step. Trade-off needs measurement.
