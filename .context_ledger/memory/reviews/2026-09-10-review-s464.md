## Findings

### 1. HIGH — `grep_search` is unreachable by the model (pre-existing) → B-2026-09-10-8

**Description.** `backend/src/tools/grep_search.py` registers a `grep_search`
tool under `Intent.GREP_SEARCH` (added by B-2026-08-23-31, commit `f632ca6`),
and both `agents/selection.py:82` and `agent/tool_dispatch.py:32` route that
intent. But the name appears in **none** of the three model-facing tiers in
`backend/src/core/agent/tool_schemas.py`: not in `TOOL_DEFINITIONS`, not in
`CORE_TOOL_NAMES`, not in `LONG_TAIL_TOOL_NAMES`.

**Evidence it was never exposed** (not dropped later):
`git log -S'"grep_search"' -- backend/src/core/agent/tool_schemas.py` is empty.
The tier-split assertion `CORE_TOOL_NAMES | LONG_TAIL_TOOL_NAMES == catalog`
passes only because `grep_search` is in no tier at all.

**Impact (live, this session).** Prompt *"Search all text files in my Documents
folder for the word 'invoice'"* → the model selected **`shell`** and hand-rolled
`grep -rniE --include=…`. It never had the option of the bounded content tool,
because the model cannot see it.

**Why nothing fails loudly:** the shell guard (B-2026-08-25-1) *deliberately*
lets bounded searches through — `test_bounded_or_non_search_commands_pass`
explicitly lists `grep -rn foo backend/src` as permitted. So the fallback is
legal by design and the gap is silent.

**Recommendation.** Decide one, per B-2026-09-10-8: **expose** `grep_search`
(add to `TOOL_DEFINITIONS` + a tier + `AGENT_ALLOWED_TOOLS` +
`INTENT_TOOL_SCOPES` + a classifier route, minding Session 400's "one search
front door" rationale — a second name-affinity search tool can re-split
weak-model traffic — then live-verify selection per ADR-40), **or retire it**
(remove registration, `Intent.GREP_SEARCH`, its routes, and its unit test).

### 2. MEDIUM — a model-facing description named a tool the model cannot see (fixed)

`dir_explorer`'s description told the model: *"For finding files by name/content
use system_search/grep_search"*. Naming an unreachable tool actively mis-steers.
Fixed in `ef1c7cd` (phantom reference dropped; description shortened, staying
inside the pinned lean budget). Re-verified live afterwards per ADR-40: selection
still **3/3 dir_explorer** (list PASS, stat PASS, tree BLOCKED on a 429).

### 3. MEDIUM — stale pin left by this feature: a NEW failure on `main` (fixed)

`tests/core/test_describe_tool_on_demand.py::test_tier_split_covers_catalog_exactly`
asserted `len(CORE_TOOL_NAMES) == 11`, but promoting `dir_explorer` to CORE took
it to 12. The test **fails on main**, and it is **not** in
`scripts/pytest-baseline.txt` — so `ci-check.sh` reports it as a new failure.
S462 updated the lean-surface pins (`test_tool_schemas_lean.py`) but missed this
one. Fixed in `e61fd9f` (pin 12, plus assert `dir_explorer` is in the core set).
Confirmed pre-existing by running it with this session's edits stashed.

### 5. HIGH — three more `dir_explorer` wiring/budget leftovers, all failing on `main` (fixed)

Found by the exit gate after the first closeout attempt (`ci-check` reported 5 new
failures; 2 were the unrelated date-bombs of Finding 6). All three are the same
class as Finding 3 — the feature shipped without finishing its wiring — and all
three were confirmed **not** this session's doing (this session's commits touch
only 3 files, none of them the failing ones):

1. **`test_list_intent_mappings_covers_all_intents`** — `Intent.DIR_EXPLORER` was
   added with no entry in `agents/selection.py`'s `_INTENT_TO_AGENT`, so the intent
   had no routing anchor at all. Fixed: route it to `coding`, alongside
   `system_search` (`a69b8cc`).
2. **`test_every_non_excluded_intent_has_a_template`** — no `GoalInterpreter`
   template for `DIR_EXPLORER` and no exclusion either. Fixed: add it to the
   test's `_EXCLUDED_INTENTS`, matching the existing `GREP_SEARCH` /
   `SEARCH_TOOL_RESULTS` precedent — a read-only inspection reports what is there
   and has no checkable goal contract (`a69b8cc`).
3. **`test_system_prompt_within_budget[sysinfo]`** — the executor prompt grew to
   11,355 chars against an 11,200 budget. The growth is `dir_explorer`'s own
   steering (planning templates + `TOOL ARGUMENT` rule, injected into every
   execute intent); `sysinfo` holds the tightest budget. Fixed by justifying and
   raising to 11,500 — the test's own instruction is "trim or justify", and the
   alternative was trimming the guidance the tool needs (`f2cb8fb`).

These three plus Finding 3 mean the feature's CORE promotion was closed out of
its own pin ledger: it updated the lean-surface pins but left four other tests
that assert on the tool catalog / intent set. **A green suite is not a claim
about a new tool's wiring; this is the concrete cost of treating the pins as
optional.**
