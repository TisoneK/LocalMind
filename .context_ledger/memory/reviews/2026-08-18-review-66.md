## Verdict

The parent's **contract text is a faithful, compact encoding of the spec's §41**
and it is genuinely injected into the model (not dead). But there is **one real
gap**: the parent's *deterministic completion-verification floor is not wired* —
absent model-volunteered criteria, "done" on the user-facing path rests on model
assertion. And the parent's **identity is written in the spec's §38 _future_
form** (delegation-forward), which is the parent-level face of the ADR-47 / §36
divergence.

## The headline gap — the parent's completion-verification floor is unwired

Spec §6 ("Done means the outcome is achieved AND **verified against success
criteria**"), §29 ("distinguish *action succeeded* from *objective succeeded*"),
§30 ("perform an appropriate verification step before declaring completion").
On the live parent path, three facts combine:

1. **`parent.run(...)` passes no success contract.** `agent_runtime.py:678-691`
   calls `parent.run(...)` with **no `success_criteria=` and no `plan_steps=`** →
   `BaseAgent.run` default `success_criteria=None` (`base_agent.py:230`).
2. **The deterministic backfill is dead code.** `GoalInterpreter`
   (`goal_interpreter.py`) was built (ADR-18 P0+) exactly to derive criteria
   when the model omits them — but **nothing in production imports or calls it**.
   The only `GoalInterpreter()` instances are inside `goal_interpreter.py` (a
   docstring example at :55, an unused module default at :373); the only import
   is the docstring (:53). So `TaskState.success_criteria = list(trace.success_criteria)`
   (`loop.py:922`) is **empty unless the model itself calls `create_plan` with
   criteria**.
3. **The F4 secondary net is skipped for the parent.** `post_execution_verify`
   only runs for high-stakes intents `{file_write, file_edit, code_exec, shell}`
   (`post_execution_verifier.py:137-144, 170`). The parent's turn intent is fixed
   at `Intent.ANALYZE` (`agent_runtime.py:680`) and is **never reassigned** in the
   loop (per-tool intents use separate vars `tc_intent`/`tool_intent`; `intent` at
   `loop.py:4011` is still ANALYZE) → `post_execution_verify` returns
   "skipped — non-high-stakes intent" for every user-facing turn.

**Net:** when the model does not volunteer `create_plan` criteria (the common
weak-model / simple-execute case), `is_parent_done → criteria_gate` sees empty
criteria, passes vacuously, and the parent stops on the **model's own "done"** —
with no deterministic objective-level verification. This is precisely the §29
failure mode ("completion = a model generated an answer").

**Caveats (kept honest):** this is a *floor* gap, not "no verification." (a)
Per-write **grounding/read-back** ([VERIFICATION]/[GROUNDING CHECK]) still fires
for `file_write` regardless of intent — write *correctness* is still checked, just
not objective *completion*. (b) When a capable model *does* emit `create_plan`
criteria, the gate enforces them fully. The gap is that there is **no
deterministic floor** for the turns that need it most.

## IMPLEMENTED (same session, `fd48db5`)

The headline gap is now closed. `parent_completion_floor_note` (loop.py) + an
`is_parent` branch in `_acceptance_gate_at_final_answer`: when the parent claims
done with no criteria and its last high-stakes tool failed, the gate rejects
"done", injects a recovery block, and continues (bounded by the existing
iteration + same-tool-streak caps). Failure is judged by `tool_failed` OR the
reused F4 `verify_last_tool_succeeded` observation check — the latter was
necessary because `shell.py` returns a nonzero-exit command with `success=True`,
so `tool_failed` alone misses command-level failures (found via live-testing).

LIVE-VERIFIED (glm-4.5-flash, isolated 8765): failing `cat` → floor fires (1
`gate_failed_replan`), model forced to continue and resolve; `echo` success → 0
fires, iter=2. Backend 1947/0 (+10 floor tests). The chosen design's tradeoff
(same as the shipped F4 verifier: a legit `grep error` could trip it, bounded by
caps) is documented in the helper. The identity divergence (§38 form) remains
part of B-2026-08-18-1.
