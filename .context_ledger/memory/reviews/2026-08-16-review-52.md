# Review 52 — Generalize reasoning handling beyond zai/GLM (Session 276, B-7)

**Agent:** Claude Code (claude-opus-4-8) · **Platform:** macOS (local) · **Core:** 0.5.0
**Commit (product):** `b3f489d` — `feat(adapters): generalize reasoning handling beyond zai/GLM`

## Trigger
User, on a gpt-oss-120b/cerebras trace: "the agent streamed thinking into chat" +
"we have only trained glm-4.5-flash to actually think and act but not other
models." Then: "we already saw how the thinker made the agent efficient and
precise even on lesser model — so that shouldn't be a question" (i.e. generalize
it; don't treat the token cost as a blocker).

## Root cause (grounded, not assumed)
1. **Live probe of cerebras/gpt-oss-120b** (delta key-names only, no secrets):
   reasoning arrives in a **`reasoning`** field — NOT `reasoning_content`, no
   `<think>`, no harmony markers. `_extract_content_and_reasoning` only read
   `reasoning_content`/`<think>`, so gpt-oss reasoning was missed (not routed to
   the ThinkingBlock).
2. **`thinking_enabled` returned False for every non-zai provider** (openai_compat
   .py:722) — and the loop gates the mid-loop **Thinker consult** and the
   thinking-aware timeout on it. So the Thinker (the thing that made glm-4.5-flash
   efficient/precise) NEVER ran for gpt-oss/cerebras or any other provider.

## Fix
- `_extract_content_and_reasoning`: read `reasoning_content` OR `reasoning` — any
  capable model's thinking routes to `StreamChunk.thinking`, not the chat answer.
- `thinking_enabled`: True for all capable providers (z.ai keeps its own GLM-5.3
  force-enabled logic first); tunable off via `LOCALMIND_THINKING=disabled`.
- Safety: it stays a read-only signal. The z.ai `thinking` REQUEST param and its
  one-shot override are gated to zai in `_add_provider_params` (broadening the
  signal must not send a `thinking` key to cerebras/gemini); `force_off` is
  read+cleared for ALL providers so it never lingers and suppresses reasoning_effort.

## Verification
- **Live (cerebras/gpt-oss-120b), per system/live-testing.md:** `agent_thinker_start`
  + `agent_thinker_done` fired (the Thinker now consults for gpt-oss — it never did
  before), 30 thinking tokens streamed to the thinking channel (not leaked into
  chat content), and `shell` ran (the model acted). The turn's final synthesis hit
  cerebras's known tokens/min rate limit — a provider cap (present in the user's
  original trace too), not this change.
- 31 adapter + 366 agent/loop tests pass; +3 tests (reasoning-field extraction,
  precedence, thinking_enabled tunable-off for non-zai); ruff clean. Updated the
  ADR-41 non-zai test: thinking_enabled is now True (Thinker applies), request
  param still absent.

## Honest limit / owed
- The exact original "thinking in chat" symptom (#1) wasn't reproduced pre-fix
  (reasoning is a separate field, so it was more likely dropped than leaked); the
  fix routes it correctly regardless, verified live.
- cerebras rate-limits the synthesis call — the md→docx / count tasks still can't
  fully COMPLETE on cerebras free tier. Generalized reasoning is orthogonal to that
  quota; a headroom provider or a paid tier would show full completion.
- The empty-after-reasoning one-shot-off recovery stays GLM-specific (it's a GLM
  quirk); other models didn't need it in the trace.

## Relates to
ADR-41 (native reasoning — now provider-generic, not zai-only), ADR-42 (Thinker —
now reaches all capable models). Closes B-2026-08-16-7. Standing principle: "use
any capable model; a model failing is OUR bug."
