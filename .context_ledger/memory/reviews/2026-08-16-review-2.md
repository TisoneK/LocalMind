# Review — 2026-08-16 (Session 247)

## Executive Summary

Investigated the user report that the agent "combines words in its reply"
(e.g. a web-search answer rendered as "HereHere arethe trending
storiesIfound fortoday"). Root cause: the final-synthesis path streamed
each delta through the TRIMMING `_strip_minimax_tool_calls`, whose
`.strip()` ate the boundary space between fragments. One-line fix + a
regression test.

## Finding

- **[High] Final synthesis welds words together** — `_force_final_answer`
  (`backend/src/core/agent/loop.py`) applied `_strip_minimax_tool_calls`
  (which ends in `.strip()`) to every streamed chunk. `.strip()` per
  chunk removes the leading/trailing whitespace at every fragment
  boundary, so the joined answer loses the spaces that happened to land
  on a boundary ("Here" + " are" + " the" → "Herearethe"). This is the
  exact Session 231 bug, but in the final-synthesis/rescue path (Session
  231 only fixed the init producer + plan stream). The "HereHere"
  duplication is the heading-only first attempt ("Here") followed by the
  rescue synthesis ("Here are the trending stories…").

## Fixes Applied

- `backend/src/core/agent/loop.py`: `_force_final_answer` now uses the
  whitespace-safe `_strip_minimax_tool_calls_stream` per chunk, matching
  the init + main-loop streaming paths.
- `tests/core/test_final_answer_rescue.py`: added
  `test_synthesis_stream_preserves_interior_word_spaces` — a multi-chunk
  mock stream must rejoin with intact interior spaces.
- `CHANGELOG.md`: Fixed entry.
