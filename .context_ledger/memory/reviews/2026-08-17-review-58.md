## Findings & fixes

### Bug — thinking block not restored on reopen → FIXED (`d161c36`)
- **Cause:** the ThinkingBlock render is gated on `message.thinking &&
  message.isAgent` (ChatMessage.tsx). The history-restore mapping set `thinking`
  but never `isAgent`, while the live SSE path always sets `isAgent:true` for
  assistant turns. So restored assistant messages had `isAgent:undefined` and the
  persisted block was suppressed.
- **Fix:** `getSessionHistory` marks restored assistant turns `isAgent:true`.
  Test extended with the assertion that would have caught it.

### Sweep — the agent's opening acknowledgement lost on reload → FIXED (`5c8d082`)
- Same class as the thinking bug (live-only artifact). The ADR-36 acknowledgement
  ("I'll do X") was shown live but never persisted. Added an `acknowledgement`
  column (idempotent migration), captured from the `agent_initialization_ack` obs
  event at persist time, returned by the history endpoint, restored client-side.
- **Other not-restored fields (lower severity, backlogged):** `thinkMs` (thinking
  duration label — cosmetic), `diffData` (edit_file diff — but the edit is in
  toolCalls), `candidates` (best_of_n — niche). `statusText`/`pendingWrite` are
  transient and correctly not persisted.

### ROOT — "Hi" enters the tool loop / hangs (any model) → FIXED (`035809c`)
- **Model/env-agnostic cause:** `parse_initialization` failed open to `execute`
  on any unparseable classify output. The tool loop — the most expensive,
  unbounded, only state-changing path — was the DEFAULT-when-confused, for every
  model. Capable models hide it (they usually emit clean JSON); everything else
  fell into the loop. phi4-mini hanging on "Hi" (screenshot: execute, 0 tokens,
  0 steps, 247s) is the visible instance.
- **Fix:** EXECUTE IS OPT-IN. The tool loop requires an explicit, parseable
  `mode:"execute"`. Every uncertain outcome (unparseable, unknown mode, direct
  w/o answer, clarify w/o question) → a bounded DIRECT answer built from the
  model's own output (`_salvage_response`: a model that "fails" the JSON contract
  usually just answered in prose — that prose IS the answer). Loop timeout/error
  fallbacks now salvage the partial stream instead of discarding it.
- **Also:** direct turns now report the init call's real provider usage (was
  dropped → inflated estimate; surfaced by a test that got 797 vs 84); the init
  decision is logged with `mode + confidence + raw snippet` so an operator can
  SEE why a turn went direct vs execute ("what is actually happening?").
- **ADR-46** records the principle: the tool loop is opt-in, never the fallback.

### S289 reframing
- The `slow_provider` init-timeout (ADR-45) is now SECONDARY: a timed-out init no
  longer hangs — it resolves to a bounded direct answer. The compact-init-env
  (S289) already applies to ALL providers in code (only the comment framing said
  "local"). The context-window detection (ADR-44) stands as a correct root fix.
