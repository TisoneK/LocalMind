# Review — ADR-40 option B shipped: lean tool schemas + single-source tool list (Session 251)

**Agent:** Buffy · **Model:** deepseek/deepseek-v4-flash (per system prompt) · **Date:** 2026-08-16 · **Type:** implementation (B-2026-08-16-1)

## Summary

Implemented ADR-40 **option B** (lean-but-callable schemas) end-to-end: the 30-tool catalog that was re-sent on every model call shrank from **24,230 chars (~6,057 est tokens) to 15,981 chars (~3,995 est tokens) — a 34% cut (~2,062 tokens saved per model call)** — while keeping every structural element (names, types, enums, `required`) and all guardrails + weak-model disambiguation. Also collapsed the duplicate tool catalog surfaces to ONE source of truth. **Live-verified tool selection on both the active weak model (z.ai/glm-4.5-flash) and cerebras — no regression.**

## What changed

1. **New `backend/src/core/agent/tool_schemas.py`** — the single source of truth for the model-facing tool catalog. All 30 tool definitions rewritten lean: top-level `description` = name + one-liner + guardrails (e.g. "reset --hard is BLOCKED", "ALWAYS read the file with file_task before editing", "file_task reads FILES, shell lists directories", "use web_fetch AFTER web_search"). Per-param `description` kept ONLY for non-obvious params (browse `@e1` refs, network filters, edit_file action-pairing, git stash/reset modes, delegate agent mapping, …) and guardrail params. Tutorial prose and self-evident param descriptions (path/query/content/message/…) deleted. The optional UI-label `description` param was dropped from 6 tools — safe because the loop already builds structured action labels from path/command/query when the model omits it (loop.py `action_label` fallback; added a `web_fetch` fallback label for parity).
2. **`loop.py`** — the ~900-line inline `TOOL_DEFINITIONS` block replaced with an import from `tool_schemas.py`.
3. **`prompts.py` + `loop.py` call sites** — `build_agent_system_prompt` / `build_planning_prompt` gained a `tool_defs` param: when the loop passes the scoped defs, the in-prompt "Available tools" list is rendered from the SAME source as the native `tools` param (the collapse of the 3 copies). Backward-compatible fallback for other callers (agent_runtime, base_agent, context_pruner). Bonus win: the all-30 in-prompt list shrank 9,832 chars (2,458 tok) → 5,929 (1,482 tok).
4. **Tests** — `tests/core/test_tool_schemas_lean.py` (6 tests): size budget (9k < catalog < 17k chars), structural integrity (all 30 keep `type`/`name`/`description`/`required`), guardrails preserved, `update_subgoal` required stays `["id"]` (status is optional in the tool), `render_tool_list` matches defs, system prompt derives its list from the defs.

## Verification (numbers)

- **Structural parity:** programmatically diffed the new defs against the pre-change HEAD defs (descriptions excluded): names, types, enums, `required`, item schemas, `additionalProperties` are IDENTICAL for all 30 tools. The only structural difference is the intentional removal of the optional `description` label param from 6 tools (web_search, web_fetch, code_exec, file_write, file_task, shell).
- **Tests:** full backend suite **1,770 passed / 2 skipped / 4 pre-existing env-gated `test_shell.py` failures** (same 4 as the 1,764-pass baseline + 6 new). Ruff clean on all touched files.
- **Live trace 1 — z.ai/glm-4.5-flash (the ACTIVE weak model, the ADR's worst-case):** "list the projects in my dev folder" → `agent_initialization_done mode=execute` → **`tool_call: shell` with valid args** (`ls /Users/bao/dev`) → executed, returned real output, model ADAPTED on the failure (`ls /Users/bao` → deeper) → final synthesis emitted. "hi" stayed `mode=direct`, zero tools. **No tool-selection regression on the weak model.**
- **Live trace 2 — cerebras/gpt-oss-120b (capable provider, temp LOCALMIND_HOME, keys never printed):** same task → `mode=execute` → **`tool_call: shell` with valid args** (`ls -1 ~/dev`) → executed. The follow-up synthesis call hit cerebras's known tokens-per-minute cap (`agent_loop_degraded`, `provider_error_code: rate_limit`, `evidence_preserved: true` — the Session 241 path handled it gracefully). Provider-reported `prompt_tokens: 9800` for the turn vs ~14.5k raw estimate for the same task pre-lean (Session 245) — the leaner catalog directly reduces the tokens-per-minute trips that caused this.

## Honest limits

- **B delivers ~36% of ADR-40's theoretical ~5.7k-token reclaimable**, not the ADR's sketched 50-70% — the remaining weight is structural (names, types, enums, `required` ≈ 8,954 chars, irreducible for callable schemas) plus the guardrail/disambiguation prose the ADR says to KEEP. The rest of the reclaim requires **option C** (on-demand loading of the long tail — browse/delegate/sql/csv/json/best_of_n/propose_*/subgoal/skill), which is the next session.
- cerebras's rate-limited synthesis was a provider quota (documented in `system/ai-models.md`), not a schema regression — the tool loop itself verified clean.
