## Findings and Fixes Applied

### Medium — head-only output lost trailing failures

`code_exec` and the shell command path previously retained only the beginning of long output. A traceback or error emitted at the end could be hidden.

**Fix:** Added dependency-light `BoundedOutputBuffer` and `bounded_output()` helpers in `backend/src/core/utils.py`. They preserve short output unchanged and otherwise retain a head, explicit `[...TRUNCATED DUE TO LENGTH...]` marker, and tail within the configured character cap. The helper is thread-safe for concurrent shell stream readers.

### Medium — capture could retain unbounded subprocess output

The shell and code paths captured process output before truncating it.

**Fix:** Code execution now consumes stdout/stderr incrementally with asyncio readers and bounded buffers. Shell execution uses bounded threaded readers with timeout-aware process polling and kill behavior. The combined rendered code-execution result remains within the 4000-character tool budget.
