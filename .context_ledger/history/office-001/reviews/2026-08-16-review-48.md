# Review — Windows shell regression + agent tool-chaining (Session 258)

**Agent:** Buffy · **Model:** deepseek/deepseek-v4-flash · **Date:** 2026-08-16 · **Type:** bug fix (live user report from the Windows app)

## Summary

The user's Windows app showed two failures on "create a recipe on desktop": (1) **"we broke shell"** — a legitimate PowerShell command (`Get-ChildItem -Path $env:USERPROFILE\Desktop`) was rejected with `error_type='nl_dispatch_removed'` before reaching the shell; (2) **the agent doesn't chain tools** — after the shell listing succeeds, it stops instead of calling `file_write` to create the recipe. Both fixed.

## Root-cause findings

1. **Shell regression (`nl_dispatch_removed`):** the loop dispatches the model's `shell(command=...)` through the legacy `dispatch(Intent.SHELL, ...)` → `shell_exec()`. Its Case 2 raw-command gate only routes `_RAW_CMD_TOKENS` (builtins + known command names) plus shell operators (`&& || >> > ; |`). Session 189 told the model it's on **PowerShell** on Windows, so it emits cmdlets — but `Get-ChildItem`'s first token is not in the token set and `$env:USERPROFILE\Desktop` carries no operator, so **every cmdlet fell through to Case 3 and was rejected as `nl_dispatch_removed`**. The irony: `_looks_like_powershell()` (Session 189) and `_looks_like_natural_language()` already treat cmdlets as real commands — only the legacy gate forgot to consult the detector. A quoted literal path (`"C:\Users\tison\Desktop"`) happened to survive via Case 3's quoted-path extraction, which is why the second attempt at 13:41 listed the desktop while the `$env:` variant died.
2. **No tool chaining:** the shell/file_write schemas, the SHELL/FILE_WRITE planning workflows, the Operator persona, and the universal FOLLOW-THROUGH rule never stated the shell→file_write connection. On a weak free-tier model, listing the folder is where the turn stopped (then Session 256/257's think-then-empty compounded it).

## Changes

1. **`tools/shell.py`** — `shell_exec()` Case 2 now also routes `_looks_like_powershell(message)` to `run_command`, so cmdlets with env-var paths or quoted Windows paths reach the shell instead of the NL rejection.
2. **`core/agent/tool_schemas.py`** — shell description: "To CREATE a new file use file_write — do NOT stop after listing a folder if the user asked you to create a file there" + PowerShell cmdlets OK on Windows; file_write description: use the exact folder path from the shell listing (check-before-acting).
3. **`core/agent/prompts.py`** — SHELL workflow gained step 5 (create-file follow-through, PowerShell cmdlets OK); FILE_WRITE workflow gained step 0 (list the target folder with shell first when unsure); universal FOLLOW-THROUGH RULE now says "CHAIN RELATED TOOLS: listing the folder with shell is only the FIRST step — then call file_write with that exact path"; Operator persona gained the chain rule.

## Verification

- 2 new regression tests in `tests/tools/test_shell.py`: `test_env_var_powershell_cmdlet_is_detected` (the exact live-user shape) and `test_legacy_shell_exec_routes_powershell_cmdlet_to_run_command` (pins that the legacy gate never returns `nl_dispatch_removed` for a cmdlet).
- Full backend suite **1,802 passed** — the 4 failures are the same pre-existing env-gated `test_shell.py` shell-disabled failures as every baseline (all 20 shell tests pass with `LOCALMIND_SHELL_ENABLED=true`). Ruff clean. One `test_model_router` env artifact (local `backend/.env` carries `ZEN_API_KEY`, defeating the test's `delenv`) did not reproduce in the full run.
- Prompt/schema edits don't change any pinned test strings (verified by grep before editing).

## Notes for future sessions

- **Two gates, one classifier:** Session 189's PowerShell routing lives in both the `run_command` NL guard and the legacy `shell_exec` dispatch gate — the live bug was the second gate not sharing the detector. Any tool with two entry gates must route both through the same classifier.
- **Prompt-edit trap:** a new line inside a single-quoted Python string literal containing an apostrophe ("don't") silently broke module syntax; caught by the first test run. Use double-quoted literals for prose with contractions.
- Complements Sessions 256/257: even with empty-reasoning recovery, a turn that stops after the listing never reaches the file_write the recovery would nudge. The chaining guidance targets the free-tier model's tool-selection weakness directly; per ADR-40's "don't ship a schema change without live tracing" the descriptions were extended, not trimmed.
