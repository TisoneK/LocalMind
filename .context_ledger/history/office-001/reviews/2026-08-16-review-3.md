# Review — Session 248 (2026-08-16)

## Scope

Four user-reported issues fixed in one session:

1. **New Chat should reset tabs + context counter** (frontend)
   Clicking New Chat now snaps the left panel back to the Chat tab and the
   right panel to the Agents tab, and zeroes the context-window counter.
   Root cause: `handleNewChat` generates a client-side session ID the
   backend doesn't know yet, so the hook's "clear stale data on session
   switch" branch never fired — added an explicit `resetSession()` to the
   `useChat` hook (clears `lastMetrics`, `liveObservation`, `elapsedMs`,
   `sessionStats`) and `forceChatTab`/`onChatTabShown` props on `LeftPanel`
   (mirroring the existing `forceAgentsTab` pattern on `RightPanel`).

2. **Actions shown as pills while active, cards only after session ends**
   The Actions tab branched on `activeToolCalls.length > 0` and rendered
   compact one-line pills during/just after execution; only fell through to
   the expandable `ActionHistory` cards once the list emptied. Removed the
   pill branch entirely — the tab now always renders the cards, and `actions`
   already merges live tool calls with persisted history.

3. **Duplicate messages in transcript after closing/reopening a chat**
   Root cause was BACKEND, not frontend. The guaranteed-persist safety net
   (chat route `finally` block) checked `get_history(session_id, limit=2)`
   which orders ASC — so `limit=2` returned the OLDEST two messages, never
   the just-saved reply. Every reply from turn 2 onward was written twice.
   Fix: added `SessionStore.get_recent_history()` (newest-first) and pointed
   both `_guarantee_persist_assistant` implementations (agent_runtime.py +
   `_persistence_mixin.py`) at it, dropping the now-wrong `reversed()`.

4. **Action card polish** — scrollable body (`max-h-72 overflow-y-auto`),
   copy buttons per section (Input/Command, Error, Output), step number
   stacked on top instead of a left rail (full-width container), and
   pretty-printed + color-coded JSON input.
