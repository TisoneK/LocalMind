# Review — Session 204: authoritative current time/date handling

## Executive summary

A live LocalMind trace for `whats the time?` showed the parent agent first
emitting `shell(command="Get-Date")`, which the structured shell contract
correctly rejected, then calling `sysinfo` successfully. The final model
answer changed the verified date from August 14 to August 1. The defect was in
parent-loop tool selection and final paraphrase handling, not the UI.

## Root cause

The parent-agent contract described `sysinfo` generally but did not make the
clock rule explicit enough for small/free-tier models. The tool loop also
allowed a successful sysinfo result to go through another model-generation
turn, where the date could be corrupted.

## Changes

- Added a parent-agent rule: current time/date/day requests use `sysinfo`
  exclusively, and successful sysinfo output is authoritative.
- Added a narrow deterministic query guard for current time/date/day wording.
- Corrected an accidental parent `shell` call to a `sysinfo` call before shell
  dispatch, including multi-tool calls, while retaining parent-loop ownership
  and observability.
- Terminated clock queries from the loop with the exact verified
  `Current date/time:` line instead of asking the model to paraphrase it.
- Updated environment guidance and added `tests/core/test_system_query_guard.py`.
- Added an Unreleased changelog entry.
