# Review — B-2026-08-25-4: internal "Worker report" format leaking into user-facing answers

**Session:** S469 (Zawadi / glm-5.3-flash, ZCode local, Windows) — 2026-09-11
**Scope:** `fix <the worker-report leak>` — reproduce, fix with regression tests, live-verify.
**Product commits:** `78fadbcc` (fix), `bb9555b1` (changelog).

## Executive summary

The model sometimes appended the house-internal "Worker report — tool
execution evidence:" block verbatim to its user-facing answers (field finding
on bankofai/deepseek-v4-flash: the block appeared INSIDE a model token event —
2 iterations, gate pass, no fallback involved — so the model authored it).

Root cause found: the deterministic worker report is a USER-facing fallback
rendered from the trace (`WorkReport.render()`), but the appended block
persists with the assistant message and flows **verbatim back into the
model's own context** through five history feeds (prompt tail, ParentSession
recent tail, thinker history, memory distill, memory resolver, social fast
path). A model that reads the format back starts mimicking it — the
over-disclosure family the field finding captured.

Fix (model-agnostic, no prompt patch): one canonical strip helper beside the
format owner, applied at every model-facing history feed and at the loop's
full-text emission boundaries. The model never reads the format back; if it
authors a copy anyway, the copy is dropped so the deterministic renderer
stays the only author. The user-facing fallback report is preserved exactly
as designed (it still reaches the user and is still persisted).

## Discovery

- `WorkReport.render()` (`core/agent/models.py`) is the single source of the
  format; the loop appends it when `needs_report()` says the answer quotes no
  tool evidence (short/empty answers, iteration-limit path).
- The appended block is part of the persisted assistant content; the next
  turn's prompt rebuilds the last-8 history verbatim (`agent_runtime` context
  build) — the pollution path. The same content also feeds ParentSession
  `recent_tail` → prompt section, the thinker's pre-tool history, the episode
  distiller, the memory resolver transcript, and the social fast path.
- `presentation.py` is structured-block machinery, not a text boundary — the
  right home for the strip is the format owner (`models.py`) plus the loop's
  emission boundaries, where full text is already available (the S332
  buffering design).

## Fixes applied

1. `core/agent/models.py` — `WORK_REPORT_HEADER` constant (render now uses
   it; the format lives in one place), `strip_worker_reports(text)` (removes
   complete rendered blocks; tolerant of the small drift models introduce —
   `1)` numbering, 1–4 space Output indents; a block requires the exact
   header + at least one entry, so prose mentions never match), and
   `strip_worker_reports_from_history(messages)` for `{role, content}` lists.
2. History feeds stripped (the model never reads the format back):
   `agent_runtime` prompt tail + memory-resolution history,
   `parent_session.update_with_turn`, `trivial_input._direct_chat_response`,
   `memory_resolver.build_resolution_messages`, `episode_memory._build_excerpt`,
   the loop's thinker-history build.
3. Emission boundaries stripped (a mimicked block is dropped before the gate
   evidence check, the flush, and persistence, so `needs_report` evaluates
   the clean answer and the deterministic report still fires):
   both buffered gate-flush blocks in the main loop,
   `_force_final_answer` (rebuilds the buffered replay), and
   `_rescue_final_answer` via the same path. Accepted partial coverage,
   noted honestly: paths that stream text live before the gate (conversational
   fast path) cannot retract already-streamed text — but with clean history
   those turns have no legitimate report in context to mimic.
4. Tests: `tests/core/test_work_report_strip.py` — 14 tests covering the
   strip shapes (exact render, trace-shaped mimicry, hit-limit variant,
   drift tolerance, prose/bare-header non-matches) and the three cheap feed
   boundaries (parent session, resolver transcript, episode excerpt).

## Live verification (the bar: real provider, before AND after)

Scenario (`scratch/s469_worker_leak_trace.py`): boot isolated server on 8765
+ fresh scratch `LOCALMIND_HOME`, adapter bankofai pinned to qwen3.8-flash
(the free tier this account can serve), then a 3-turn conversation in ONE
session — turn 1 a count prompt, turn 2 a terse "reply with ONLY the number"
count prompt (the shape whose answer gets the deterministic report appended),
turn 3 a readback probe ("Repeat your previous reply exactly") that can only
reproduce the internal format if the model's CONTEXT still carries it.

- **BEFORE** (pre-fix code checked out in a throwaway worktree at the fix's
  parent commit, venv junctioned, import precedence verified): turn 2's
  stream ended with the deterministic append (the format planted), and the
  turn-3 readback echo — 743 chars, model-authored — **reproduced the full
  internal report verbatim, including the header and entries**. Pollution
  demonstrated on a real model.
- **AFTER** (fixed main, same scenario, two runs): **zero model-authored
  report text anywhere**. Every header occurrence in the SSE is the exact
  deterministic append shape (`\n\nWorker report — …` as a single trailing
  chunk) or a recorded provider network-error artifact — i.e. the designed
  user-facing fallback, preserved. In the second AFTER run turn 2 planted the
  append exactly as in the BEFORE run, and the next turn's model no longer
  had it in context — its echo contained no report.

Honest caveats: verbatim-echo behavior is model-stochastic run to run (one
BEFORE-side readback echoed just the number); the deterministic proof of the
strip at the prompt boundary is the unit-test layer, and the live runs show
the format appearing in the model's own words before the fix and never after.
Evidence kept in `scratch/`: `results-s469-{before,before2,after,after2}.json`,
matching `sse-*.sse` + `server-*.log` captures.
