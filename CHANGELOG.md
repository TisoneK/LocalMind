# Changelog

All notable changes to LocalMind are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **The context meter now shows what fills the model's working window.** The chat header has always carried one number — how full the model's context is on the latest request — but when it climbed there was no way to learn what was eating it. Clicking the meter now opens a breakdown: the standing instructions, the tool catalogue, the conversation so far, the results the tools returned, and the current question, each with its size and share of the last request. The shares add up to the exact total the model was billed for. Nothing about how the agent works changed — this is purely a window into where the memory goes.
- **The agent can now look around a folder without a shell command.** Ask "what's in this folder?", "sketch this project's structure", or "is there already a file there?", and it answers with a tidy, bounded listing — names, sizes, and dates — instead of running `dir`/`ls` and pasting whatever pours out. It never opens or reads file contents (looking around is not reading), skips heavyweight clutter like `node_modules` and `.git` (saying so), and if a folder is big it honestly says the sketch stopped early rather than pretending that's everything. Live-checked on a weak free-tier model: it picks this tool for folder questions, and still picks the right search/shell tools for theirs.

### Changed
- **Big tool results are no longer truncated and lost — the agent can pull the rest back on demand.** When a tool returns a large result — a fetched web page, a long file read (over ~5 KB) — the agent used to keep only the first ~2,000 characters in its working context and silently discard the remainder, so anything further down (a definition buried deep in a spec, a later section of a document) was simply unavailable unless it re-ran the tool. The full result is now stored in a searchable index the moment it's produced, and the agent carries a short pointer next to the visible head; when it needs detail the head doesn't contain, it looks it up with a new "search stored tool results" step instead of re-fetching or guessing. Verified live on a real model: asked what HTTP status 404 means per the full HTTP/1.1 spec, the agent fetched the ~400 KB document, then retrieved the exact §10.4.5 definition — far past the visible head — and answered correctly, while carrying ~79% less of that result inline. Honest trade-off: for a single buried fact the lookup can add a step, but a research turn that gathers several large sources no longer balloons its context or loses what it already read.
- **The agent now answers as soon as it has the information, instead of over-planning.** On a look-it-up turn (weather, a page fetch, a source read), the agent used to gather the answer and then run another full round of "thinking about which tool to call next" before finally writing the reply — on a slow free-tier model that extra round could add a minute of dead air to an already-answered question. Once a page fetch has put the requested content in hand, the next step is now an answer-only pass: the agent writes the final reply from what it just fetched instead of re-planning more tool calls. If the fetched page genuinely isn't enough (a multi-site comparison, for example), the agent gets its tools back and continues — nothing it could do before is lost. Measured on the same task: the part of the turn after the evidence lands went from two extra page fetches plus a 38-second final round to a single ~3-second answer round.
- **The Terminal panel was redesigned to read like a real terminal.** Each command and its output are now grouped into one block with a single header — a status dot, the time, the command, and how long it took — instead of a flat wall of lines that repeated a timestamp on every row. Output sits dimmed beneath its command, so your eye lands on what you ran first and reads the details only when you need them. Status now speaks in one clear colour each: amber while a command runs, green when it succeeds, red when it fails — and a tiny set of marks (a red ✗, a green ✓, a yellow !) replaces the mixed symbols that rendered as inconsistent colour emoji across machines. Command text uses your theme's normal text colour (light on dark, dark on light) rather than terminal-green, and a blue highlight is reserved for things you can click or type into, so an active prompt is never mistaken for a green "success". Everything you relied on stays: tabs, the Mine/Agent filter, the package installer, search, history, autocomplete, and the live "executing…" cursor.

### Fixed
- **Memory can now remember things even when the local embedder is offline.** The vector store gets its embeddings from a local Ollama model; when Ollama wasn't running, every store silently failed ("All connection attempts failed" in the log) and memory was dead for the session with no way to recover. If you configure a cloud embedding endpoint (an OpenAI-compatible `/v1/embeddings` URL, model, and API key — set in `settings.json` or via environment variables), the store now binds that backend at startup when Ollama is unreachable and memory keeps working. Two guardrails keep the memory trustworthy: the whole index is one embedding space, so the backend is chosen once at startup and never mixed per-call (a cloud vector is never silently compared against Ollama-era vectors — a populated foreign-space index refuses the switch instead of corrupting itself), and cached vectors are keyed by the backend that produced them, so a swap can't return poisoned results. With no cloud embedder configured, everything behaves exactly as before.
- **The agent no longer pastes its internal work log into your answers.** After running tools on your request, the agent sometimes tacked a raw internal work report — tool names, commands, output dumps — onto its chat reply instead of just answering you. That happened because the internal report (which exists as a fallback for when an answer comes up empty or gets cut off) was being fed back into the agent's own memory of the conversation, and the model is a copycat: show it a format and it starts reusing it. The report is now stripped from everything the agent sees of past turns, and if the model copies the format into a new reply anyway, that copy is removed before the reply reaches you — the clean, deliberate report still appears exactly when it should. Verified live on a real model: asked to repeat its previous reply, the agent used to recite the internal report word for word from its memory of the conversation; after the change it can't, while the fallback report itself still reaches you when an answer is empty or cut short.
- **Reading a document no longer invents busywork.** Ask the agent about a long passage you pasted ("read this and answer one question") and it builds a checklist of what you asked for by scanning your words. It used to hunt the whole message for words like "create", "new" or "folder" without checking how they were used — so background prose like *"we moved to a folder convention everybody tolerated"* or *"every new hire shadows a senior"* read as instructions. The agent then dutifully created an empty folder in its workspace and finished by proudly reporting it had met the "folder created" goal — busywork it asked itself, plus a stray folder in the chat's files. A named file or folder now becomes a to-do only when your own sentence actually asks to make it: pure reading turns just answer (one such test went from 94 seconds of artifact-busywork to 29 seconds with a direct answer), and genuine create-a-folder/write-a-file tasks keep getting the same verified checklists as before.
- **"Remember this:" now saves the fact, not your instruction.** Telling the app "Remember this: my project is called Falcon" used to store the raw words — the "this:" and even trailing instructions like "Just acknowledge" — inside the memory itself, so the confirmation read back with broken grammar and future lookups matched the leftovers instead of the fact. The save path now strips the "remember this:" framing (including when a colon follows it) and drops trailing "just acknowledge" style instructions before storing, keeping the fact clean. Asking what you told it now recalls what you actually said, not the words around it.
- **"How are you?" now gets a real answer instead of a canned greeting — and quick replies no longer fake their speed stats.** Asking "How are you?" or "How's it going?" used to trigger the same canned "Hi! I'm LocalMind…" line as a bare "Hi", because those questions were treated as pure greetings. They now get a genuine, context-aware answer from the model. Separately, the instant canned replies used to report made-up token counts and impossible speeds (thousands of tokens per second) that quietly skewed the session's average-speed and latency stats; they now honestly report that no model call happened, so the stats you see reflect real model work only.
- **The agent now actually remembers what you told it in conversation mode.** When the chat answered from its memory-repair work, the system prompt claimed "You remember things about this user" — but the actual facts were dropped from the prompt on the conversational path, so small-talk turns could impute or invent what you'd told it. Your stored facts now ride along with the reply (after the stable instruction block, so responses stay fast).
- **Windows: the agent no longer keeps working after it already finished.** The internal gate that decides whether the agent's "done" is real misread file-verification goals whose paths contained words like "pytest" (e.g. any file under a pytest cache folder) as "must run pytest" — so a finished file task got rejected and the agent looped on. File-existence checks now route to the file checker regardless of what the path happens to be named.
- **Windows: server restarts report port conflicts honestly again.** The "is this port busy?" probe could bind a socket straight over an already-running server on Windows and report the port free — the stale-server false-start trap. It now probes by connecting: a running server is always detected, while leftover time-wait sockets from a just-closed instance still don't block a restart.
- **Your own messages now show up in chat exports and the chat list count.** In a short small-talk conversation — greetings, "how are you", "what can you do" — the exported file and the chat list's message count showed only the assistant's replies, as if you had never typed anything (the live transcript still showed your messages, so reopening the chat looked wrong too). Those quick-reply turns now save your message to history just like every other turn, in the right order, so exports, counts, and the chat-list preview match what actually happened.
- **Chat exports now carry real dates, the answering model, and every turn's provider.** The JSON export showed times like "07:39" with no date — impossible to tell which day a chat happened — and never said which model answered a turn. The export (v3) now records ISO-8601 timestamps for each chat and message, plus the model and provider per turn (a chat that switched models shows exactly where). The thinking the agent streams on quick conversational turns now persists with the reply too, so the export shows the same reasoning the live chat did — previously those turns saved their answer but dropped the reasoning. Canned greetings record no model identity (no model was involved). Everything the older v2 export had is still there, so old copies and readers keep working.
- **Sidebar chat previews no longer show raw markdown noise.** Previews used to render literally as "🌤️ **15°C (59°F)** … | | |---|---|" — asterisks for bold and table pipes that meant nothing in one line of text. Previews are now plain, single-line text; the full formatted reply is untouched in the chat itself and in exports.
- **The Agent Workspace panel no longer advertises delegation that doesn't exist.** Its caption said the workspace tracked "delegated work" and that "child agents" report back to the parent — but there is exactly one active agent (the Parent), which runs every turn and tool step itself. The panel now says so plainly and keeps tracking what it always tracked: the Parent's turns and tool steps.
- **Files stored in OneDrive can now be read even when OneDrive isn't running.** A file that lives in the cloud until opened (OneDrive "Files On-Demand") used to fail every read with a cryptic "Invalid argument" — the agent then wasted turns trying alternate ways in and came back with a wrong diagnosis. Now the reader recognizes the situation, starts OneDrive if it isn't running and waits briefly for the file to download, and if that still isn't enough it says exactly what's wrong and what to do — instead of leaving the agent to flail. (Side effect you may notice: asking about a cloud-only file can now bring OneDrive back to life on its own.)
- **Documents no longer need the "right" file extension to read correctly.** Files are now recognized by their actual content, not their name — so a renamed PDF still parses as a PDF, a text file wearing a .docx name reads as text instead of erroring, and genuinely unreadable formats (old Microsoft Publisher/Word/Excel binary files, ZIP archives that aren't documents) get an honest "this format isn't supported — re-save as .docx or .pdf" instead of garbage or a parse error. Word documents built from tables (common in CVs and forms) now include the table text — previously those read as blank — and documents with embedded pictures now say so instead of silently skipping them.
- **Code the model sends with a Windows path in the first line no longer gets bounced.** A snippet like `path = "C:\Users\...\document.docx"` was rejected as "no executable code" and cost a wasted round-trip every file task; it now runs. The rejection message also stopped claiming a code fence is required.
- **Picture files are now reachable by name.** The image reader (with text extraction from scans/photos) already existed, but a path ending in .jpg/.png never resolved — it answered "No file found". Path matching now also treats .JPG and .PNG the same as lowercase, so real-world file names resolve.
- **When a file format genuinely can't be parsed, the agent stops trying.** Under the old generic "try a different tool" hint, a weak model spent ten code-execution attempts hand-decoding an unsupported file before giving up. The guidance now says plainly: no tool can parse this format — report the limitation and the conversion suggestion instead.
- **Memory refuses to remember things that change on their own.** Ask the app to remember your IP address or your internet provider and it used to store them like any other fact, then treat them as true days later when they are simply wrong — those values change with every reconnect, VPN toggle, or network switch. It now says plainly that it won't keep a live value and that it will read it fresh whenever you ask. Durable things about you (preferences, where you live, what you're building) are remembered exactly as before, and now carry a note of how fresh and how certain they are. Verified live on a free-tier model: the same request that previously stored the IP and provider now gets a straight "I'd rather not keep that" — and nothing lands in memory.
- **The same fact is no longer stored twice, and "done" now means done.** Saying one thing twice left two memories behind, a cleanup could report "I've removed that" while the memory was still sitting there, and if the local embedder was offline, deleting anything failed outright. A fact now has one identity, so restating it updates that one memory instead of adding a copy; every save and removal is confirmed by reading memory back before the app tells you it happened; and deleted means deleted even when the embedder is down. The list of what the app knows also prints a short id per memory, so you can point at one exact item — "forget #98802f19" — and it does.

### Added
- **Right-click menus for the chat.** Selecting text in the conversation and right-clicking it now opens a real menu instead of nothing: Copy the selected words, Copy the whole message you clicked in, or Select all. The message box at the bottom gets the familiar editing menu too — Cut, Copy, Paste, and Select all — and Paste drops the text exactly where your cursor was (or replaces what you had selected). Copy is greyed out until you actually select something, like on any native app.
- **Bulk chat export can now go straight to the clipboard.** When you mark several chats in the sidebar, the new Copy action next to Export puts the same export (Markdown or JSON) onto your clipboard instead of downloading a file — paste it wherever you need it. If the clipboard refuses (for example, the app lost focus at the wrong moment), a small notice says so instead of failing silently.
- **You can now watch the agent actually think.** The reasoning the agent does between steps — the "is this the right file, which option wins, what would change my mind" part — used to happen behind a curtain: you'd see an empty Thinking box for a while, then actions. That reasoning is now shown live as it happens, right where the model's own thinking already appears, and it reads like a person working through the decision: grounded in what was actually found (real file names, values, results — not "I will now look for information"), weighing options when the evidence is thin or conflicting, and landing on the next step with a reason. Each round of thinking also builds on the previous one during a turn instead of starting over. The agent still moves at the same speed — this opens up thinking that was already happening, it doesn't add more of it.
- **The agent now thinks between every step, without slowing down.** While it works through a multi-step task, the agent now checks in with its own reasoning after each step — not just once or twice per task — and that thinking overlaps the work instead of adding to it, so turns stay just as fast (in our tests, slightly faster). When a step fails, the agent still stops to reason through the recovery before its next move. We also fixed a security slip from our own house: the server log used to record provider API key values in plain text on every start; it now records only the key names — if you share old logs, rotate the keys they contain.
- **A finished answer no longer gets labeled as a failure.** When the agent ran out of room mid-task, it still tried one last time to pull everything it had gathered into a final answer — and usually succeeded. But the banner above that answer still read "Agent loop failed". The app now checks what actually happened before labeling the turn: if the final answer came through, no failure is shown; and when a turn really is cut short, the banner now says *which* limit was hit — out of time vs. out of steps vs. going in circles — instead of always blaming the step count, so the "tell me to continue" advice actually matches the problem.
- **The agent now stops itself when it repeats the same call and gets the same result.** A weak model could burn its entire budget re-running the identical search or command three-plus times while tweaking a character. After three identical calls (same tool, same input), the turn now ends honestly with what was gathered so far and a suggestion to rephrase with more specifics — instead of dying on the step cap with a misleading "out of iterations" message.
- **A search that finds nothing now relaxes to a *distinctive* word, not a generic one.** Asking "find my CV" with a mangled query used to make the local search fall back to matching the word "files" — returning dozens of unrelated folders — while skipping "CV" entirely (deemed too short). The fallback now skips generic filler words, reads a pasted folder path as the folder it names, and tries a short distinctive word like "cv" as a last resort — so the very first search surfaces the target instead of the model flailing through retries and raw shell commands.
- **The context meter no longer fills up after a handful of turns.** The top-bar "Context" percentage was comparing the session's whole conversation (every turn's prompt added together) against the model's per-request context window — so after 4 short turns on a 32K-token model it read 100% even though every single request had fit easily (prompts re-send the conversation, so per-turn prompts overlap; they don't stack). It now measures the LAST request's prompt against the window — the number that actually predicts when the next message degrades — and its cached share uses the same basis (previously the meter and the stats bar could show two different cache percentages for the same turn). Session-cumulative totals stay in the stats corner where they belong.

### Added
- **You can now see how much of a prompt came from the provider's cache.** Many AI providers re-send the same instructions every turn but bill repeat content at roughly a tenth of the price — the app wasn't showing that, so the context meter looked costlier than it really is. When the provider reports it, the stats bar now shows how many prompt tokens were cache-served (with the hit percentage), the context meter shows the cached share next to its raw percentage, and a calls chip shows how many model calls a turn took (agent turns chain several calls, each re-sending the conversation). Providers that don't report caching simply don't show the new chips.
- **Heavy-JavaScript and "skeleton" sites now return real data.** Many live sites (scores, standings, single-page apps) send only a shell of a page and fill in the data with JavaScript afterwards — a plain fetch got the empty skeleton, so answers came back partial or wrong. LocalMind now escalates those pages to a stealth browser (via the companion Scrapamoja project, run separately so it stays optional) that actually loads the page, waits for the content to appear, and reads it — after a plain fetch and the lightweight browser both come back thin. When Scrapamoja isn't installed, nothing changes and the feature is simply skipped.
- **Local Search: one tool now answers "where is… / find… / do I have…" questions about your computer.** A new `system_search` tool gives the agent a single front door for local discovery: files and folders by name (glob, keywords), files modified recently ("what did I work on?"), the largest files, duplicate copies (same name + size in multiple places), installed applications (registry / Applications / dpkg + PATH executables), and which program opens a file type ("what can open this .psd?"). Results come back as a small ranked page with sizes and dates instead of a raw directory dump, searches stay inside your allowed folders with a time budget, and partial scans say so. Questions like "Where is my project?" now reach the agent (they previously got a generic conversational answer with no search at all), the shell tool steers the model to search instead of running `find`/`du` hunts, and the older find-by-name tool is retired from the model surface (kept internally) so there is exactly one search entry point.

### Changed
- **The graphite dark theme sits on a deeper background.** The default dark theme's surface palette was darkened by roughly a third across the whole ladder — window, panels, cards, inputs and code areas move down together — so white text reads with more contrast and the app feels less washed-out while the relative layering between surfaces is preserved. Only the graphite dark theme changes: light themes and the other dark themes (Midnight Iris, Warm Ink) are untouched, and the Tone slider in Settings still lets you brighten or deepen it further.
- **The whole app now sits on the same surface as the Settings page (dark themes).** The main window, side panels, header, and title bar used a flat, slightly darker background than the Settings dialog; in dark themes they now use the same elevated panel surface, so the app reads as one consistent, layered surface (inputs and code areas stay recessed against it, matching how Settings already looked). In light themes the app shell stays plain white — the elevated grey looked wrong as a full-app background. Background/tone only — no layout changes.
- **The old per-message tool picker is gone; the Chat/Agent/Auto mode picker is the only selector.** The message box used to carry a second dropdown (Auto / File Write / Code Exec / Grep / Shell / Memory) that hinted a specific tool for the backend — a leftover from the old intent-based system. It sat next to the newer Chat-mode picker and was redundant and confusing. It's now removed, leaving a single, clear control: Auto (classifier decides), Agent (always the full agent loop), or Chat (no tools).
- **The reasoning labels are swapped to read the right way round.** The collapsible box in chat that shows the model's actual reasoning is now labeled **"Thinking"** (it was "Approach"), and the internal analysis step in the Agents panel is now labeled **"Approach"** / "Approach ready" (it was "Thinking" / "Analysis ready"). Names only — no behavior change: the internal reasoning pass is the "approach", and what you read is the "Thinking".
- **Todos show short titles; the agent keeps the full details.** The plan checklist in the Todos panel now shows a clean, verb-led label ("Create `a.txt`", "Create the folder path-test") instead of the long absolute paths the goals actually check — hover a row to see the full path/command in a tooltip. The agent's context and the acceptance gate still use the complete content (migration 010 adds a `title` column; existing todos fall back to their content).
- **Files the agent creates land in the session's own workspace folder.** When a request names a file by a bare name ("create `a.txt`"), the goal checklist, its ordered sub-goal route, and the acceptance gate now resolve it to the session workspace's absolute path — so the model sees the exact destination, checks/writes/verifies that path, and the turn's artifacts stay with the chat (deleted with it) instead of scattering guesswork across `~`. You still control explicit destinations: as absolute paths ("~/Desktop/notes.txt") they're honored verbatim. The per-iteration agent context repeats the workspace line alongside the derived goal route to steer free-tier models.
- **The goal checklist now carries an ordered sub-goal route.** When you ask for concrete deliverables (a file, a folder), each goal in the Todos panel expands into the fastest+safest sub-steps the agent will follow — check the current state first, prep (create the parent folder if missing), write, then verify — rendered as nested rows under the goal and injected into the agent's context so it follows that order instead of guessing. The sub-goals stay part of the same fixed checklist (never mutated mid-turn), complete together with their goal, and don't change the n/n progress count.
- **File diffs now appear no matter how a file was changed.** Previously the before/after diff (green/red lines in chat + the preview dialog's Diff mode) only showed after an `edit_file` — a file created or overwritten with `file_write`, or rewritten by a script, showed no diff at all. Now the agent loop snapshots the pre-write content and emits the same diff event for `file_write` (new files show as all-added, overwrites show exactly what changed), and the model is steered to prefer the dedicated write tools over shell redirection (`>`, `tee`), keeping writes diffable and verified.
- **Tables now render as clean cards.** Structured answers — a weather forecast, prices, a schedule, a comparison — show up as a polished table (rounded card, tinted header, alternating rows) instead of a wall of text, and the agent is nudged to use a table when the answer is naturally tabular.
- **The agent now shows its plan as a live task list.** For a multi-step request, LocalMind lays out the ordered steps it's going to take up front — they appear in the Todos panel — and checks each one off as it works through them, so you can watch the plan and its progress instead of just a "planning…" label with nothing behind it. (Simple one-step requests skip the checklist.)
- **Agent Workspace cards behave better:** completed turns now collapse automatically so only the active turn stays expanded (you can still click any turn open), and the cards scroll inside their own panel instead of scrolling the whole page.
- The Agents workspace now updates in **real time** during a turn — the agent's phases (getting started, understanding, planning, running tools, verifying) appear as they happen instead of all at once after the reply. It also keeps a **history of your turns**: each turn is its own numbered, collapsible group (the active turn is expanded, past turns tuck away) instead of the panel wiping itself every message. Child agents narrate their phases live too, and the whole thing got a visual refresh — a breathing status rail, turn badges, and a connected lifecycle timeline (with motion turned off automatically if you prefer reduced motion).

- Faster first message with a local (Ollama) model: the app now warms the model up at the correct size at startup, so your first request no longer triggers a slow model reload (previously a 10–30s stall on the first message after launch).
- The agent uses fewer tokens on each step of a task: a duplicate copy of the tool list that was being re-sent on every step has been removed (~280 tokens saved per step), leaving more room for the actual work — especially helpful on small local models and free-tier limits.

### Changed
- **The "Thinking" box now shows a clean, plain-language play-by-play instead of the model's raw internal monologue.** It used to stream the model's raw chain-of-thought — which leaked internal wiring (echoes of its own instructions, "the synthesis reminder", tool-schema musing, and messy recovery deliberation). Now, while the agent works, the box shows short, human lines of what it's actually doing — "Checking your system…", "Searching your files…", "Running a command…", "Searching the web…" — so you stay in the loop without the technical noise. The raw reasoning stays internal.

### Fixed
- **Research turns no longer stall for minutes on a single query.** The new stealth-browser step was being run for *every* candidate source inside a multi-source web search, stacking up to a minute each — long enough that the provider rate-limited the final answer and you got raw notes instead. The stealth browser now runs at most once, only as a last resort when every ordinary source came back empty, so research stays fast.
- **Pages that just say "please enable JavaScript" (or show only a spinner) no longer get treated as the answer.** Some sites send a shell that says to turn on JavaScript, or a bare "Loading…", with the real content filled in later. Those are now recognised as empty and handed to the browser step that actually runs the page, instead of being accepted as-is. (A normal long article that happens to mention "enable JavaScript" somewhere isn't affected.)
- **If a rate limit forces the assistant to show raw findings, they're now readable.** When the provider rate-limits the final write-up and the assistant falls back to showing what the tools found, it now strips the page clutter — "Subscribe now", "LOGOUT", "Loading…", menus — so you see the actual headlines instead of a wall of sign-in prompts.
- **Web tables no longer come back as unreadable strings of digits.** When the agent read a page with a table (a league table, a price list, a schedule), the columns were being glued together — a row like `Man City 2 2 0 0 6 2 4 6` arrived as `22006246`, which the model then had to guess at, often getting it wrong or giving up and trying more sources. Table cells are now separated, so tables come through clean and the agent can just read them.
- **Long tables are no longer chopped in the middle.** Page content is trimmed to keep responses fast, but the cut used to land anywhere — including halfway through a table, so a 20-row standings table came back with only the top and bottom few rows. The trim is now table-aware: it cuts on a line boundary and keeps a table whole rather than slicing through it.
- **The browser no longer hangs for three minutes on a stubborn page.** Opening certain heavy or bot-blocking pages could stall for ~3 minutes before giving up, because the timeout that was supposed to stop it didn't actually kill the browser's child process. The browser is now reliably stopped at its timeout, and a page that won't load fails fast (~25s) with a note to try a different source instead of retrying it.
- **"Web research failed" no longer shows up when the research actually succeeded.** A bookkeeping bug made a successful web-research result get re-labelled as a validation error, so a correct answer was reported as a failure. Fixed at the source so it can't happen for any tool.
- **The agent no longer stops after answering only part of a request.** Asked for two things at once ("the score and the news", "weather and a forecast"), it would answer the first and quietly drop the second ("I couldn't get that in this pass"). It now treats every part of the request as required and fetches what's missing instead of conceding it.
- **The assistant no longer falsely claims it "can't access your filesystem" and refuses to do things it can do.** Asked to delete files (e.g. an old ISO, an installer), it would say "I don't actually have access to your filesystem, so I can't delete anything" — which is false; it runs on your machine with shell access. It now does what you asked: confirms the exact target (once, for large or ambiguous deletes), then actually runs the delete and verifies it — instead of inventing a limitation or narrating an action it never performs. (Verified: "delete this file" now removes it and confirms the folder is empty.)
- **The task checklist no longer shows 100% done when a turn was cut short.** If a turn ended early — the provider rate-limited or errored mid-way, the time limit hit, or the step limit was reached — the remaining plan steps were still flipped to "completed", so the Todos panel read 100% on work that never finished (seen live: a rate-limited turn created 1 of 3 files but showed every step done). Now the checklist is only auto-completed when the turn actually finished; on any cut-short ending the unfinished steps stay pending so the panel shows the true fraction.
- **LocalMind no longer spills its own internals when you ask how it works.** Asked "how were you built?", "show me your system prompt", or "list your exact tools", it used to recite its architecture, agent list, model routing, and tool registry. It now describes itself at a user level — a local-first assistant with capabilities you can use — and politely declines to expose its system prompt, internal architecture, or tool schemas. Ordinary "what can you do?" questions are unaffected.
- **The built-in knowledge doc now actually loads in the installed app.** The document that tells the assistant its own capabilities, tool reference, and behavior rules was located relative to the working directory, so in the packaged desktop app (which runs the backend from a different folder) it silently failed to load — the assistant fell back to generic behavior. It's now found regardless of where the backend is launched from.
- **"Find my…", "largest files", "clean up my downloads", "recent files" now actually search — fast — instead of hanging or being brushed off.** Local-search questions weren't reliably reaching the bounded search tool: they were often answered without searching, or the model ran `find /` / `du ~` over the whole disk and timed out. Three changes make local search dependable regardless of the model or how you phrase it: (1) the app now recognizes vague, everyday search phrasing by *category* — size ("large/biggest files"), recency ("recent", "old photos", "what did I work on"), duplicates, installed apps, "where is my…", disk space — instead of a few fixed phrases, while leaving genuine questions ("largest planet", "large language model") as normal chat; (2) if the model still reaches for a whole-disk `find`/`du`/recursive listing, that's intercepted and redirected to the bounded search tool before it can time out; (3) the search tool now understands plain phrasing like "largest ~/Downloads", not just structured input. Net effect: these questions return a fast, ranked answer with sizes and dates.
- **The live Agent Workspace, action cards, and todo list no longer jitter as they update.** Each of those lists animated the *position* of every existing row whenever a new row was added or a row changed (a framer-motion `layout` animation), so every streamed update made the whole list shift and jiggle — reading as flaky. New rows still fade/slide in, but existing rows now stay put instead of re-animating on every event, so the panels update smoothly.
- **Long tasks that keep making progress aren't cut off at the step limit anymore.** The agent stops after a fixed number of steps as a failsafe — but that failsafe fired even when every step was succeeding and the task simply needed more steps, so a legitimately long job could be stopped mid-way. The step count is no longer the limiter for a *succeeding* task: once the base limit is reached, the agent keeps going **as long as its last tool call succeeded**, bounded now by the overall **time limit** (not a step count) and by failure detection. A run that's failing or spinning still stops at the base limit exactly as before, and an absolute ceiling guarantees it can never truly run away. (Very long jobs are ultimately bounded by the wall-clock limit, which stays configurable.)
- **Chats now get a real title in Agent mode instead of staying "New Chat".** In Agent mode the classifier is skipped, so the session title fell to a background task that generates one from your message — but that task was started fire-and-forget with its reference dropped, so Python could garbage-collect it before it ran, and the title never got written. It's now retained until it finishes, so Agent-mode chats get titled (and the sidebar picks it up within a couple of seconds) the same as the other modes.
- **System info now actually reports your disk, memory, CPU, and network — so the agent stops shelling out for it.** The built-in system-info tool was written to report disk usage, RAM, CPU, network interfaces, top processes, and uptime, but it relied on a library (`psutil`) that was never listed as a dependency — so it was missing on every install, and every one of those sections silently degraded to "install psutil". The result: asking "what's my disk info" returned only OS/hostname, and the agent had to fall back to a slow shell command (a 40-second `Get-Volume` scan) to answer. `psutil` is now a declared dependency, so after updating, system info returns the full picture directly — disk volumes and free space, RAM, CPU, network, uptime — no shell fallback needed. (Verified: disk + memory + network now populate from the system-info tool.)
- **Longer commands like disk-usage scans no longer get killed too early.** The shell tool's per-command timeout was 45 seconds — too short for a legitimate recursive scan (e.g. sizing up a deep Windows user profile), which routinely needs a minute or two, so those commands were cut off and reported as a timeout (seen live: "what's taking up space on C:" failed twice at 45s). The default is now **120 seconds** (still bounded so a true hang can't run forever, and still configurable via `LOCALMIND_SHELL_TIMEOUT` for very large trees). When a command does time out, the message now tells the agent to narrow the scope or use the process tool instead of blindly re-running the same broad command.
- **Asking for your system info or storage now just works, instead of the agent tying itself in knots.** When you said "show me my system" or "show me my storage", the agent called its built-in system-info tool the natural way — with no extra query — and an over-eager internal guard rejected that as "input too short" before the tool could run. The agent would retry, get rejected again, and then either narrate "running the checks now…" without ever showing results, or run out of steps and dump a raw internal "worker report" at you (both reproduced in the shared chats, on Windows and Mac). The guard now knows that the system-info and desktop-observe tools are meant to be callable with no query — a bare call returns the full overview — so the request runs the first time. Tools that genuinely need input (shell, web search) are still checked, on every model path. Regression-tested.
- **A task is now considered done only when the work you asked for actually happened — not when the agent stopped talking.** When you ask for concrete deliverables ("create a folder, write `a.txt` and `b.txt`…"), LocalMind now derives a fixed checklist from your request up front, shows it in the Todos panel as the task list, and only reports completion once tool evidence confirms every item. The old behavior let a turn end as "100% done" after the agent merely described what it would do — reproduced live: the model answered "I'll set up the tools needed for file operations." with zero tool calls, zero files, and the panel showed 2/2 complete. Now a premature stop with unmet deliverables is caught by the acceptance gate, the agent is nudged to keep working, and if it still doesn't finish, the panel shows the true fraction (never a false 100%) and the reply states what's still unmet. Verified live on deepseek-v4-flash: the same "create path-test folder + two files" task that previously ended with nothing now creates the folder and both files with the exact content, and the todos are checked off only with real evidence.
- The agent's internal mid-turn reasoning pass (the Thinker) no longer leaks its raw monologue into the visible transcript. The model's private chain-of-thought from that analysis — including echoes of its own instructions ("You are the Thinker…") and JSON-format musing — used to render into the Thinking block on every model; it now stays internal, and only the structured analysis shapes the agent's next action. The Thinking block still shows the agent's own genuine reasoning, and the Workspace still shows the analysis pass ran (started/ready + its next step).
- Reading a file back on Windows no longer fails when the path uses backslashes without a drive letter. The reader's path extractor only accepted forward slashes in bare paths, so a Windows-relative path like `dev\test-run\notes.txt` got truncated to `notes.txt` and looked up in the wrong place — a file the agent had just written read back as "not found" (reproduced live on Windows: the write reported 19 bytes to `C:\Users\tison\Dev\test-run\notes.txt` and the immediate read of the same path failed). The extractor now keeps Windows-relative backslash paths whole.
- The file-write verification line now reports the file's **real size on disk** instead of the length of its own read-back report. The auto-check that confirms a write landed used to count the whole "File: <path> / Size: N bytes" header plus the preview — so a 19-byte file came back as "~79 chars verified on disk" (seen live on Windows), and that ~60-char header also masked real truncation (a 200-char write landing as 90 bytes could slip past the 50% loss check). The read-back tool now reports the actual byte count, and the verification uses it.
- **The agent no longer ends the turn by promising to create files without doing it.** The tool-talk detector's creation-commitment pattern was defeated by hyphenated or dotted names — "Let me create the **path-test** folder and the two files" streamed as a final answer (after a recon listing, with no `file_write`), the turn ended, and the Todos panel showed 2/2 as if the task were done (reproduced live on Windows). The adjective slot now accepts hyphens and dots, so a commitment to create/write files with no tool call is intercepted and the loop nudges the model to actually do it instead of ending.
- **The Todos panel now always populates during a task that runs tools.** It used to rely on the agent voluntarily emitting a plan or calling `todo_write` — and since the warm-kernel architecture retired the per-turn plan call, the panel was structurally empty on every turn (the agent would just narrate its steps in the Thinking block instead). Now the loop synthesizes one todo per real tool execution — "Run: …", "Write: …", "Read: …" — created when the tool starts and checked off when it lands, so the panel shows live progress no matter which model is running. Loading tool docs also appears as a step ("Load tool docs: shell") right before the tool is used — so you can see the agent consulting a tool's schema before acting, the how-and-why of its tool choices. A real plan-based checklist still takes precedence.
- The agent no longer gets stuck narrating what it will do instead of actually doing it. When a recovery nudge interrupts the model (it described a tool without calling it, or returned text/empty where a tool call was required), the nudge now restates **your actual request** and — if tools already ran — tells the model not to repeat them. A nudge can no longer bounce the model back into re-listing directories when you asked it to create a project. The tool-talk detector also catches "I'll create/write the project files…" narration that ends a turn without a tool call, so the loop nudges the model to actually call `file_write`. (Verified live on deepseek-v4-flash: a "create a project" turn that previously ended with zero files now writes and verifies a real project file.)
- Asking the assistant to **create a script and run it** now works. When it wrote a file and then tried to “run” it through the code runner (which executes code you paste, not a file), it used to hit a dead end and give up. It now recognizes a run-a-file command and runs it through the shell automatically, so the script actually executes and you get the output.
- Follow-up questions no longer get a generic "I'm here and ready to help — could you tell me more?" that ignores the conversation. When the model's internal routing step returned nothing usable (which happened on longer chats), the reply fell back to that canned line instead of using what was already said. Now, in that case, the assistant answers your latest message directly from the conversation so a follow-up like "why did you say that?" is actually addressed.
- The agent no longer spins on a tool that keeps "succeeding" without helping. If it runs the same tool several times in a row without getting closer to the answer (e.g. repeated searches that return results but not the answer), it now stops, changes approach, or answers with what it has — instead of looping until it gives up.
- **Web search now returns results that actually match your question.** Searches race several engines in parallel and used to take whichever answered *first* — so a fast engine that misread the query could win with off-topic results. Asking "current weather in Kitengela" could come back with pages about the word "current" (a banking app, an "electric current" encyclopedia entry, a dictionary) or even weather for the wrong city, which left the assistant with nothing useful and it would give up. The race now prefers the engine whose results genuinely match your query's key terms (the place, the topic), falling back gracefully if none are a clean match. Verified live: that weather query now returns Kitengela, Kenya results.
- **The thinking block now shows the model's reasoning as formatted text.** The box that appears while the agent is working used to dump the reasoning as one unformatted block — headings, lists, bold, and code all flattened into a wall of plain text. It now renders that reasoning through the same markdown pipeline as the agent's reply, so the structure comes through, while the live cursor, copy button, and per-step labels keep working.
- The agent no longer says a task is **done when its last action actually failed**. If the agent runs a file write/edit, a shell command, or code and that step fails (for example a command that errors out), it will no longer report success and stop — it recognizes the failure, keeps working to fix it, and only finishes once the action genuinely succeeds (bounded, so it still stops and reports honestly rather than looping forever). Successful tasks and read-only/lookup tasks are unaffected. Verified live on a small model: a failing command is now caught and retried instead of being reported as done.
- Creating a file at a full/absolute path (e.g. `/var/data/report.txt`) now saves it exactly there, instead of accidentally nesting it under your home folder. And the agent's built-in "did the write succeed?" check now looks at where the file was actually written — so a successful save (including documents it auto-timestamps) no longer shows a false "could not verify the file" warning.
- The agent is less likely to reach for the wrong tool when you ask it to create a file: the read tool now clearly states it's read-only and that creating/writing goes through the write tool. (Verified live on a small model.)
- Embedding models (e.g. `mxbai-embed-large`) no longer clutter the chat-model list — they only appear in the embedding-model picker.
- Your chosen local (Ollama) chat model and embedding model are now remembered and restored the next time you open the app — previously the local model choice was lost on restart.
- Fixed a cloud model name (e.g. `deepseek-v4-free`) wrongly showing as the Ollama model. Switching from a cloud provider to Ollama could leave the old cloud model attached to Ollama; local and cloud model choices are now kept separate.
- The Settings dialog opens right away instead of sitting on "Loading settings…" while it fetches the local model lists (which can take a few seconds on Ollama); the lists now fill in a moment later. The loading state also matches your selected theme now.
- The context-window field in Settings now reflects the model you've selected — its hint shows that model's window and updates when you switch models. Leave it blank to auto-fit the model, or enter a number to pin a custom size.
- The context-usage meter no longer reads ~64% on a nearly-empty chat with a local model. LocalMind was treating any Ollama model it didn't recognise as an 8K-context model, so a 5,000-token chat looked almost full. It now reads the model's real context window from Ollama and gives the model a genuine working window instead of the old tiny 8K cap — so the same chat reads a sane low fraction (live-verified on phi4-mini: 16% where it used to show 64%). The window is adjustable in Settings (0 = auto), so you can raise it on capable hardware or lower it to load faster / use less memory.
- A simple message like "Hi" no longer gets pulled into the full tool-using loop and left hanging. The agent decides up front whether a message needs tools, and it used to fall back to "run the tools" whenever that decision was unclear — which happens for any model whose first reply isn't in the exact expected shape (most common on smaller local models, but not unique to them). Now the tool loop only runs when the agent clearly asks for it; anything unclear is answered directly using the model's own reply, so no model ever gets stuck running tools for a greeting. Live-verified on a local phi4-mini model: "Hi" now answers in one step with no tools (previously it ran tools and timed out after ~3 minutes), while a real request like "list the files here" still correctly runs its tools. The agent also writes a short line to the log explaining why each turn went one way or the other, so this is easy to confirm.
- The reasoning ("Thinking") block now reappears when you reopen a chat, instead of vanishing. It was being saved correctly but the reload path dropped a flag the display needed.
- The agent's opening line ("I'll do X…") now also survives a reload, alongside the reply, thinking, and tool steps that already persisted.
- Simple messages cost far fewer tokens: the agent's initial decision step no longer includes the long tool descriptions or machine details it never needed. Combined with the tool-loop fix above, a "Hi" now uses roughly 700 tokens instead of ~5,200. Context-window handling for local models was also corrected (see below).
- The web_search Actions card now shows **which search engine answered as a badge** (e.g. a small `BING` pill next to "Searching the web") instead of only in the result text. The agent loop reads the winning provider from the tool result metadata (generic `provider` key, falling back to web_search's `successful_provider`), carries it on the tool_call event, and it flows through the live SSE bridge and the persisted actions table — so the badge survives a reload too.
- Web search gains a **reliable no-key second free tier: Bing** (scraped organic results). Public SearXNG instances churn constantly (rate-limited / behind anti-bot within days), so the SearXNG fallback chain from the previous fix is a stopgap, not a dependable tier. Live-verified: Bing returns clean, decoded results and wins the race.
- Web search's SearXNG tier was effectively dead: the default instance (`searx.be`) sits behind an Anubis anti-bot page that answers HTTP 200 with HTML, so every request raised a raw `JSONDecodeError` and the tier never returned a result (the error message even leaked the parser error to the user). SearXNG now walks a fallback chain of instances — the configured `SEARXNG_URL` (comma-separated list supported) first, then curated public fallbacks, capped at 3 attempts — and detects non-JSON challenge pages and rate limits so it moves to the next instance instead of dying on the first. `json.JSONDecodeError` is caught explicitly with a friendly message, and the DDG provider no longer uses the deprecated `asyncio.get_event_loop()`.
- Leaving a chat and coming back no longer loses the Agent Workspace run tree or the Observe data. The Agents tab (parent/child runs, tool steps, evidence) and the phase strip were frontend-only live state rebuilt from SSE obs events and cleared on every session switch; the Observe panel read an in-memory engine dict that died on backend restart. The runtime now rebuilds the run tree + phase strip server-side from the request's obs events (mirroring the frontend's logic: delegation children, evidence entries, tool attachment) and persists them with the assistant message; the history endpoint returns them and the frontend restores the last turn's tree. The observation (merged metrics + structured snapshot summary) is written to a new per-session `observations` table at turn end, and the observability endpoint falls back to it on a cache miss — so the Observe panel survives a backend restart too.

The `messages` table only stored role/content, so thinking, errors, tool-step timelines, and per-turn metrics were transient frontend state that vanished on reload. Each assistant message now persists those artifacts (thinking trace, raw error string, tool-call timeline with the same delegation output boundary as the live SSE bridge, and prompt/completion/latency metrics); the history endpoint returns them (error normalized at the presentation boundary) and the frontend restores the ThinkingBlock, ErrorMessage card, step pills, and reseeds the cumulative context counter from the per-message performance.
- The context counter in the top bar now counts tokens cumulatively across the whole conversation instead of showing just the last response's prompt — so it grows as you chat and matches the running total in the bottom-right stats bar (while a reply is streaming, the in-flight estimate is added on top).
- The "Why" block in the Actions tab (and the chat tool-step cards) is now hidden when the reasoning is empty or whitespace-only — an empty plan-step label no longer leaves a blank "Why" section (or a stray "why:" line) eating vertical space.
- The reasoning ("Thinking") block now has a maximum height with its own scrollbar instead of stretching the message indefinitely, a copy button at the bottom to copy the full thought process, and it auto-scrolls to the bottom so newly generated reasoning stays visible while it streams.

The tool may have failed or returned no useful output. Please try rephrasing your request."). Root cause found via real-model testing against Zen/DeepSeek-v4-flash-free: two adapter bugs in `openai_compat.py`. (1) DeepSeek rejects requests where the last message is a `tool` role — returns HTTP 400 "Upstream request failed". The agent loop sends this format after every tool execution. Fix: `chat_with_tools` appends a synthetic `user` message when the last message is `tool` role. (2) DeepSeek produces 80+ reasoning chunks before the tool_call delta arrives; Phase 1 detection was breaking at chunk 15 (during reasoning), falling through to Phase 2b which silently dropped the tool_call deltas. The fallback messages were also revised to surface actual tool inputs/outputs from the trace instead of guessing "overload" — honest evidence > speculation
- Fixed the iteration limit being too low for multi-step tasks. `MAX_ITERATIONS` was 3 (lowered in an early tuning pass to fit a 90s wall-clock cap) — the model did 3 reconnaissance calls (checking state before acting, exactly what we want) and hit the cap before the actual work. Raised to 8 (configurable via `LOCALMIND_MAX_ITERATIONS` env var). `MAX_WALL_CLOCK_SECS` raised from 90s to 180s (configurable via `LOCALMIND_MAX_WALL_CLOCK_SECS`). 8 iterations gives room for: reconnaissance (2-3 calls) + actual work (3-5 calls) + verification (1-2 calls). The wall-clock cap is the real safety net against a spinning model, not the iteration cap

This kills the misdiagnosis pattern that sent users down wrong paths across multiple sessions

Applies to shell (mkdir/rm/cp), file tools (file_write/edit_file/file_task), code_exec, web tools, and memory_op. Fixes the bug where the model ran `mkdir` before checking if the directory existed, and barreled into a non-empty unrelated folder instead of creating a `hello_world/` subdirectory

The SSRF protection validated the initial URL but `follow_redirects=True` let httpx follow 302 responses to internal addresses without re-validation.
