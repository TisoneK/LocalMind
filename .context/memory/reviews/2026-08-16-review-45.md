## Changes

- **`backend/.env.example`** — documents `LOCALMIND_THINKING`, `LOCALMIND_REASONING_TIMEOUT_SECS` (≥45), `LOCALMIND_REASONING_PLAN_TIMEOUT_SECS` (≥8), `LOCALMIND_REASONING_EFFORT` under a new "Reasoning models (z.ai/GLM, ADR-41)" section.
- **`backend/src/core/config.py`** — 4 Settings fields (`localmind_thinking`="enabled", `localmind_reasoning_timeout_secs`=180, `localmind_reasoning_plan_timeout_secs`=30, `localmind_reasoning_effort`=""). pydantic folds the env in at startup; `load_runtime_settings` applies settings.json on top — **UI (settings.json) wins over env**, consistent with adapter/model precedent.
- **`backend/src/adapters/openai_compat.py`** — `_zai_thinking_payload` + effort read the Settings singleton (was `os.getenv`). GLM-5.3 hard-rule (never disabled) unchanged. The adapter no longer reads env at call time.
- **`backend/src/core/agent/loop.py` / `orchestrator.py`** — `_per_call_timeout_for`, `_plan_timeout_for`, `_orchestrator_timeout_for` read `settings.localmind_reasoning_*` when the adapter has thinking enabled, falling back to the constants (which remain the module-level/test surface).
- **`backend/src/api/routes/config.py`** — GET /api/settings returns `thinking`/`reasoning_timeout`/`reasoning_plan_timeout`/`reasoning_effort`; new POST /api/settings/thinking validates (enabled/disabled; ≥45s; ≥8s), persists via `save_runtime_settings`, and removes the `reasoning_effort` key from settings.json when explicitly cleared (the preserve-empty contract would otherwise resurrect it on restart).
- **Frontend** — `client.ts` getSettings type + `setThinkingSettings()`; `SettingsModal` gains a "Reasoning" section (thinking toggle, per-call + plan timeout number inputs, GLM-5.2+ effort select) after the AI Provider section.

## Notes for future sessions

- Precedence is now **settings.json (UI) > env > module default** for all thinking knobs. Tests assert it (adapter reads Settings, not env). Don't flip back to `os.getenv` in the adapter — it would silently ignore the UI.
- `save_runtime_settings`'s empty-preserve contract is load-bearing for adapter/model; the effort-clear edge is handled by directly removing the key.
- The Settings singleton is a module-level import — tests that need a different policy patch attributes on `core.config.settings` (monkeypatch.setattr), they don't set env after import.
