# Review — Thinking levels for glm-4.5-flash: bound reasoning, not on/off (Session 262)

**Agent:** Claude Code / claude-opus-4-8 · **Date:** 2026-08-16 · Follows a live user trace.

## Trigger (live user trace, glm-4.5-flash on Windows)
"Create a recipe on desktop for a nice dinner" → the Thinker produced EXCELLENT reasoning (inspected the desktop, found 2 .lnk files, identified format/filename/content ambiguities, chose defaults, laid out the file_write plan) — the user praised it: "it's actually good, gives the agent a lot of context and lays the plan." BUT it then "thinks too hard": 202.6s of reasoning, repeated the `Get-ChildItem`, and the turn FAILED with "context too long". User: "there should be thinking levels, not turned off."

## Root cause
For glm-4.5-flash, thinking was binary `{type: enabled}`, and the `reasoning_effort` level (max/high/medium/low/minimal/none) was gated to GLM ≥5.2 — so 4.5 reasoned UNBOUNDED (→ 200s+, context overflow).

## Fix (`6a95238`)
Apply `reasoning_effort` (the "thinking level") to ALL GLM versions, not just ≥5.2. A version that rejects it degrades via a new 400-retry (`reasoning_effort_retry`), so it stays additive/safe.

## Live verification (z.ai/glm-4.5-flash, reasoning_effort=low)
- The field is ACCEPTED (no rejection logged) — 4.5 supports the level.
- The SAME recipe task that failed with "context too long" now COMPLETES a full agentic workflow: `ls ~/Desktop` → `file_write` (created a real 2,253-byte recipe, verification passed) → `file_task` (read-back verify). No context overflow. The S261 empty-after-reasoning thinking-off recovery covered two think-but-don't-act steps.
