# Review — 2026-08-24 (Session 399)

## Scope

Two user chat exports (`localmind-chats-1-2026-08-24*.json`, Windows + Mac)
showing "a lot of failures". Diagnose the remaining failures and fix at the
root, model/env-agnostically.

## Failures observed (from the exports)

1. **`sysinfo`/`observe` bare call rejected** — `[Action rejected: input for
   'sysinfo' is empty or too short.]`, repeated 3× in each session.
2. **Zero-tool narration reaching the user** — "Running the checks now… in
   parallel:" with no tool call (export 1, multiple turns).
3. **Iteration-limit → raw "Worker report — tool execution evidence:" leak** as
   the final user-facing answer (export 2, "Show me my storage").
4. **First-turn fabrication** of Ubuntu system specs with no tool call (export 1).

## Root-cause analysis

The single root cause behind #1, and the trigger for #2 and #3:

The parent loop's degenerate-input guard —
`if not tool_input or len(tool_input.strip("?. \t")) < 3` — is applied to
**every** tool. But `sysinfo("")` and `observe("")` are valid, meaningful calls:
both default to a full overview. The model made the *correct* bare call and the
guard rejected it before dispatch. It then retried, flailed about the schema
(its own thinking: "maybe the parameter name is different" — it was not), burned
iterations, and fell into either narration (#2) or the iteration-limit
worker-report fallback (#3). Session 398 had just expanded `sysinfo`, so the
expansion was effectively unreachable via the natural phrasing.

The guard existed at **four** sites: single-call (loop.py:3628), parallel batch
(3161), and two minimax-XML provider paths (4697, 5582). A fix at only the common
site would leave minimax users broken — violating the model/env-agnostic rule.

#4 (fabrication) is a separate weak-model grounding issue. In export 1 it is
also plausibly downstream of #1 (the model could not get real data from the tool
it is told to use). Not patched this session — re-observe after #1 is fixed
before touching the fragile narration/fabrication heuristics.

## Fix

- `tools/__init__.py`: `register_tool(..., input_optional=False)` metadata +
  `input_is_optional(intent)` helper.
- `tools/sysinfo.py`, `tools/observe.py`: `input_optional=True`.
- `core/agent/loop.py`: `_tool_allows_empty_input(tool_name)` (name→intent→flag);
  all four guard sites skip the rejection for input-optional tools.
- `tests/core/test_degenerate_input_guard.py`: 5-case regression test.
