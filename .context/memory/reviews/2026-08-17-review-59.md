## Findings & fixes

### Bug — context meter STILL read 64% (S289/S290 fix was incomplete) → FIXED (`325fd02`)
- **Live-caught:** `/api/models` reported `context_window: 8192`, so 5248/8192 =
  64% persisted. My S289 fix detected the real DECLARED window (131072) but the
  meter shows `effective_context_window`, which the "mini→8192" special-case
  capped to 8192. That special-case was the weak-hardware assumption the user
  flagged.
- **Also live-caught:** `_extract_context_length` was order-dependent —
  phi4-mini's model_info has BOTH `phi3.context_length` (131072) and
  `phi3.rope.scaling.original_context_length`; both end in `.context_length`, so
  a naive suffix match could return the rope value.
- **Fix:** (1) resolve the canonical key via `general.architecture`, excluding
  rope/original variants. (2) Replace the whole small/medium/large num_ctx
  tiering with ONE model-agnostic rule: declared window bounded by
  `_DEFAULT_MAX_NUM_CTX` (32768) or the operator override. Meter now reads 16%
  at 5K, live-verified. Measured why full-window isn't the default: num_ctx load
  is 8192→13s, 32768→29s, 131072→84s (KV-cache prealloc). Removed dead
  _is_small_model/_is_medium_model/tag tuples.
