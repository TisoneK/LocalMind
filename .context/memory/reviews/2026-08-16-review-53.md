# Review 53 — Drop redundant read-back (L3) + steer create→file_write (L2 partial) — Session 277, B-5

## Trigger
ADR-43 lever L2 (right-tool steering) + L3 (redundant read-back), from the user's
recipe traces: the agent listed the folder before creating, and read the file back
after writing to "confirm" — both wasteful; the read-back also hit the S264 Windows
path bug and cascaded to empty_response.

## What was there (verified, not assumed)
- prompt line 740 (Operator block) + 874 (CRITICAL RULES point 7): "shell lists the
  folder, then file_write" / "listing the folder with shell is only the FIRST step".
- prompt line 878: "file_write: read the file back with file_task and confirm it
  was written" — the explicit read-back instruction.
- loop.py `_verify_tool_result`: on file_write success it ALREADY reads the file
  back (dispatch verify_result), but returned **None** — "silent pass, no message"
  — so the model never saw a verified signal (which is exactly why the prompt told
  it to re-read). The discovery→find_path guardrail (736) already existed.

## Fix
- **L3:** loop.py now surfaces its own read-back verification to the model as a
  `[VERIFICATION]: file_write confirmed — N chars verified on disk … do NOT read it
  back` line (instead of returning None). Prompt 878 changed to trust that line and
  not re-read. `verification_results` is only a log counter, so returning a string
  is safe.
- **L2:** removed the list-before-create instructions (740, 874) → "call file_write
  DIRECTLY with the path and content."

## Verification (live, glm-4.5-flash, per system/live-testing.md)
- **L3 — WORKS.** The `[VERIFICATION] … do NOT read it back` line surfaced
  verbatim; the model created the recipe and did NOT read it back. Old sequence
  `shell → file_write → file_task(read-back)` is now `shell → file_write`.
- **L2 — PARTIAL.** The weak model STILL ran `ls ~/Desktop` before file_write. Root
  cause found live: "Create a recipe file on my desktop" is classified as the
  **`analyze`** intent (not file_write), and in analyze-mode the model explores by
  default — prompt steering doesn't override that on a weak model. The extra listing
  is now benign (one fast call, no read-back, task completes).
- Full suite 1875 pass (4 pre-existing env-gated shell fails).
