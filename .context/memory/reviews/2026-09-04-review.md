# S416 — P0 Context Engineering Step 1: Surface cache data to the UI

**Date:** 2026-09-04 · **Agent:** ZCode / qwen3.8-flash (per system prompt; local Windows) · **Feature:** `p0-context-engineering`

## Executive Summary

Executed **Step 1 of the addendum-confirmed Implementation Plan** (`2026-09-04-context-architecture-research-addendum.md`): wire the provider-reported prompt-cache telemetry — which the backend already captures — through to the frontend, so the user sees the *discounted* cost of a turn instead of the undiscounted raw prompt count. The research showed bankofai/qwen3.8-flash passes caching through (81.5% hit live, S414) while the UI displayed only the raw estimate; the gap was purely plumbing.

**No agent-loop behavior changed.** The loop's per-call usage merge gained bookkeeping fields (`total_*`, `llm_calls`); occupancy semantics (last-call wins) are preserved and pinned by tests.

## Discovery / Data path (verified this session)

1. **Adapter** (`openai_compat.py:718`) — normalizes `cached_tokens` across DeepSeek/OpenAI/Anthropic field names. Already shipped (prior session).
2. **Loop** (`loop.py`) — `_provider_usage` accumulated per call via `.update()`; per-iter cache log at ~3536. Each call's usage reached the runtime via `StreamChunk.usage` / `result.usage`.
3. **Runtime** (`agent_runtime.py`) — reads `usage` after the loop, emits `turn_complete` with `provider_usage=usage` (already on the wire, unused by the frontend) and records streaming metrics.
4. **SSE bridge** (`chat.py` ~963) — re-emits a `metrics` event but dropped the cache fields; the polling `/api/metrics` route had none.
5. **Frontend** — `useLocalMind.ts` parsed `prompt_tokens_approx` only; `PerformanceMetrics.tsx` showed prompt/completion; `CenterPanel.tsx` showed raw occupancy %.

**Live caveats (honest):** (1) The `metrics` re-emit event never appeared in the traces — on this path the frontend gets its numbers from the `turn_complete` obs event (primary path, verified above) and the polling `/api/metrics` (verified). The re-emit is belt-and-braces for other paths. (2) bankofai omits cache telemetry on some calls (trace-b: `cached_tokens: 0` with `llm_calls: 1` — the model parallelized its tool calls into ONE response; S414 measured 81.5% when the provider reports). The UI hides the chip when the provider doesn't report — no fake numbers.

## Findings (non-blocking)

- **`total_*`/`llm_calls` are enablers, not yet surfaced as a distinct number.** The corner now shows cached share + calls; a future slice can add "equivalent work across N calls" using `total_prompt_tokens` (the per-call re-send cost the addendum's Component 4 targets). Data is already on the wire.
- **Trace-b pattern:** when the model batches multiple tool calls into one response, `llm_calls` under-counts wall-clock LLM round-trips 1:1 with actual calls — it counts *usage-reporting* calls, which is the right basis for token math but not for a "steps taken" metric. Documented in the tooltip.
