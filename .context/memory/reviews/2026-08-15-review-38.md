# Review — Mac/Windows provider discrepancy

## Summary

The Mac app can load its provider settings, but a real chat completion from the clean committed checkout received a provider HTTP 429. The user's Windows capture shows the same code/settings family can successfully execute an initial Cerebras call and complete `web_search`, with only the later synthesis call rate-limited. The cross-machine cause remains unresolved.

## Verified Mac evidence

- Product files were restored to committed `HEAD` before the live smoke request.
- `/api/health` reported `adapter=zen`, `model=deepseek-v4-flash-free`, and `provider_reachable=true`.
- `/api/settings` reported the active Zen model and configured-key flags for Zen, Cerebras, and Gemini. No key values were printed or logged.
- A real `POST /api/chat` request for `hello` reached:
  `https://opencode.ai/zen/v1/chat/completions`.
- Zen returned HTTP 429 three times; the adapter retried and then emitted the canonical retryable rate-limit SSE error.

## Verified Windows evidence

The user's live Windows capture shows:

- `cerebras + gpt-oss-120b` accepted the initial request.
- `web_search` completed successfully.
- The subsequent provider call for final synthesis was rate-limited.

This demonstrates that the Cerebras key/model pair is usable for at least one request on Windows. It does not prove that the Mac and Windows sent identical request payloads or used the same egress/runtime conditions.

## Conclusions

- Settings deletion is not supported by the Mac evidence; settings were loaded and keys were present according to boolean status flags.
- The Mac error was not fabricated by the frontend; the provider returned HTTP 429 for the completion call.
- A provider-wide payment/quota diagnosis is not justified from the available evidence because Windows successfully reached Cerebras and the latest Mac smoke used Zen.
- The actual Mac/Windows difference is unresolved.

## Required next comparison

Capture sanitized metadata from both machines, excluding API keys and authorization headers:

1. exact commit SHA and working-tree state;
2. backend startup source path, adapter, and model;
3. completion endpoint URL;
4. message count, tool count, and request parameters;
5. active backend process and loaded settings source;
6. network/proxy/VPN/egress information.

No product fix is claimed by this review.
