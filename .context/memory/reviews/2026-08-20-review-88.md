# Review — Session 322: rename B.AI provider bai → bankofai (drop "bai")

- **Date:** 2026-08-20
- **Agent:** Buffy / deepseek/deepseek-v4-pro
- **Target:** "Still referencing bai? Failing with 404 — I said drop bai"
- **ADR:** ADR-55 (correction)

## Executive Summary

The user wanted the `bai` identifier dropped entirely (not just the domain
changed) and reported the provider still 404ing. I renamed the provider key
`bai` → `bankofai` across the codebase, migrated the user's `settings.json`
(`adapter` id + `api_keys.bai` → `bankofai`), and found the 404 root cause:
the user's still-running backend was the OLD code, which had re-written the
stale `model: DeepSeek-V4-Flash` back into `settings.json` (overriding the
Session 321 lowercase fix) and was sending the case-mismatched ID →
`model_not_found`. Re-fixed the model and re-verified live through
`OpenAICompatAdapter(provider="bankofai")`.

## Discovery

- Grepped the repo for remaining `bai`/`BAI_` references: 6 files (code,
  config, models route, frontend, env.example, tests) plus the runtime
  `settings.json` (`adapter: bai`, `api_keys.bai`).
- `settings.json` had `model: DeepSeek-V4-Flash` AGAIN (reverted from the
  Session 321 fix) — the user's running backend (old code, whose default was
  `DeepSeek-V4-Flash`) re-wrote it, which is the actual 404.

## Fix Applied

- `bai` → `bankofai` in: `openai_compat.py` (ProviderConfig key/name,
  `BANKOFAI_API_KEY`/`BANKOFAI_MODEL`, `bankofai_model`), `config.py`
  (`bankofai_model` field + env map), `models.py` (listable-models tuple),
  `SettingsModal.tsx` (provider id), `.env.example`, and
  `test_provider_registry.py` (all `test_bai_*` → `test_bankofai_*`).
- Migrated `settings.json`: `adapter` bai→bankofai, `api_keys.bai`→bankofai,
  and re-fixed `model` → `deepseek-v4-flash`.

## Baseline / Verification

- `tests/api/test_provider_registry.py` → 6 passed.
- Full backend suite → 2071 passed / 1 pre-existing failure
  (`test_parent_recovery_cap.py` broken `tests.` import, B-2026-08-20-19);
