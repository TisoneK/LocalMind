# Session 224 Review — B-2026-08-14-7 Parent Bootstrap + Fast Public Thinker

- **Date:** 2026-08-15
- **Agent:** Super Z / GLM-5.2 (Z.ai cloud sandbox)
- **Core:** 0.5.0
- **Target:** ADR-34 B-7 — parent bootstrap + fast public thinker
- **Feature:** adr-34-realtime-workspace

## Problem

ADR-33 made the parent initializer model-owned, but the visible UX still
waited 7+ seconds before showing any model-owned content. The user saw
generic transport status strings ("I'm understanding the request…") while
the initializer collected a full JSON blob before parsing. The
acknowledgement, objective, and plan were invisible until the entire
init JSON closed.

Live baseline (Zen `laguna-s-2.1-free`, "Hey whats the time?"):
- `agent_initialize` latency: **7,631 ms**
- No model-owned acknowledgement or understanding event before the full
  decision arrived.
- Total turn latency: **12,721 ms**.
- Final assistant token was the raw `sysinfo` tool output (B-8 problem,
  addressed in Session 225).

## Root cause

1. `_initialize_parent` in `core/agent/loop.py` was a single `await`
   that collected all adapter chunks into a string, then parsed the full
   JSON at the end. No progressive extraction.
2. `_process_unlocked` in `core/agent_runtime.py` serialized memory
   retrieval, failure recall, decision recall, and attachment parsing
   BEFORE starting the initializer — even though the initializer only
   needs the user message + recent history + tool catalog.
3. The SSE boundary only emitted generic `status_update` strings during
   the initializer; no model-owned `thinking_token` or `status` events
   flowed from the model's actual acknowledgement / objective fields.

## Fix

### 1. Streaming initializer (`core/agent/init_stream.py` + `loop.py`)

- New module `init_stream.py` with `InitializationPreview`,
  `extract_preview()`, and `render_understanding()`.
- `extract_preview()` uses bounded regex patterns to pull individual
  string fields (`acknowledgement`, `objective`, `response`,
  `clarifying_question`, `mode`) from a PARTIAL JSON stream as soon as
  each field's closing quote arrives. Each preview is capped to 600
  chars; raw JSON envelope and chain-of-thought never surface.
- `render_understanding()` produces a single bounded thinker line from
  the preview (objective > clarifying_question > direct-mode response
  prefix > mode label).
- New `_initialize_parent_streaming()` generator in `AgentLoop`:
  - Runs the adapter chat as a producer task that pushes events onto an
    `asyncio.Queue`.
  - The consumer generator pulls events in order: `("ack", str)` →
    `("understanding", str)` → `("decision", InitializationDecision)`.
  - Ack and understanding are each emitted at most once per turn.
  - Terminal pre-generation errors (auth/payment/permanent-quota-429)
    raise `TerminalProviderError` immediately.
  - Non-terminal errors (e.g. transient 503) and unparsable output
    fail open to execute mode — the consumer never hangs.
  - A `finally` block guarantees a decision event is always put on the
    queue, even if the producer exits with zero chunks.
- The old `_initialize_parent()` is retained as a thin non-streaming
  wrapper for compatibility (child agents, isolated loop tests).

### 2. Phase 0 consumption (`loop.py` `run()`)

- The parent initialization phase now consumes the streaming generator
  and forwards events to the SSE boundary:
  - `("ack", str)` → `StreamChunk(status=str)` + `obs.emit("agent_initialization_ack", ...)`.
  - `("understanding", str)` → `StreamChunk(thinking=str)` +
    `obs.emit("agent_initialization_understanding", ...)`. The frontend's
    `ThinkingBlock` renders this as a live thinker line.
  - `("decision", InitializationDecision)` → stored for the execution
    phase.
- A `streaming_ack_emitted` flag prevents duplicate ack status lines
  after the decision is parsed.

### 3. Nonessential memory work reorder (`agent_runtime.py`)

- `_process_unlocked` now kicks off memory retrieval + failure recall +
  decision recall + attachment parsing as a single concurrent
  `asyncio.create_task(_gather_nonessential())`.
- The task runs concurrently with adapter setup and the early transport
  acknowledgement. The initializer starts as soon as the adapter is
  ready, not after all memory work completes.
- The task is awaited before `build_context` (which needs memory_facts),
  but by then the initializer has been streaming for seconds.

## Acceptance evidence (live Zen `laguna-s-2.1-free` smoke)

Message: "Hey whats the time?"

| Metric | Baseline (Session 223) | After B-7 |
|---|---|---|
| Transport acknowledgement | ~0 ms | ~0 ms (unchanged) |
| First model-owned ack event | 7,631 ms (full init only) | **1,812 ms** |
| First model-owned understanding event | never | **3,089 ms** |
| `agent_initialize` stage latency | 7,631 ms | **3,146 ms** |
| Total turn latency | 12,721 ms | **3,355 ms** |

Both SLOs from ADR-34 §2 are met:
- acknowledgement ≤250 ms (transport ack is immediate) ✓
- first public understanding or next-action event ≤5s under a healthy
  provider ✓ (3.1s measured)

The final assistant token is now a natural-language model-synthesized
answer ("It's 8:23 PM on Friday, August 14, 2026…") rather than the
raw `sysinfo` tool output — though this is partly a B-8 concern and
will be hardened in Session 225.

## Tests

- 19 new tests in `tests/core/test_init_streaming.py`:
  - Streaming initializer emits ack before decision.
  - Raw JSON envelope / schema field names never leak into events.
  - Terminal pre-generation errors raise `TerminalProviderError`.
  - Non-terminal errors (transient 503) do NOT hang the consumer.
  - Empty adapter stream does NOT hang the consumer.
  - Unparsable output fails open to execute mode.
  - Ack and understanding each emitted at most once per turn.
  - `extract_preview` unit tests (partial JSON, escape decoding, caps).
  - `render_understanding` unit tests (objective / clarifying_question /
    direct-mode response fallback).
  - `InitializationPreview.diff` unit tests.
- Full backend suite: **1,721 passed**, 2 skipped, 0 failures
  (was 1,702 before B-7; +19 new tests).
- Ruff: clean. Frontend build: clean.

## Open items / spillover

- **B-8 (next session):** the final assistant token can still be the
  raw tool output when the model parrots `sysinfo` results. The
  evidence/final-synthesis boundary needs a hard contract: tool results
  → parent model → synthesis, never direct to chat.
- **B-12 (later):** the init prompt still includes the full tool JSON
  catalog. Compacting it to a capability summary will further reduce
  the 3.1s init latency. The 5s SLO is already met, but B-12 will
  harden it for slower models.
- The free Zen model sometimes omits spaces in JSON string values
  ("Checkingthecurrenttimeforyou."). This is a model quality issue,
  not a B-7 bug — the extraction is correct.
