# Real-time Agent Progress UI Review — 2026-07-31

## Executive Summary

Session 39 repaired the disconnect between streamed agent execution and the LocalMind workspace UI. Tool execution now focuses the left Actions tab, streamed actions carry meaningful tool arguments, todos update in place and complete from stable IDs/orders, elapsed time and token estimates move during streaming, and all active backend status variants are handled consistently.

## Findings and Fixes

### High — streamed execution stayed visually disconnected

Tool-start events now focus the left Actions tab. The right Observe/Terminal panel no longer competes for generic tool focus; terminal auto-focus remains limited to shell/code execution.

### High — actions and todos were generic or stale

The SSE bridge forwards tool arguments. Frontend action labels and input previews can show paths, commands, queries, and code previews. Todo events are normalized through shared helpers, replace generic same-ID rows, and apply status/completion updates by stable ID or plan order.

### High — active status handling was inconsistent

`pending`, `started`, `in_progress`, and `running` now share `isActiveToolStatus()` across tool-result matching, terminal completion, stream completion, timeout/abort cleanup, terminal auto-switching, Actions rendering, and the running-task footer. Active rows render amber instead of as failures.

### Medium — live metrics were delayed or reset

A request clock ticks every 250ms while streaming. Cumulative thinking plus answer text drives a live completion-token estimate. Sparse final provider metrics preserve the live estimate rather than replacing it with zero.

### Medium — final tool rows could remain stale

Stream completion now finalizes the closure-owned tool list synchronously and publishes the same snapshot to active-tool state and the assistant message, avoiding reads from a React state updater before it has run.
