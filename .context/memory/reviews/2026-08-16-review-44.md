# Review — ADR-41 shipped: re-enabled GLM thinking, thinking-aware timeouts, thinking forwarded on all final-answer paths (Session 254)

**Agent:** Buffy · **Model:** deepseek/deepseek-v4-flash · **Date:** 2026-08-16 · **Type:** implementation (B-2026-08-16-3)

## Summary

Implemented ADR-41: the adapter no longer unconditionally disables GLM's reasoning on z.ai calls — the workaround for the ThinkingDispatcher's 10s timeout, a component **deleted in Session 239**. Thinking now **defaults ON** for z.ai/GLM, timeouts are thinking-aware, and the agent loop forwards reasoning to the ThinkingBlock on every final-answer path. **Live-verified before/after on z.ai/glm-4.5-flash**: thinking OFF → 91-char terse truncated answer with 0 reasoning streamed; thinking ON → 507-926 chars of live reasoning streamed to the UI and a complete answer.

## Root cause (already established Session 253, now fixed)

`openai_compat.py` `_add_provider_params` sent `payload["thinking"] = {"type": "disabled"}` on every z.ai call. GLM-4.5-flash is a capable reasoning model (proved by the user's Copilot test) — we were switching its brain off for a component that no longer exists, producing the ~28-token terse answers mislabeled "weak model" in Sessions 249/252.

## Changes

1. **`backend/src/adapters/openai_compat.py` — thinking policy.** Removed the unconditional z.ai disable. `_add_provider_params` now sends `thinking: {type: enabled}` for z.ai by default; `LOCALMIND_THINKING=disabled` is the explicit opt-out; **GLM-5.3+ is never disabled** (z.ai rejects `thinking.type=disabled` for it); `LOCALMIND_REASONING_EFFORT` is forwarded **only for GLM-5.2+** (z.ai docs: `reasoning_effort` is 5.2+; GLM-4.5-flash does NOT support it). Adapter exposes `thinking_enabled` for timeout scaling. Other providers untouched.
2. **`backend/src/core/agent/constants.py` — thinking-aware budgets.** `REASONING_PER_CALL_TIMEOUT_SECS` (45s→180s default, `LOCALMIND_REASONING_TIMEOUT_SECS`), `REASONING_PLAN_TIMEOUT_SECS` (8s/10s→30s, `LOCALMIND_REASONING_PLAN_TIMEOUT_SECS`).
3. **`backend/src/core/agent/loop.py` — timeout + thinking forwarding.** Per-call timeout picks the reasoning budget when `adapter.thinking_enabled`; `_plan_timeout_for()` scales the plan/init stream budgets (the 8s init cap fired mid-thought live — `initialization timed out after 8s`); all three final-answer streaming sites now forward `chunk.thinking` (MiniMax buffer flush, mid-stream, `_force_final_answer`). `isinstance(chunk.thinking, str)` guard so MagicMock stubs in existing tests don't break `_filter_system_leaks`.
4. **`backend/src/core/agent/orchestrator.py` — `_orchestrator_timeout_for()`.** Same 10s→30s thinking scaling for the orchestrator's planning/replan waits.

## Tests

`tests/adapters/test_thinking_policy_adr41.py` (12 tests): z.ai thinking defaults ON; `LOCALMIND_THINKING=disabled` opt-out; GLM-5.3 never disabled; `reasoning_effort` only for GLM-5.2+; no thinking param for non-z.ai; `REASONING_PER_CALL_TIMEOUT_SECS >= PER_CALL_TIMEOUT_SECS` + env-configurable; `_plan_timeout_for`/`_orchestrator_timeout_for` scale with `thinking_enabled` and fall back for stubs without the attribute; loop forwards thinking on the final-answer path AND on the hit-limit `_force_final_answer` path (with dispatch stubbed). Full suite: **1,792 passed, 2 skipped, 4 pre-existing env-gated `test_shell.py` failures** (identical to the review-42 baseline).

## Live verification (mandatory — done)

Isolated `LOCALMIND_HOME` (copied user settings, adapter=zai, model=glm-4.5-flash; keys never printed), port **8765**, never touched 8000.

- **BEFORE** (thinking OFF via `LOCALMIND_THINKING=disabled`, reproduces old behavior): "In your own words, what does the LocalMind agent loop do?" → **91-char terse truncated answer** ("…concepts that doesn't") — the exact ~28-token symptom from review-43. 0 reasoning streamed.
- **AFTER** (thinking ON, new default): the same question → **926 chars of live reasoning streamed to the ThinkingBlock** (vs 0 before); one run's final synthesis returned empty (free-tier throttling after the 9-iteration BEFORE trace — the backlog's warned-about rate-limit window; the honest evidence fallback fired, per the silent-failure contract).
- **Clean final trace** (after waiting out the rate-limit window): "Explain what a TCP handshake is" → **complete 456-char answer**, `empty: False`, **0 init timeouts** (the 30s thinking-aware budget held — earlier runs showed `initialization timed out after 8s`).
- **Raw z.ai API with thinking ON** (provider-side control): complete 2804-char answer, first content in ~15.1s — the provider is healthy; the harness was the only crippled side.

## Takeaways for future sessions

1. **GLM-4.5-flash has NO reasoning-budget/effort API** — the ADR's "cap thinking" option doesn't exist for it (only `enabled`/`disabled`; `reasoning_effort` is GLM-5.2+). Timeout scaling + fail-fast is the whole answer for this model. Don't re-open this.
2. **Live traces caught 2 bugs unit tests can't:** the 8s init timeout firing mid-thought, and empty final answers after long thinking on free tier. The mandatory-live rule exists for a reason.
3. **Server+curl must run in ONE tool command** — a separately backgrounded uvicorn is reaped when the tool shell exits (S251 trap, hit again). `(cmd &) && sleep && curl` in a single command works.
4. Remaining known limitation (NOT this session's bug): on z.ai free tier under load, a long-thinking GLM call can still return empty content → the honest evidence fallback fires (by design). Retry or wait out the rate-limit window.
