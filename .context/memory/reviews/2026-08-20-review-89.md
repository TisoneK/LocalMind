## Executive Summary

The user pasted a real failing session (deepseek-v4-flash via bankofai, Windows): the model planned a good modular
project (task-cli) in its thought stream, but every attempt to act was intercepted by the loop's tool-talk detector and
the corrective nudge was **task-blind** ("Call the tool now using the function-calling format"). The model read that as
"prove you can call a tool" and re-ran `ls`/`Get-ChildItem` reconnaissance — 2 turns, 8 tool steps, zero files created.
Session 314 had already fixed this class of bug for the empty-reasoning nudge (embed the user's original question); the
tool-talk, forced-tool, and empty-response nudges never got that treatment.

**Fix shipped (`3880cfc`):** (1) `_recovery_nudge_tail()` — appends the user's original request plus an advancement
hint ("you already ran X — do NOT repeat them, call the tool that takes the NEXT step") to all three task-blind
nudges; (2) a creation-commitment pattern in `_TOOL_TALK_PATTERNS` that catches "I'll create/write the project
files…" narration with no tool call — the exact way the user's turn ended with zero files.

## Discovery

- Reproduced the user's failure chain in code: narration ("Let me describe the tools…") → `_is_tool_talk` interception
  (`text_tools.py:399`) → task-blind nudge (`loop.py:3709`) → model re-runs recon (the trace's reasoning literally said
  "call shell with ls -la").
- Verified the Session 314 precedent: the empty-reasoning nudge already embeds the original question; the other three
  nudges were still task-blind.
- Live traces on the real model (bankofai/deepseek-v4-flash, isolated 8765) surfaced a second hole in the SAME failure:
  the model ended the turn with "Now I'll create the project files — a modular Python project…" — a creation
  commitment with no `file_write` call. No existing pattern matched it (requires a creation verb + file noun; "I'll
  create" was not in the phrase lists and no tool name appeared in the text).

## Fixes Applied

1. **`loop.py` — `_recovery_nudge_tail(loop_messages, trace)`:** returns a suffix with `The user's request was: "<…>"`
   (300-char cap) plus, when `trace.steps` has tools, "You have already run these tools this turn: <names>. Do NOT
   repeat them — call the tool that takes the NEXT step…". Wired into the tool-talk nudge, the forced-tool nudge, and
   the empty-response nudge (base texts preserved — one existing test pins "requires a tool call").
2. **`text_tools.py` — creation-commitment pattern:** `(i'll|i will|i'm going to|let me) [now|then|next]?
   (create|write|make|build|add) (the|a|this)? <word>? (project|file|files|script|module|package|folder|directory)`
   — requires a creation verb + file-like noun (one optional adjective word between article and noun), so legitimate
   prose ("I'll create a summary/table") and past tense ("I created the files") never false-trigger. Bounded by the
   existing tool-talk recovery cap (2) + iteration cap.
3. **Tests:** `tests/core/test_task_anchored_nudges.py` (3: forced-tool nudge embeds the request; tool-talk nudge after
   tools ran embeds request + advancement hint + forbids repetition; empty-response nudge embeds the request) +
   creation-commitment cases in `test_dsml_interception.py`.
