# Review — Session 208: immediate chat acknowledgement

## Executive summary

LocalMind already created a local assistant placeholder, but the backend emitted
no real SSE payload until request prelude work had completed. Slow clients could
therefore experience 9–15 seconds of apparent silence even though the agent was
starting. The final model answer remains provider/model dependent, but transport
latency and generation latency are now separated.

## Root cause

`api.routes.chat._event_stream()` performed first-turn title persistence before
starting the engine stream. The frontend's local placeholder was the only early
signal; no server-side lifecycle event was available to proxies, native clients,
or the stream contract itself.

## Fix

- Emit a `status_update` SSE event as the first event from `_event_stream()`.
- Send it before title persistence, memory retrieval, adapter construction, or
  model generation.
- Initialize response accumulation before that first yield so interrupted streams
  retain the existing persistence safety behavior.
- Add an API regression asserting the first SSE event and exact status payload.
- Document the transport contract in `CHANGELOG.md`.

This is a transport/UX fix only. It does not bypass the parent-agent workflow,
change tool selection, or claim to reduce provider generation time.
