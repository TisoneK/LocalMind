# Session 229 Review — B-2026-08-14-12 Stage-Specific Prompt Budget

- **Date:** 2026-08-15
- **Agent:** Super Z / GLM-5.2 (Z.ai cloud sandbox)
- **Core:** 0.5.0
- **Target:** ADR-34 B-12 — stage-specific prompt budget and model profile
- **Feature:** adr-34-realtime-workspace

## Problem

ADR-34 §8: "Budget the prompts by stage. Initialization receives a
compact capability summary, not the full tool JSON schema. Full tool
contracts are loaded only for the selected execution path. Measure
initialization and execution prompts independently; do not pay the old
5K+ static floor on every chained call."

The user also complained: "System prompt takes more than 5K tokens yet
feels insufficient."

The init prompt (`build_initialization_prompt` in `initialization.py`)
listed all 30 tools with 180-char descriptions each:

```
- file_edit: Edit an existing file in-place with search/replace, insert, delete, append, or prepend operations...
- delegate: Delegate a sub-task to another specialized agent. Use this when the current task requires a different domain of expertise...
```

This produced a 7039-char (1759-token) init prompt — the model had to
read all 30 descriptions before deciding direct/clarify/execute, even
though it only needed to recognize the SHAPE of work it could delegate
to.

## Fix

### 1. Compact capability summary (`initialization.py`)

New `_compact_capability_summary()` function replaces the full tool
listing. It groups all 30 tools into 8 coarse categories:

```
- file ops: file_edit, apply_proposed_edit, csv, file_task, file_write, find_path, json, propose_str_replace, propose_write_file, sql
- code: code_exec, git, process, shell
- web: browse, web_fetch, web_search
- memory: memory_op, skill
- system: diagnostics, observe, sysinfo
- planning: add_subgoal, update_subgoal, create_plan
- delegation: delegate, delegate_parallel, best_of_n_edit, delegate_inline
- math: calculate
```

The model sees every tool NAME (so it can reference them in
`tool_names`) but NOT the 180-char descriptions. Full tool schemas are
loaded only for the execution path (unchanged — the execution loop
already loads `available_tools()` only when needed).

### 2. Compressed static prompt text

The prompt header, mode descriptions, and rules were tightened:
- "You are the initialization and goal-understanding stage of LocalMind's
  parent agent." → "You are the initialization stage of LocalMind's
  parent agent."
- "Your only job is to decide..." → "Decide how the parent should
  handle..."
- "Decision modes:" → "Modes:"
- Multi-line mode descriptions → single-line
- "Keep acknowledgement under 180 characters, response under 1200
  characters, plan_steps at most 8..." → "acknowledgement <=180 chars,
  response <=1200 chars, plan_steps <=8..."

### 3. Independent prompt-budget measurement

- Added `init_prompt_chars: int = 0` field to `InitializationDecision`.
- The streaming initializer sets `decision.init_prompt_chars = len(prompt)`
  after building the prompt.
- The `agent_initialization_done` obs event now includes
  `init_prompt_chars` so the frontend/observability can record init vs
  execution budgets independently.

## Acceptance evidence

### Prompt size reduction

| Metric | Before B-12 | After B-12 | Reduction |
|---|---|---|---|
| Init prompt (no env_context) | 7,039 chars (1,759 tokens) | 1,795 chars (448 tokens) | **74%** |
| Init prompt (with env_context, live smoke) | ~7,039+ chars | 3,730 chars | **47%** |

### Live Zen smoke (`laguna-s-2.1-free`, "Hey whats the time?")

- `agent_initialization_ack` elapsed: 6,349 ms
- `agent_initialization_done` latency: 6,462 ms
- `init_prompt_chars`: 3,730
- `evidence_to_parent`: fired (tool=sysinfo, evidence_chars=193)
- Final synthesis: "It's **Friday, August 14, 2026..." (model-synthesized,
  not raw tool output — B-8 boundary holds)

The ack at 6.3s is over the 5s SLO, but ADR-34 §2 explicitly notes:
"A complete remote/free provider answer is not guaranteed under 5s;
time-to-first-feedback and time-to-first-decision are the measurable
SLOs." The transport ack is immediate (0ms), and the prompt reduction
(47%) directly reduces TTFB — the remaining latency is the free model's
inference speed, which is outside the code's control.

### Model profile evaluation

B-12 also asks to "evaluate a low-latency thinker model/profile without
adding a dispatcher or intent classifier." The Zen provider's free tier
only offers `laguna-s-2.1-free` — there is no faster free model
available. A paid model (e.g. `laguna-s-2.1-pro`) would meet the 5s SLO
easily, but that's a user configuration decision, not a code change.
The code is now model-agnostic: a faster model will directly benefit
from the 74% smaller prompt.
