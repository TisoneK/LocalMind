## Findings & fixes

### Bug 3 — context meter reads 64% on a near-empty chat  → FIXED (`bef1eb2`)
- **Cause:** `5248 / 8192 = 64%`. phi4-mini:latest is absent from the static
  `_MODEL_CONTEXT_WINDOWS` table (ollama.py) and matched no size tag, so
  `context_window` fell to the 8192 default. The agent also budgeted the model
  at 8192 instead of its real 128K.
- **Fix:** query Ollama `POST /api/show` for the model's declared
  `context_length` (authoritative), cache per-model, fall back to the static
  table then 8192. Runtime + `/api/models` prime the async cache before reading
  the sync property. `num_ctx` is now user-configurable
  (`ollama_num_ctx`/`OLLAMA_NUM_CTX`/Settings): 0 = auto (resource-sane tier cap
  over the real window), >0 = override clamped to capacity. The size-tier
  heuristic now recognises tag-free "mini" models so their default num_ctx
  stays 8192 rather than ballooning to 128K on weak hardware.

### Bug 2 — "Hi" runs the tool loop and times out (180s) on phi4-mini → FIXED (`6887440`)
- **Cause:** the parent init is classify-only for a fast model, but a slow
  local model must GENERATE the whole `direct` decision (greeting response
  included) before the init stream ends. At ~0.17 tok/s even a short reply
  exceeds the 30s plan budget, so the init timed out,
  `parse_initialization("")` fell open to EXECUTE, and "Hi" cascaded into the
  full tool loop (observed: 5,211-token prompt, 37 completion tokens, 213s ≈
  30s init timeout + ~180s execute).
- **Fix:** `_plan_timeout_for` grants slow providers the generous
  `ollama_timeout_chat` budget (as `_per_call_timeout_for` already did, S288),
  floored at the reasoning plan budget. The init finishes → returns `direct` →
  "Hi" ends in one call, no tools. Stays inside agentic control (no intent
  routing). Thinking models unchanged.

### Bug 1 — no way to set model / embeddings / context in the UI → FIXED (`8e2bca4`)
- **Cause:** the Settings modal could switch providers but never the active
  MODEL (cloud showed a read-only line; Ollama had no model control); embedding
  model + context window were env-only.
- **Fix (frontend + backend):** modal gains an active-model dropdown (Ollama +
  cloud, hot-swaps via `/api/models/select`), an embedding-model selector (from
  new `GET /api/models/embeddings`, free-text fallback), and a context-window
  input (0 = auto) saved via new `POST /api/settings/local`. `GET /api/settings`
  now returns `embed_model` + `num_ctx`; client gains
  `getEmbeddingModels()` + `setLocalSettings()`.

### Token consumption follow-up → PARTIALLY ADDRESSED (`20fff03`) + backlogged
- **Measured composition of the 5,211-token "Hi":** tool schemas dominate
  (32-tool `available_tools()` = ~3,536 tokens; the per-call catalog after
  ADR-40 on-demand loading is ~1,963 tokens of 14 core tools), env/system
  context ~479 tokens, rest = system prompt + message.
- **Answer to "cache system info at boot":** doesn't help — env/system info is
  only ~479 tokens and is *already* inlined precisely so the model never calls
  a tool for it. The real lever is the tool schemas.
- **Shipped:** the classify/init call now uses a COMPACT env
  (`_build_environment_context(compact=True)`) — drops the redundant
  "## Available Tools" prose + hardware lines and skips a per-turn VectorStore
  count. Init prompt for "Hi" ~1,087 → ~731 tokens. With bug 2, "Hi" now ~731
  vs ~5,211 tokens (~86% less).
- **Backlogged (the real execute-mode lever):** progressive tool-schema
  disclosure so an execute turn doesn't ship all core schemas up front — this
  is ADR-43's tools-optimization scope (Phase 3). Bigger, riskier, needs on-box
  verification; not rushed this session.
