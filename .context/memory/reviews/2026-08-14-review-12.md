# Review — Session 207: user-visible parent workflow progress

## Executive summary

LocalMind already had a parent-agent Plan→Execute→Verify loop, but the user-facing
stream exposed raw provider planner/reasoning text and gave no immediate
acknowledgement before memory/provider work began. That made substantive turns
feel detached even though the parent loop was active.

## Root cause

`AgentRuntime` entered memory retrieval and `ParentAgent.run()` without an
immediate status event. `AgentLoop` streamed the planner's raw
`UNDERSTANDING`/`STEPS` output and raw pre-tool provider content as frontend
thinking events. The existing SSE/UI status path was available, but the loop did
not use it as the primary lifecycle surface.

## Fix

- Added an immediate runtime acknowledgement for substantive turns before
  memory retrieval and the first provider call.
- Added concise parent lifecycle statuses for plan preparation, plan creation,
  parsed plan summary, next-action selection, and final verification.
- Kept the complete plan in the parent execution context and `TaskState`; raw
  planner/provider reasoning is no longer forwarded as chat thinking content.
- Preserved native tool calls, tool progress/results, acceptance-gate verification,
  replanning, delegation, and the single parent-agent execution contract.
- Updated the affected parent-runtime regression to consume the acknowledgement
  before asserting the loop contract.
- Added dedicated workflow-progress regressions covering status ordering,
  verification visibility, completion, and planner-output privacy.
