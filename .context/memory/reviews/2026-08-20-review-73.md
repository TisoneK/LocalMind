### The tool-call emission gap (NEW finding)

After the reasoning, the model produced **one content token**:

> "I'll help you list the files in the /tmp directory using the shell tool. Let me first describe the shell tool to understand its schema."

…and then the response stream **ended**. No `tool_call` event was ever emitted. The loop correctly detected stream-end and treated the prose as the final answer (`agent_loop_done` → `agent_runtime_done` → `turn_complete`).

This is **not** the empty-content-after-reasoning pattern fixed in B-2026-08-18-11 (Session 298) — here the content is non-empty prose. It's a distinct weak-model behavior: **the model commits to a tool action in prose ("Let me describe the shell tool", "I'll use the shell tool to...") but does not emit the actual `tool_call` in the response**.

The loop's acceptance gate (`_acceptance_gate_at_final_answer`) returned `("", True)` — the legacy model-assertion path — because:
- No `success_criteria` were registered for this turn (the parent path uses generic ANALYZE intent, no per-task criterion).
- The completion floor (B-2026-08-18-2) only fires when the last high-stakes tool *failed* — here no tool ran at all.
- The prose is non-empty, so the empty-content synthesis rescue (B-2026-08-18-11) doesn't fire.

So the loop's behavior is *correct given its current contracts* — the gap is that no contract detects "model committed to a tool action in prose but didn't emit one."

## New backlog item

- **B-2026-08-20-6 (new, Medium):** detect "prose tool-action commitment without tool_call" and re-prompt. When the loop is about to accept a final answer on iter=1 (or any iter where no tool_call was emitted this run) AND the prose contains tool-action commitment language ("let me describe", "I'll use the shell tool", "I need to call", "first I should…"), inject a bounded re-prompt: "You committed to calling a tool but didn't emit the tool_call. Emit the tool_call now, or proceed with the action." Bounded by iteration cap + a one-shot retry (don't loop forever on a model that refuses to emit tool_calls). This is the natural complement to B-2026-08-18-11 (empty content) — both are "the model intended to act but didn't." Live-verify on glm-4.5-flash with the exact `list /tmp files` task before shipping. Files: `backend/src/core/agent/loop.py` (the `stream_ended_early` → `_acceptance_gate_at_final_answer` path ~line 3956, and the post-iter completion path ~line 4084). Pattern-detection could be a cheap keyword/phrase scan on `full_text` — but scope it to iterations where `tool_calls_this_run == 0` to avoid false positives on legitimate prose answers.
