# Review — addressed greeting routing

## Executive Summary

Session 221 investigated whether the parent loop and provider fail-fast path were broken after a screenshot showed a 36-second `Hey LM` turn and several provider-error conversations. The parent/provider paths were behaving as implemented: substantive turns make planning/tool-capable model calls, conversational questions make one direct model call, and terminal provider errors are covered by the ADR-32 fail-fast boundary. The confirmed defect was narrower: `Hey LM` did not match the deterministic social detector and therefore entered the substantive parent path.

## Findings and Fix

### High — addressed greetings entered parent planning — fixed

The greeting matcher recognized `hey` only as a complete message. `Hey LM` and `Hello LocalMind` fell through to `AgentRuntime`'s substantive path, which performed context building and model generation even though the user had supplied no task. The matcher now accepts `hi|hello|hey|heya` followed by `lm|localmind`, case-insensitively. These turns use the existing canned social response and acquire no adapter.

## Provider-error interpretation

The screenshot's usage-limit/auth cards do not prove that LocalMind skipped the model. They are produced after a provider call returns an error. For a direct conversational question this is one plain `chat()` call; for a substantive task the parent loop first plans, then executes through its model/tool boundary. ADR-32's terminal-error regressions confirm that terminal quota/auth/payment errors are not allowed to continue through additional parent iterations. A provider or network timeout can still make the one required provider call take time before the provider returns its error.

## Regression Coverage

- Addressed greeting detector cases: `Hey LM`, `hi lm`, `Hello LocalMind`, `hey localmind!`.
- Runtime cases prove `Hi`, `Hey LM`, and `Hello LocalMind` do not acquire an adapter or enter `ParentAgent.run()`.
- ADR-32 error-normalization, terminal-provider, planning fail-fast, and runtime propagation tests remain green.

## Limitation

This fix removes the avoidable provider wait for addressed social greetings. It does not make a real substantive model call instantaneous; provider generation and provider-side timeout latency remain observable for requests that actually need model reasoning.
