- **ADR:** ADR-55

## Executive Summary

Added B.AI as a new OpenAI-compatible provider (`bai`). This is a
config-only change (same class as ADR-9/ZenMux): one `ProviderConfig`
entry, one context-window entry, the settings field + env-key mapping, the
frontend provider picker, and `.env.example`. While adding it I found and
fixed a latent drift bug — `models.py`'s two hardcoded provider→settings
maps silently omitted ZenMux (ADR-9); all three derived maps now come from
`PROVIDER_CONFIGS`, so future providers cannot drift. **The B.AI addition is
unit-tested but NOT live-verified — there is no B.AI API key on this
machine, so the smoke test is BLOCKED** (documented in ADR-55).

## Fixes Applied

1. **`bai` provider (config-only).** `ProviderConfig` (base URL
   `https://api.b.ai/v1`, `BAI_API_KEY`/`BAI_MODEL`, `bai_model`, default
   `DeepSeek-V4-Flash`), `DeepSeek-V4-Flash: 128000` context window, UI label
   `B.AI (promo free models — time-limited)`, frontend picker entry, and
   `.env.example` env vars. `Hy3` left without a context-window entry
   (unknown → `default` fallback 32768) and not made the default, pending
   live `/v1/models` verification.
2. **Provider-map derivation.** `models.py` `_model_setting_attr` /
   `_build_model_setting_map` and `health.py` `model_setting_map` now derive
   from `PROVIDER_CONFIGS` (behavior-preserving + fixes the ZenMux omission).
3. **Listable-models tuple** in `models.py` gained `"bai"` so the Settings
   model dropdown can query B.AI's `/v1/models` live.
4. **Regression tests** — new `tests/api/test_provider_registry.py` (4 tests)
   locking the no-drift invariant and B.AI registration.
