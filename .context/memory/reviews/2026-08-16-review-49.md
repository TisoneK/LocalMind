# Review 49 — file_task Windows read-back path bug (Session 264)

**Agent:** Claude Code (claude-opus-4-8) · **Platform:** macOS (local) · **Core:** 0.5.0
**Commit (product):** `dbfe6de` — `fix(tools): file_task reads back Windows absolute paths`

## Trigger
User pasted a live Windows (`tison`) app trace of "Create a recipe on desktop
for a nice dinner" (glm-4.5-flash). The Thinker behaved correctly (S263 fix
held — anchored on the real request, called the `Facebook.lnk`/`WhatsApp Web.lnk`
evidence irrelevant, moved to create the file). But the turn ended
`✗ empty_response`. Steps: `shell` (list Desktop) ok → `file_write` ok →
`file_task` (read-back) → **`error_type=not_found`** → model retried → empty.

## Root cause (verified)
`file_task`'s path extractor used a forward-slash-only char class
`[\w.\-/]` (file_reader.py). On Windows, `C:\Users\tison\Desktop\Nice_Dinner_Recipe.md`
can't match across the backslashes, so it was truncated to the bare filename
`Nice_Dinner_Recipe.md`, then looked up under `~/` and `cwd` (never the Desktop)
→ `not_found`. Proven by running the exact regex against the trace path:
`WINDOWS -> ['Nice_Dinner_Recipe.md']`, `MAC -> ['/Users/bao/Desktop/…md']`.
This is why the same code passed on my Mac traces (forward slash was already in
the class) and failed on `tison`.

**The file was actually created.** `file_write` returns "ok" only after
`shutil.copy2` to the final dest succeeds, so `Nice_Dinner_Recipe.md` is on the
user's real Desktop. The harness falsely reported failure because its read-back
self-verification couldn't parse its own path.

## Fix
Add a dedicated Windows-drive pattern (`[A-Za-z]:[\\/]…`, backslashes or
forward slashes, spaces allowed) that runs BEFORE the Unix pattern, so the full
absolute path is the first candidate (`file_task` returns on the first that
exists; the bare filename remains a harmless fallback). Lifted the extractor to
a module-level `_extract_path_candidates()` for testability.

## Verification
- 6 new regression tests (Windows abs, Windows+spaces, Windows forward-slash,
  Unix abs, prose-embedded, bare/none). 14 file_reader tests pass; ruff clean.
- End-to-end smoke: `file_task` reading a real `~/Documents/*.md` returns
  `success=True`; Windows path extracted whole.

## Owed / follow-ups
- The agent's read-back is a self-verification the loop already does at write
  time (`file_write verification passed`). Consider whether the extra `file_task`
  read is needed for "create" tasks — a lean-tools item, not this fix.
- A live Windows re-run of the same task to confirm the turn now completes
  (can't run Windows from this Mac session; user can verify — the file should
  already be on their Desktop).
