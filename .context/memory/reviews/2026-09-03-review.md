## Change

`backend/src/core/context_compactor.py` — two default constants tightened:

| Constant | Legacy | Session 410 | Rationale |
|----------|--------|-------------|-----------|
| `KEEP_LAST_TOOL_RESULTS` | 4 | 1 | Only the immediately-previous tool result stays verbatim — the model just acted on it and may still need to reference its details. Older results the model has already synthesized from collapse to stubs. |
| `STUB_MAX_CHARS` | 600 | 400 | Smaller head+tail stubs (200+200) for results the model has already acted on. Still preserves the result's opening (where the useful title/summary lives for web_fetch, the file path for file_task, the command for shell) plus a tail stub. |

The ADR-19 policy `keep_markers` are unchanged — they still protect task-critical content (errors, URLs, source citations, git diffs, etc.) verbatim regardless of age, bounded by `policy.max_keep`. So debug/code/research/verify tasks keep their important signals even with `keep_last=1`.

### Note on the first fix-1 run

The first fix-1 run hit a transient bankofai HTTP 400 on the iter-2 replan call (gate replan #1 after "MiniMax XML detected" on iter 1). I initially suspected a regression from the compactor change. Re-running fix-1b succeeded cleanly with 5 iterations. The 400 was a transient provider error — the compactor only stubs OLDER results, and iter 2 had only 1 tool result which stays verbatim under `keep_last=1`. The compactor could not have caused the 400. This is logged in `inefficiencies/log.md` (Session 410) as a new variant of the bankofai rate-limit pattern.

## Findings (other issues identified)

Per the protocol's "identify other issues you might see and fix unless broad" directive:

1. **bankofai transient 400 on replan calls** — new variant of the rate-limit pattern. Logged to `inefficiencies/log.md`. Not a code bug; a provider quirk to expect during live-testing.
2. **Background processes die immediately in this sandbox** — `nohup ... &` and `& disown` both die when the parent Bash command returns. Affects venv installs, full pytest runs, any long-running backgrounded command. The `live-testing.md` "Harness gotcha (Session 330)" note documents this for the live-test server specifically; it generalizes to ALL backgrounded commands. Logged to `inefficiencies/log.md` + `environments.md` Quirks.
3. **Bash tool resets working directory** — each call starts at `/home/z/my-project`, and `cd <path> && <cmd>` gets the cd stripped. Use `git -C <path>` or absolute paths. Logged to `inefficiencies/log.md` + `environments.md` Quirks.
