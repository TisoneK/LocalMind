# Session 231 Review — Spaceless streamed text (init + plan)

- **Date:** 2026-08-15 | **Agent:** Claude Code / claude-opus-4-8 | **Platform:** macOS 15 (local) | **Core:** 0.5.0
- **Feature:** bugfix on adr-34-realtime-workspace
- **Target (user):** Thought process + quick replies rendered with NO spaces
  ("Respondtoacasualgreeting", "Hey!Notmuch,justhereandreadytohelp...").

## Root cause (corrects Session 230's wrong diagnosis)
NOT the model's output. `_strip_minimax_tool_calls` (text_tools.py) ends with
`return cleaned.strip()`, and it ran on EVERY streamed delta in two loops:
- the parent init producer (`loop.py` ~4775) — direct-mode `objective`
  (thought) + `response` (answer);
- the plan/thinking stream (`loop.py` ~4947) — execute-mode reasoning.
A model streaming a JSON value token by token emits deltas like "Respond",
" to", " a"; trimming each dropped the leading space, so the joined buffer
collapsed to spaceless text. Session 230 wrongly concluded "the answer
streams verbatim, so it's the weak model" — verbatim, yes, but of an
already-corrupted (per-delta-trimmed) buffer.

## Fix
Added `_strip_minimax_tool_calls_stream` — identical tool-call/markup removal
WITHOUT the trailing `.strip()` — and used it per-chunk in both streaming
loops. The trimming variant is unchanged and still used on complete texts.

## Validation
- `test_streaming_whitespace.py` (4): concatenated deltas keep their spaces;
  markup still stripped; trimming variant still trims edges.
- 40 tests pass (new + `test_dsml_interception` regression + init streaming);
  ruff clean. Full backend suite: see session entry (2 pre-existing macOS
  shell/powershell env failures remain, unrelated).

## Lesson (for the inefficiencies log / future agents)
Never apply an edge-trimming text normalizer to individual streamed deltas —
it eats the inter-token whitespace. Trim only complete texts.
