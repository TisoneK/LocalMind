# Review — 2026-09-06 — Session 428: concurrent post-tool Thinker consults (ADR-57 slice 2) + log-secret redaction

## Executive Summary

The owner approved ADR-57 slice 2: thinking after **every** tool with zero
added wall-clock. The post-tool Thinker consult now runs as a background task
overlapping the next model call — its prose streams to the ThinkingPanel and
its analysis is injected at the first call boundary after completion. The
once-per-turn / failure-or-≥2-sources gate was replaced by per-tool firing,
one-in-flight throttling, and a 5-per-turn cap; the failure-path consult stays
blocking. LIVE on bankofai/qwen3.8-flash (same prompt, before/after): consults
**2 → 4**, streamed consult reasoning **2223 → 7463 chars**, latency
**66.7s → 60.6s** (overlap, no added latency), answer quality held.

Bonus security fix: `core.config` logged the entire runtime-settings dict at
INFO **including plaintext provider API key values** on every boot — now logs
key names only (`cbbbabe`). Key values also surfaced in this session's chat
via a debug script that loaded real settings without `LOCALMIND_HOME`
isolation; rotation of the configured keys is advised.

## Discovery / Design

- Data-dependency map (ADR-57 Open-Q1): observation-N analysis blocks the next
  action ONLY on failure; after success the model already holds the raw
  observation, so the analysis is needed at the first call boundary AFTER the
  consult completes — the consult can overlap the next model call.
- Injection mechanics: `iteration_messages = list(loop_messages)` is copied
  per iteration, so appending the analysis to `loop_messages` at the iteration
  head (before the copy) lands it in the current call.
