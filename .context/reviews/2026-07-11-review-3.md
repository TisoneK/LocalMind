### Low

**L1 — README "Known Issues" stale bullet** (fixed this session, commit `abbbb3f`)
- **Description:** README.md line 231 claimed `npm run dev:backend` uses a Windows-only venv path and pointed to the legacy `REVIEW.md` at the repo root. But `dev:backend` was made cross-platform in Session 1 via `scripts/dev-backend.js` (which detects `process.platform === 'win32'` and spawns the correct venv binary). The `REVIEW.md` reference also pointed to the pre-`.context/` legacy location (ADR-3 moved reviews to `.context/reviews/`).
- **Impact:** Users on macOS/Linux following the README would unnecessarily avoid `npm run dev:backend` and use a manual workaround for a problem that doesn't exist. Documentation drift — the code moved on but the docs didn't.
- **Recommendation:** Remove the stale bullet entirely. The issue is fixed.
- **Status:** Fixed — commit `abbbb3f`.

**L2 — DRY violation in `config.py` settings field lookup** (fixed this session, commit `70926a5`)
- **Description:** Two places in `backend/src/api/routes/config.py` were reconstructing the settings field name via string manipulation instead of using the derived `ADAPTER_MODEL_FIELDS` map that Session 6's consolidation (`e2c0258`) created specifically to centralize this:
  - `get_settings()` (line 87): `getattr(settings, model_env.lower(), "")` — relied on the convention that env var `OPENAI_MODEL` maps to settings field `openai_model`.
  - `set_provider_key()` (line 183): `f"{req.provider.replace('-', '')}_model"` — relied on the convention that provider key `lite-llm` maps to settings field `litellm_model`.
- **Impact:** This is exactly the kind of drift the Session 6 consolidation was meant to eliminate. If a future provider's `settings_field` ever diverges from the `{provider_no_dash}_model` / `{model_env_lower}` convention, these two paths would break silently while every other path (using `ADAPTER_MODEL_FIELDS`) works. The `ProviderConfig` dataclass already has a `settings_field` attribute specifically so this coupling doesn't have to exist.
- **Recommendation:** Use `ADAPTER_MODEL_FIELDS[prov]` (derived from `PROVIDER_CONFIGS`) in both places.
- **Status:** Fixed — commit `70926a5`. No behavior change — the derived map produces identical field names for all 19 current providers. 197 tests pass.

### Nice to Have

**N1 — FastAPI `on_event` deprecation** (flagged for backlog)
- **Description:** `backend/src/api/app.py` uses `@app.on_event("startup")` (line 108) and `@app.on_event("shutdown")` (line 249). FastAPI deprecated these in favor of `lifespan` context managers. The 81 pytest warnings are almost entirely from these two usages (each test triggers the deprecation warning).
- **Impact:** No runtime impact yet — `on_event` still works. Will eventually break when FastAPI removes it (no announced removal date). The 81 warnings add noise to test output.
- **Recommendation:** Migrate to `lifespan` async context manager. Mechanical refactor: define `async def lifespan(app): ... yield ...` and pass it to `FastAPI(lifespan=lifespan)`. Safe but a refactor that touches the app factory — flagging for backlog rather than fixing inline.
- **Status:** Open — added to `tasks/backlog.md`.

**N2 — E501 count drifted +1** (noted, not fixed)
- **Description:** `ruff check .` reports 112 E501 errors (lines >120 chars). Session 6's review reported 111. The +1 is from the consolidation commit `e2c0258` adding a long log line in `openai_compat.py`.
- **Impact:** None — E501 is a style rule, not a bug. Already tracked under backlog item L1.
- **Recommendation:** A `ruff format .` pass would clear most E501s, but review the diff carefully — it can reformat in ways that hurt readability (per backlog L1 notes).
- **Status:** Open — already tracked under backlog L1.

### Memory-mode observations (`.context/` surface)

**M1 — Duplicate Session 6 entry in `agents/sessions.md`** (logged as flaw)
- **Description:** `agents/sessions.md` lines 39-48 and 50-59 are identical — the Session 6 entry was appended twice. Likely an accidental double-append (perhaps the agent ran the append command twice, or a tool call was retried).
- **Impact:** Pure noise. The duplicate carries no information the first entry doesn't. Future readers see two identical entries and wonder if they're missing something.
- **Recommendation:** Cannot remove — `sessions.md` is append-only per `.context/README.md` Rule 1. The append-only model has no way to deduplicate accidental double-appends. Logged as a `.context/` flaw (the protocol's append-only rule is correct for preserving history, but doesn't distinguish "history" from "duplicate noise").
- **Status:** Open — logged in `flaws/log.md`. Not fixable under current protocol rules.
